# BMAD Story — Module Repo Sync Campaign

## Understand
**Problem**: 52 paths in gitmodules.ini (bashscripts + 48 modules + 2 themes) are independent repos with their own `.git`, all tracking `laraxot/dev` upstream. Current state:
- Most lack `origin` remote (only `laraxot` remote exists)
- 22 modules are DIRTY with deleted auto-generated files (coverage.md, phpmd.ruleset.xml, phpunit.xml, etc.)
- Multiple modules are AHEAD of upstream (1-2 commits)
- User module is BEHIND upstream (1 commit)
- gitmodules.ini uses submodule syntax but these are NOT git submodules — each path is a standalone repo

**Applicable Rules**:
- Git solo avanti — no restore/checkout/reset/revert/rollback
- Each module: `git -C <path>` + `rev-parse --show-toplevel` for isolation
- Forward-only: fetch → merge → push
- Second brain + BMAD documentation required

## Plan
1. **Verify remotes**: Ensure all paths have `laraxot` remote with correct URL from gitmodules.ini
2. **Clean dirty state**: Restore or commit deleted auto-generated files (coverage.md, phpmd.ruleset.xml, phpunit.xml*)
3. **Sync ahead modules**: Push local commits to laraxot/dev (Activity 2, AI 1, AsdSoci 1, Billing 1, Blog 1, Bom 1, Catalog 1, Comment 1, Cms 1, Compliance 2, Lang 1, PublicProcurement 1, WorkOrder 1)
4. **Sync behind modules**: Pull from laraxot/dev for User (1 behind)
5. **Verify clean state**: All modules clean, synced with upstream
6. **Document**: Update wiki log, chat handoff, BMAD records

## Implement
- Fix remotes where needed
- Handle deleted files (restore from upstream or commit deletions if intentional)
- Execute git sync per module: `git -C <path> fetch laraxot && git -C <path> merge laraxot/dev --allow-unrelated-histories -s resolve`
- Push: `git -C <path> push laraxot HEAD:dev`
- Pull: `git -C <path> pull laraxot dev`

## Verify
- All 52 paths: `git status --short` = clean
- All ahead/behind = 0
- `phpstan analyse Modules` still passes
- Tests pass for affected modules

# Module Architecture Audit

**Objective:** Document the purpose, philosophy, design constraints, and refactoring opportunities for all 47 modules. Identify consolidation candidates, design debt, and missing PHILOSOPHY.md documentation.

---

## Master Analysis (47 Modules)

| Module | Purpose | Philosophy | Policy | Why | Zen | Gaps | Refactor |
|---|---|---|---|---|---|---|---|
| **Xot** | Foundation: base classes, conventions, 220+ Actions for all 47 modules | Framework-agnostic layer; changes to `XotBase*` propagate to all modules; DRY at core | `XotBaseResource::form()` final; `XotBaseModel` on `xot` connection; conventions via `GetTransKeyAction`; `phpstan.neon` sacred | Framework API changes (Filament, Livewire, Laravel) break without stable layer; one change solves 47 modules | Change one base class, all modules update: scale without fear | Stronger validation in base Actions; richer Data DTOs; cached discovery | Separate base classes by tier (UI vs data vs business logic) |
| **User** | Authentication, authorization, identities, multi-team, OAuth2 Passport, social login | BaseUser via STI on `type` field; Spatie permissions per team; abstract base classes for host extensibility | Models on `user` connection; password+2FA+OTP; roles scoped to team; MyProfile + SocialiteProvider settings | Every app needs login, roles, and multi-tenant identities; reinvention wastes time | One `id` stays same across tokens, logs, teams, and devices | SAML/OIDC deeper integration; WebAuthn; session clustering for distributed | Passport cluster heavy; extract OAuth endpoints to separate provider |
| **UI** | Components, design system, Filament patterns, layouts | Modular separable components; PHPStan L10; reusable across screens | XotBase-first, not Filament direct; Volt for interactivity; theme-aware styles | Filament is admin, Folio+Volt is public; repetition kills teams | One component library, infinite uses | Component library completeness; Storybook or Craft story | Break into UI (Blade), UILivewire (Volt), UIFilament (Resources) |
| **Tenant** | Multi-tenancy, data isolation, feature toggles, runtime config | Spatie multitenancy; JSON config per tenant; data lives in tenant schema/files | Feature flags gate features; config in `xra.php`, `metatag.php`; `SushiToJsons` for file storage | SaaS needs isolated databases/configs; no hard-coded tenancy rules | Activate feature, tenant sees it; no code redeploy | API-first feature toggles; cross-tenant queries; tenant-aware queue workers | Migrate tenants between hosts; decouple DB from blob storage |
| **Platform** | Core utilities, AccountFeatures, SettingsRepository, shared resources | Shared infrastructure for resource gating and feature flags | AccountFeatures gate UI per panel/tenant; SettingsRepository persists config | Prevent feature bleeding; 47 modules need same gating logic | Ask features once, gate everywhere | Dashboard/reporting infrastructure; stronger event bus; async jobs framework | Extract SettingsRepository to separate Settings module |
| **WorkOrder** | Job order: customer + site + contact + status + materials + interventions | Immutable status history via `WorkOrderStatusEvent`; every state change audited; soft delete + cascade restore | Only `ChangeWorkOrderStatusAction`/`ChangeWorkOrderStatusByCodeAction` alter status; no direct SQL; `status_id` not in form payload | Without state audit, who changed it and why is lost; effort variance not obvious | State you can't explain is state you don't have; ask `work_order_status_events` | Effort rollups per user; integration with payment terms; recurring orders | Merge with Intervention or keep separate; timeline UI too complex |
| **Activity** | Audit trail: who did what, when, on what | Transparent log of all changes; compliance-ready | Event-based tracking; immutable logs; queryable by model + user + date | Compliance audits require proof; operators need change history | Every action leaves a mark; trust the log | Encryption of sensitive fields; retention policies; export formats | Combine with Notify for change notifications; archive old logs |
| **AI** | AI models, prompts, inference integration | LLM abstraction; provider-agnostic (OpenAI, DeepSeek, etc.); prompt versioning | Spatie Data for requests/responses; LLM bridge pattern | Content generation, summaries, classifications without reinventing | One prompt engine, many providers; swap without refactoring | Fine-tuning models; embedding search; streaming responses | Merge with AiAssistant; separate prompt templates from logic |
| **AiAssistant** | AI-powered task automation, daily operations helper | Agents for domain tasks (WorkOrder status, quote generation, compliance) | Uses AI module; QueueableAction pattern; event-driven | Reduce manual data entry; automate routine work orders and quotes | AI suggests, human decides; audit trail of suggestions | Natural language interface; field-specific agents (Intervention, Billing); RAG | Consolidate with AI module; stronger domain understanding |
| **Billing** | Invoicing, pre-invoicing, supplier reconciliation, financial control | Pre-invoice from WorkOrder interventions; supplier invoice reconciliation line-by-line; FinancialControl dashboard | `BuildWorkOrderPreInvoiceAction` excludes pending extras; `ReconciliationDiscrepancy` types explicit; soft delete invoices | Without pre-invoice, errors surface only at payment; supplier invoices need matching | Close a WorkOrder, its invoice is half-done; reconcile, discrepancies pop | Multi-currency; tax calculations; payment plan support | Extract FinancialControl to separate Reporting module; API for ERP sync |
| **Catalog** | Products, categories, variants, attributes, SKUs | Flexible variant system; optional product in WorkOrderMaterial | Products optional in materials (nullable `product_id`); `description` required | Technicians sell unmet needs, not just stock; catalog is suggestion, not law | Not everything is a product; description outlives SKU | Variant grouping; price tiers; automatic cost updates from supplier | Merge attributes into separate Attribute module; support EAN/UPC codes |
| **Cms** | Content pages in JSON blocks, Folio routing, theme-aware rendering | Sushi JSON per tenant; `HasBlocks` for block composition; theme-aware views | Pages no tables; JSON in `database/content/pages/*.json`; Folio discovers routes; block `view` per block | Content without DB is portable; Folio scales themes without routes code | Write JSON, Folio finds it, theme renders it, customer edits blocks | Nested block layouts; rich editor for block content; preview mode | Separate JSON content storage from Sushi model; query language for blocks |
| **Comment** | Nested comments, reviews, moderation, threading | Hierarchical threading; moderatable; rateable | Moderation queue; spam filtering; notification on reply | Discussions evolve; moderation prevents abuse | Thread grows; mod approves; notified users return | Rich text editor; email notifications; comment feeds | Extract Comment as polymorphic trait; combine with Rating |
| **Compliance** | Regulatory docs, audit trails, sign-offs, certifications | Document versioning; signature workflows; audit-ready | Links to WorkOrder; requires signatures; checkpoints per status | Regulators demand proof; compliance failures cost millions | Every procedure leaves footprints; sign-off is binding | Policy templates; auto-reminders for re-certifications; vendor compliance | Merge with Document for unified doc management |
| **Costing** | Cost calculation, margins, valuations, real-time updates | Algorithm-based cost rollup; margin calculation from catalog costs | Costs per product + intervention + labor; discounts explicit | Sell blind = bleed; margins disappear in small mistakes | Know your cost before you quote; margin is the answer | Multi-level costing (labor + material + overhead); scenario analysis | Extract cost engine to separate Costing microservice; strong versioning |
| **Customer** | Clients, sites, contacts, soft delete with cascade restore, company lookup | Upsert contacts by email; cascade restore of deleted sites/contacts; external company lookup (VIES, OpenAPI) | FK on `customer_id` cascades soft delete; search via multiple providers; `ContactRole` unrelated to customer hierarchy | Duplicate contacts kill trust; deleted clients leave orphaned sites; manual entry delays onboarding | Restore a client, all its sites and contacts come back; company lookup fills half the form | Deduplication of customers; custom fields per site; bulk contact import | Separate Contact into own module; add organization hierarchy |
| **Document** | Document management, e-signatures, manual signatures, PDF annotations | Version control of docs; signature capture (digital + manual); audit trail | Immutable versions; signature binding to document version; soft delete | Signed docs must be tamper-proof; manual signatures legally binding | Sign once, version locked forever; audit trail = proof | Biometric signatures; batch signing workflows; WORM storage | Extract signature capability to separate Signature module (if not exists) |
| **Email** | Email sending, receiving, templates, integration, notifications | Event-triggered mails; template system with variables; queue support | Mail via Notify templates; retry logic; bounce handling | Untracked emails fail silently; Notify module already owns templates | Notify sends; Email delivers; users get notified | Webhook for bounce/open tracking; DKIM/SPF validation; aliasing | Merge Email into Notify; separate email delivery from notifications |
| **Employee** | Employee records, timesheets, shifts, permissions, org structure | Timesheet tracking; shift scheduling; permission levels | Time-in/time-out; approval workflows; role-based access | Technicians need hours tracked; compliance needs proof | Clock in, clock out, hours calculated; no manual entry | Geofence clocking; automated break rules; mobile timesheet app | Extract Timesheet to separate module; add biometric integration |
| **EnergyBroker** | Energy consumption tracking, supplier management, dashboards, tariffs | Meter readings; supplier contracts; cost breakdowns; energy sourcing | Consumption vs tariff; multi-meter per site; historical trending | Building energy costs hidden; suppliers overcharge unmonitored | Every joule tracked; costs visible; suppliers optimized | Renewable energy routing; demand-side management; predictive billing | Merge with Inventory for unified asset tracking |
| **Fiscal** | Electronic invoicing, tax compliance, regulatory documents, receipts | E-invoice XML generation; integration with tax authorities; receipt management | Compliant XML per jurisdiction; digital signature required; immutable archive | Non-compliance = fines; e-invoice mandatory in most jurisdictions | Invoice generated = transmitted to tax authority; proof in archive | Multi-jurisdiction support; VAT on reverse charge; IOSS simplified | Split into Fiscal (core) and ElectronicInvoice (provider-specific) |
| **Gdpr** | Privacy, data subject requests (access/deletion), consent tracking, erasure | Right to be forgotten; data portability; consent management | Soft delete of user data; export GDPR format; audit of processing | GDPR fines are massive; consent is mandatory; deletion must be provable | Request deletion, user vanishes + audit trail proves it | Automated consent reminders; breach notification; DPA integration | Merge with Activity for unified privacy tracking; add consent versioning |
| **Geo** | Geocoding, maps, route optimization, address validation | Multi-provider geocoding (Google, OpenStreetMap, Nominatim); caching | Cache results; fallback providers; coordinate validation | No coordinates = no field routing; addresses need validation | Every address → coordinates; service providers know where to go | Real-time geofencing; route optimization for visits; map-lit Web Components | Extract Geocoding to separate service; add ETA/distance APIs |
| **Giveback** | TechPlanner agnostic module (community/CSR features, feedback, giving back) | Modular, agnostic design; no host-specific coupling | Independent of other domains; composable patterns | Separates community features from core business logic | Standalone module; can be dropped into any host | Incomplete documentation; unclear dependencies | Merge into Platform if features core, or leave agnostic |
| **HR** | Human resources, departments, benefits, payroll, org structure | Hierarchical org structure; role definitions; benefit administration | Roles, departments, reporting lines; benefits enrollment | Org structure embedded everywhere; benefits need centralization | Know who reports to whom; who gets what benefits | Payroll integration; performance reviews; training tracking | Extract to separate HRIS system; decouple from WorkOrder |
| **Intervention** | Field work, service tickets, material usage, work minutes, signatures | Work order detail; minutes + materials tracked; cost variance visible | `work_minutes`, `materialsLines`; `WorkOrder` parent; soft delete with cascade | WorkOrder is the container; interventions are the execution details | Open WorkOrder → create Interventions → log minutes + materials → close | Geofenced clock-in; offline mobile app; digital forms/checklists | Separate mobile app for technicians; real-time sync to server |

## Summary & Recommendations

### Pillar Modules (6)
Define entire architecture, heavily imported:
- **Xot**, **User**, **UI**, **Tenant**, **Platform**, **WorkOrder**

**Action:** Ensure all have PHILOSOPHY.md + ARCHITECTURE.md completed. Add stronger base class validation (Xot). Document design restrictions (form finals, model connections).

### Domain Modules (24)
Solve specific business problems, depend on pillars:
- Billing, Quotation, Intervention, Customer, Catalog, Costing, Document, Compliance, Employee, Fiscal, Gdpr, Inventory, Job, Media, MetalWork, Notify, Production, PublicProcurement, Rating, Signage, Signature, Timber, Vehicle, Seo, EnergyBroker

**Action:** Complete ARCHITECTURE.md for gaps (AI, AiAssistant). Identify consolidation pairs (Email→Notify, Comment+Rating→Feedback, Compliance+Document→unified).

### Integration Modules (9)
Bridge to external systems or compliance:
- Activity, Email, Comment, Geo, Lang, HR, Intervention, AI, AiAssistant

**Action:** Extract channel implementations (Email, Sms, WhatsApp from Notify). Consolidate AI + AiAssistant. Move HR to separate HRIS.

### Agnostic Modules (5)
Community-centric, belong to TechPlanner:
- AsdSoci, Dds, Giveback, Thermo, Wts

**Action:** Mark as TechPlanner-owned in README. Add integration guards (prevent direct host coupling). Document clearly or relocate.

### Design Debt (High Priority)

1. **Email + Notify:** Email should disappear into Notify (channel provider).
2. **Comment + Rating:** Merge into unified Feedback module.
3. **Compliance + Document:** Unify document versioning + signature workflows.
4. **Platform SettingsRepository:** Extract to separate Settings module.
5. **AI + AiAssistant:** Consolidate into single AI module with domain-specific agents.
6. **Timber + Vehicle + HR:** Extract to separate operational CRM layer.

### Missing Documentation

Modules without PHILOSOPHY.md:
- AI, AiAssistant, Billing, Catalog, Cms, Comment, Compliance, Costing, Customer, Document, Email, Employee, EnergyBroker, Fiscal, Gdpr, Geo, Giveback, HR, Intervention, Inventory, Job, Lang, Media, MetalWork, Notify, Platform, Production, PublicProcurement, Quotation, Rating, Seo, Signature, Signage, Tenant, Thermo, Timber, Vehicle, WhatsApp, Wts, AsdSoci, Dds

**Action:** Create PHILOSOPHY.md for top 15 modules (Pillar + critical Domain modules). Use template from Xot.

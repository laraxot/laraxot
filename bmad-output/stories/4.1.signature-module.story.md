## Acceptance Criteria

### AC-01 — Signature morph model
Signature model (signed_at, payload). MorphTo `signable` (interventions, work orders). BelongsTo User (capturing operator). BelongsTo Media (stored signature image). Extends XotBaseModel.

### AC-02 — Sketch morph model
Sketch model (payload). MorphTo `sketchable`. BelongsTo User. BelongsTo Media (stored sketch image). Extends XotBaseModel.

### AC-03 — Media link for file storage
Both Signature and Sketch store their image file via a Media record (Spatie Media Library pattern using the shared Media module). Media kind = 'signature' / 'sketch'.

### AC-04 — StoreSignatureForModelAction
QueueableAction accepting: dataUrl (base64 PNG), signableType, signableId, userId, signedAt, payload. Decodes base64, stores to `media/signatures/` on `public` disk, creates Media record, creates Signature record with media_id FK.

### AC-05 — StoreSketchForModelAction
QueueableAction accepting: dataUrl (base64 PNG), sketchableType, sketchableId, userId, payload. Same flow as Signature but stores to `media/sketches/`, creates Sketch record.

### AC-06 — CaptureSignature Filament page
Full-screen signature capture page using HTML canvas. Accepts signable type/id context. Dispatches StoreSignatureForModelAction. Reusable from Intervention Resource.

### AC-07 — CaptureSketch Filament page
Full-screen sketch capture page using HTML canvas. Same pattern as CaptureSignature but saves as Sketch model.

- **SRC reference:** `/var/www/_bases/gestionale_commesse/Modules/Signatures/Infrastructure/Models/Sketch.php` — MorphTo sketchable, BelongsTo user, BelongsTo media. Casts: payload array.
- **SRC reference:** `/var/www/_bases/gestionale_commesse/Modules/Signatures/Application/Actions/StoreSignatureForModelAction.php` — Accepts dataUrl, decodes base64, stores PNG to `media/signatures/`, creates Media + Signature record.
- **SRC reference:** `/var/www/_bases/gestionale_commesse/Modules/Signatures/Application/Actions/StoreSketchForModelAction.php` — Same pattern for sketches.
- **SRC reference:** `/var/www/_bases/gestionale_commesse/Modules/Signatures/Filament/Pages/CaptureSignature.php` + `CaptureSketch.php` — Canvas-based capture pages.
- Signature and Sketch use `Modules\Documents\Infrastructure\Models\Media` (now `Modules\Media\app\Models\Media` after flattening). Media kind = 'signature' or 'sketch'.
- No Signature/Sketch-specific Policy needed — authorization handled by parent model policy.
- Module already exists in base (no Vehicle module exists yet) — flattening from `Infrastructure/` to `app/`.
- **Key design choice:** Signature/Sketch are separate morph models rather than a single polymorphic table because they have different semantics (signature has signed_at timestamp, sketch does not). This avoids nullable columns and keeps the domain explicit. [Source: architecture.md#wave-4]
- Intervention Resource gets a `SignaturesRelationManager` and `SketchesRelationManager` or inline capture page action (decided during implementation).

# Story — 5.5 Public Procurement Module

**Epic:** 5 — Manufacturing & Verticali
**Status:** backlog
**Owner:** Modules\PublicProcurement

## Intent

As a procurement officer, I want to manage the full tender-to-contract lifecycle — from sourcing opportunities through eligibility checks, contracts, progress reporting, payment certificates, and guarantees — so that public works contracts are administered correctly.

## Dev Notes

- SRC PublicProcurement module has a single large migration creating all 15 tables in dependency order. Replicate as one migration. [Source: SRC `Modules/PublicProcurement/Database/Migrations/2026_05_08_090000_create_public_procurement_tables.php`]
- This is the largest module by model count (~15 models). All models are tightly coupled to Contract as the aggregate root. [Source: SRC migration]
- SRC models use `$guarded = []` — target uses `$fillable`. [Source: `laravel/AGENTS.md`]
- Contract links to WorkOrder (Epic 1), TenderOpportunity (same module), and Customer (Epic 1). All must exist. [Source: SRC migration FKs]
- Measurements link to PriceItem (same module) and Intervention (Epic 1). [Source: SRC migration]
- PaymentCertificate links to ProgressReport (same module) and Invoice (Epic 4 Billing). Invoice FK will be nullable until Billing is ready. [Source: SRC migration]
- CIG/CUP codes are Italian public procurement identifiers. These are standard string fields with indexes for search. [Source: SRC migration]
- Estimated/contract amounts use decimal(14,2) — sufficient for euro amounts up to 99 billion. [Source: SRC migration]
- AiExtraction model is for AI-powered document extraction (future story 6.3/6.4). Store-only in this story. [Source: SRC migration]
- EconomicFrame amounts break down a contract value: works + security + available sums + VAT = total. This is a computed aggregate view stored denormalized. [Source: SRC migration]
- ProgressReport has a `progress_percentage` that could be computed from executed measurements vs price items total. For now manual entry, auto-calc for reporting later. [Source: SRC migration]

- **Measurement:** test quantity/amount decimal precision, FK resolution.
- **Resources:** test ContractResource and TenderOpportunityResource page rendering (key pages only, skip all 15 for time).
- **Policy:** admin vs operator access.
- No `RefreshDatabase`.

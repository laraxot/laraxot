# Story — 5.2 Bom Module

**Epic:** 5 — Manufacturing & Verticali
**Status:** backlog
**Owner:** Modules\Bom

## Intent

As a production planner, I want to define Bill of Materials (distinta base) for products, so that production orders know which components and quantities are required.

## Acceptance Criteria

| # | Criterion |
|---|-----------|
| AC-1 | Bom model + migration with columns `product_id` (FK products), `name` (nullable), `is_active` (bool default true). Index on `[product_id, is_active]`. |
| AC-2 | BomItem model + migration with columns `bom_id` (FK), `component_product_id` (FK products), `quantity` (decimal 12,3 default 1). Unique constraint on `[bom_id, component_product_id]`. |
| AC-3 | Bom has `product()` BelongsTo and `items()` HasMany relations. BomItem has `bom()` BelongsTo and `componentProduct()` BelongsTo relations. |
| AC-4 | Filament BomResource with List, Create, Edit, View pages. BomItem embedded as Repeater or RelationManager on Bom form. Component product searchable via Product select with model label. Quantity input with decimal step. |
| AC-5 | BomResource: product_id is disabled on edit. is_active toggle. Name auto-generated from product name if empty on create. |
| AC-6 | BomItem uniqueness enforced at model level: validate no duplicate component_product_id per bom_id. |
| AC-7 | Policy: BomPolicy extending UserBasePolicy. Read-only for operator panel; full CRUD for admin panel. |

## Dev Notes

- SRC Bom module has a single migration with boms and bom_items tables. No subsequent FKs or additional migrations. [Source: SRC `Modules/Bom/Database/Migrations/2026_02_25_000020_create_bom_tables.php`]
- Bom links to Product (Catalog module, Epic 3). Product must exist before this story can be implemented. [Source: architecture.md#wave-5]
- BomItem's `component_product_id` is a self-referential FK to the same products table — enables recursive BOM structures (sub-assemblies). The model treats component_product_id as a distinct product, not a hierarchical parent. [Source: SRC migration]
- SRC Bom model uses `$guarded = []` — target uses `$fillable`. [Source: `laravel/AGENTS.md`]
- SRC Bom class: final, no SoftDeletes, no timestamps on BomItem (but Laravel auto-adds them). Replicate faithfully. [Source: SRC `Modules/Bom/Infrastructure/Models/Bom.php`]
- No vehicle, user, or work-order FK on Bom — purely a catalog aggregation. [Source: SRC models]

## Testing Strategy

- Use Pest `it()` functions.
- **Bom model:** test factory create, product relation, items relation, is_active casting, name auto-generation.
- **BomItem model:** test factory create, bom relation, component product relation, quantity decimal, unique constraint violation.
- **Resource:** test page rendering (if Filament test patterns exist), test product search on component select.
- **BomItem uniqueness:** test database constraint with `assertDatabaseHas`/`expectException`.
- **Policy:** test admin can CRUD, operator read-only.
- No `RefreshDatabase`.

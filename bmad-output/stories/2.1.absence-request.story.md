# Story — 2.1 AbsenceRequest

**Epic:** 2 — HR & User Alignment
**Status:** backlog
**Owner:** Modules\Employee

## Intent

As an employee, I want to submit absence requests, so that my manager can approve/reject them.

## Acceptance Criteria

| # | Criterion |
|---|-----------|
| AC-1 | AbsenceRequest model + migration with columns `user_id`, `type` (leave/vacation/sick/injury), `starts_at`, `ends_at`, `notes`, `status` (pending/approved/rejected), `decided_by_user_id`, `decided_at`. BelongsTo User + decidedBy. SoftDeletes. Indexes on `[user_id, starts_at]` and `status`. |
| AC-2 | Filament Resource with List, Create, Edit, View pages. Form: type select (normalized via alias map), starts_at/ends_at DateTimePicker, notes Textarea. Status disabled on operator panel. Table: type badge, date columns, status badge (warning/pending, primary/approved, danger/rejected). |
| AC-3 | Operator scope: `getEloquentQuery` filters to `user_id = auth()->id()`. Create forces status=pending. No approve/reject buttons in operator panel. |
| AC-4 | Admin scope: all records visible. Approve/reject action buttons on pending records only. `ApproveAbsenceRequestAction` sets `status=approved, decided_by_user_id, decided_at`. `RejectAbsenceRequestAction` sets `status=rejected, decided_by_user_id, decided_at`. |
| AC-5 | Status badge colors: pending → warning, approved → success, rejected → danger. Type badge shows translated label. |
| AC-6 | Type normalization: Italian aliases (permesso→leave, ferie→vacation, malattia→sick, infortunio→injury) mapped to English keys on hydration + dehydration. |
| AC-7 | SoftDeletes trait on model. Migration includes `$table->index(['user_id', 'starts_at'])` and `$table->index(['status'])`. |

## Dev Notes

- SRC AbsenceRequest model uses `user_id` FK to `users` table, consistent with our Employee→User STI model (Employee IS-A User via Parental on `users` table). The FK references `users`, not `employees`. [Source: SRC `Modules/HR/Infrastructure/Models/AbsenceRequest.php`]
- SRC migration uses `foreignId('user_id')->constrained('users')` + `index(['user_id', 'starts_at'])`. Replicate directly. [Source: SRC migration `2026_02_17_120000_create_absence_requests_table.php`]
- SRC uses `$guarded = []` — in Laraxot we use `$fillable` explicitly. [Source: `laravel/AGENTS.md` conventions]
- SRC type aliases: `permesso`→`leave`, `ferie`→`vacation`, `malattia`→`sick`, `infortunio`→`injury`. Port verbatim. [Source: SRC `AbsenceRequestResource.php:35-40`]
- Existing WorkHourResource pattern (XotBaseResource, XotBaseCreateRecord) is the template for AbsenceRequestResource. [Source: `Modules/Employee/app/Filament/Resources/WorkHourResource.php`]
- Existing WorkHourPolicy extends UserBasePolicy — same pattern for AbsenceRequestPolicy. [Source: `Modules/Employee/app/Policies/WorkHourPolicy.php`]
- Existing Employee module uses `Modules\Employee\Models\BaseModel extends XotBaseModel`. [Source: `Modules/Employee/app/Models/BaseModel.php`]
- The module's composer.json may need `spatie/laravel-queueable-action` added if not already present. Check `laravel/composer.json` or the module's own `composer.json`. [Source: `architecture.md#actions`]
- Widget `AttendanceOverviewWidget` currently shows mock absence data — could be wired to real AbsenceRequest data in a follow-up (not in scope). [Source: `gestionale-hr-gap.md:30-31, 77-78`]

## Testing Strategy

- Use Pest `it()` functions (no PHPUnit classes, per `laravel/AGENTS.md`).
- **AbsenceRequest model:** test `factory()->create()`, `->user()` relation, `->decidedBy()` relation, soft delete, casts.
- **AbsenceRequestResource:** test page rendering via Filament tests (or skip if module has no pattern yet — existing WorkHour has no Resource tests).
- **Actions:** unit test `CreateAbsenceRequestAction::execute(...)`, `ApproveAbsenceRequestAction::execute(...)`, `RejectAbsenceRequestAction::execute(...)` with assertDatabaseHas / assertModelExists.
- **Policy:** test operator sees only own records, admin sees all.
- **Type normalization:** test Italian input → English storage, English input passes through.
- No `RefreshDatabase` trait — use `.env.testing` SQLite as per conventions.

# Story — 5.1 Inventory Module

**Epic:** 5 — Manufacturing & Verticali
**Status:** backlog
**Owner:** Modules\Inventory

## Intent

As a warehouse operator, I want to manage warehouses, locations, product units, and inventory movements, so that stock levels are tracked accurately across the organisation.

## Acceptance Criteria

| # | Criterion |
|---|-----------|
| AC-1 | Warehouse model + migration with columns `name`, `code` (nullable unique), `vehicle_id` (FK vehicles nullable), `is_active` (bool, default true), `is_final_destination` (bool, default false). Indexes on `name`, `vehicle_id`. |
| AC-2 | WarehouseLocation model + migration with columns `warehouse_id` (FK), `code` (string 64), `label` (nullable), `row`, `column`, `level` (unsigned int nullable), `is_active` (bool default true), `meta` (json nullable). Unique constraint on `[warehouse_id, code]`. Index on `[warehouse_id, row, column, level]`. |
| AC-3 | InventoryMovement model + migration with columns `product_id` (FK products), `from_warehouse_id`/`to_warehouse_id` (FK warehouses nullable), `from_location_id`/`to_location_id` (FK warehouse_locations nullable), `movement_type` (string: carico/scarico/trasferimento/reso), `quantity` (integer), `unit_price`/`line_total` (decimal nullable), `note` (text nullable), `work_order_id`/`intervention_id` (FK nullable), `created_by_user_id` (FK users nullable), `occurred_at` (datetime nullable), `origin_auto` (bool default false). Indexes on `[product_id, movement_type]`, `occurred_at`, `from_warehouse_id`, `to_warehouse_id`, `work_order_id`, `intervention_id`. |
| AC-4 | ProductUnit model + migration with columns `product_id` (FK), `serial` (nullable unique), `current_warehouse_id`/`current_location_id` (FK nullable), `status` (string: available/reserved/consumed/scrapped), `meta` (json nullable). Indexes on `product_id`, `current_warehouse_id`, `status`. Pivot table `inventory_movement_product_units` linking movements to units with unique constraint on pair. |
| AC-5 | Filament Resources: WarehouseResource, WarehouseLocationResource (nested under Warehouse via RelationManager), InventoryMovementResource, ProductUnitResource. Each with List/Create/Edit/View pages. Movement type field uses alias-normalized select (Italian input → English storage or vice versa per SRC). |
| AC-6 | Operator scope: InventoryMovement filters to movements linked to operator's assigned work orders. ProductUnit shows stock in operator's warehouses. Admin sees all. |
| AC-7 | Policies: WarehousePolicy, WarehouseLocationPolicy, InventoryMovementPolicy, ProductUnitPolicy — all extending UserBasePolicy. |

## Dev Notes

- SRC Inventory module has 4 migrations consolidated into a flat structure under `Database/Migrations/`. The base migration creates warehouses, inventory_movements, product_units, and the pivot in one file; three subsequent migrations add location support (warehouse_locations table, FK columns on movements/product_units), cost columns (unit_price, line_total on movements), and vehicle_id on warehouses. Target: single migration. [Source: SRC `Modules/Inventory/Database/Migrations/2026_02_25_000010_create_inventory_tables.php`, `2026_03_01_180000_add_costs_to_inventory_movements_table.php`, `2026_03_09_000001_add_vehicle_id_to_warehouses_table.php`, `2026_03_30_120000_add_warehouse_locations_to_inventory.php`]
- SRC models use `$guarded = []` — target uses `$fillable` explicitly per Laraxot conventions. [Source: `laravel/AGENTS.md` conventions]
- Model namespace: SRC uses `Modules\{Name}\Infrastructure\Models`, target uses `Modules\{Name}\Models`. [Source: architecture.md#module-boundary-architecture]
- Movement type aliases: Italian values (carico/scarico/trasferimento/reso) stored in DB per SRC. Keep as-is for now — no normalization required since the domain uses Italian terms natively. [Source: SRC migration]
- InventoryMovement links to modules from other epics: Product (Epic 3 Catalog), WorkOrder (Epic 1), Intervention (Epic 1), User (existing). These are FK references only — the referenced modules must exist before this story is implemented. [Source: architecture.md#dependency-graph, architecture.md#wave-5]
- Warehouse optionally links to Vehicle (Epic 4). [Source: SRC migration `2026_03_09_000001_add_vehicle_id_to_warehouses_table.php`]
- ProductUnit's `serial` field enables serialized inventory tracking (lot/serial number per unit). [Source: SRC migration]

## Testing Strategy

- Use Pest `it()` functions.
- **Model tests:** factory-based tests for each model, test all relations, casts, soft deletes where applicable.
- **Resource tests:** page rendering and CRUD operations via Filament tests (if test infrastructure exists), or skip if no pattern yet.
- **Movement validation:** test movement_type enum constraint, product FK required, quantity integer.
- **Policies:** test operator sees only own-warehouse/assigned-workorder scoped records, admin sees all.
- **ProductUnit status transitions:** test available→reserved→consumed, verify scrapped terminal state.
- No `RefreshDatabase` trait — use `.env.testing` SQLite.

# Story — 2.2 EmployeeResource CRUD

**Epic:** 2 — HR & User Alignment
**Status:** backlog
**Owner:** Modules\Employee

## Intent

As an admin, I want full CRUD for employees with medical visits, trainings, and documents, so that HR records are complete.

## Dev Notes

- Employee model uses `users` table via Parental STI (`use HasParent` on `Modules\Employee\Models\Employee extends Modules\User\Models\User`). No separate `employees` table exists; the model stores first_name/last_name in `personal_data` JSON and email/phone in `contact_data` JSON. [Source: `Modules/Employee/app/Models/Employee.php:157-200`]
- SRC EmployeeResource uses a dedicated `employees` table with flat columns (first_name, last_name, email, phone, hired_at, terminated_at, notes, is_active, user_id). Our model must map between flat form fields and JSON columns via `mutateFormDataBeforeCreate`/`afterStateHydrated` hooks. [Source: SRC `Modules/HR/Database/Migrations/2026_02_16_100154_create_hr_tables.php:13-29`]
- SRC EmployeeMedicalVisit uses `media_id` as direct FK to media table. In our codebase, we use Spatie Media Library. Attachment should use `$record->addMedia($file)->toMediaCollection('medical_visit')`, and the `media_id` FK is not needed if using Spatie's morph relation. Prefer Spatie approach over SRC's direct FK. [Source: SRC `Modules/HR/Infrastructure/Models/EmployeeMedicalVisit.php:34-37`]
- Same for EmployeeTraining and EmployeeDocument — use Spatie Media Library morph relationship instead of explicit `media_id` FK. The SRC module `Documents` is not present in our stack; Spatie Media Library is the cross-cutting media layer. [Source: `architecture.md` — «Media: Spatie Media Library»]
- Existing WorkHourResource pages (CreateWorkHour, EditWorkHour, etc.) extend XotBase* and use `getRedirectUrl()`, `mutateFormDataBeforeCreate()`, `getCreatedNotificationTitle()` — follow the same pattern. [Source: `Modules/Employee/app/Filament/Resources/WorkHourResource/Pages/CreateWorkHour.php`]
- No existing EmployeeResource in our codebase — currently only WorkHourResource exists. This is the gap identified in the gap doc. [Source: `gestionale-hr-gap.md:49-50`]
- Employee model already has `department_id`, `position_id`, `manager_id` relationship fields. These are out of scope for this story (already exist). [Source: `Modules/Employee/app/Models/Employee.php:168-181`]

## Testing Strategy

- Pest `it()` for each model: factory → assert DB, relations, casts.
- Resource page rendering: basic Filament page tests if module has test infra; otherwise manual verify.
- MedicalVisit/Training/Document create via RelationManager: test the `AddEmployeeDocumentAction`.
- Policy: admin sees all, operator sees only own (follow Operator panel convention).
- JSON mapping: test that flat form data round-trips through personal_data/contact_data JSON columns.

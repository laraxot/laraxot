# Story 1.2 — WorkOrder Module

- **Epic:** 1 — Core Field Service
- **Status:** backlog
- **Module:** `laravel/Modules/WorkOrder/`
- **Dependencies:** Customer (1.1), User (Auth)
- **Estimated effort:** 1 dev-day

---

## Story

As an admin/operator, I want to create and track work orders with configurable statuses, so that every intervention is linked to a structured job.

---

## Acceptance Criteria

1. WorkOrder CRUD with `XotBaseResource`: code, title (required), description, notes, customer link (`customer_id`), site (`customer_site_id`), primary contact (`primary_contact_id`), datetime tracking (`opened_at`, `scheduled_at`, `started_at`, `completed_at`, `closed_at`), planned effort (`planned_minutes`), soft-deletes. Searchable by `code`, `title`, `description`, `customer.legal_name`. [Source: prd.md#FR-01]
2. Status machine via lookup table: `WorkOrderStatus` model seeded with sortable statuses (`is_terminal` flag). `WorkOrderStatusEvent` audit trail recording `from_status_id` → `to_status_id` with `changed_by_user_id` and `changed_at`. [Source: prd.md#FR-01]
3. Assignment management: `WorkOrderAssignment` with `user_id`, `assigned_by_user_id`, `assigned_at`. Multi-user assignable. `AssignmentsRelationManager` on WorkOrder view. Scoped queries for operator panel (only assigned work orders). [Source: architecture.md#wave-1]
4. Activities log: `WorkOrderActivity` timeline with `content`, `occurred_at`, `created_by_user_id`. `ActivitiesRelationManager` on WorkOrder view. [Source: architecture.md#wave-1]
5. Relation managers for Interventions (count + list), Invoices/Quotes (placeholder for Wave 3/4), StatusEvents (audit trail). Panel-scoped: customer panel sees no relations. [Source: architecture.md#wave-1]
6. Full-text search (global): `code`, `title`, `description`, `customer.legal_name`. Result details show customer name + title. [Source: architecture.md#wave-1]
7. Feature visibility gating via `AccountFeatures` — `admin.work_orders`, `operator.work_orders`. Scoped `getEloquentQuery`: operator sees assigned only; admin with `hasAssignedPerimeter` sees scoped team; customer panel sees own records via `customer_id`. [Source: prd.md#FR-01]

## Dev Notes

- Module name: `WorkOrder` (singular PascalCase per NFR-04). SRC exists at `Modules/WorkOrders` (plural DDD structure) — **not ported as-is**. Create new module at `laravel/Modules/WorkOrder/` with flat nwidart structure. [Source: architecture.md#wave-1]
- Namespace target: `Modules\WorkOrder\app\Models\WorkOrder`, `Modules\WorkOrder\app\Filament\Resources\WorkOrderResource`. [Source: architecture.md#module-boundary-architecture]
- All models extend `XotBaseModel` (NFR-01). All resources extend `XotBaseResource` (NFR-01). Actions use `Spatie\QueueableAction` (NFR-01). Policies extend `UserBasePolicy`.
- SRC references to port (from `Modules\WorkOrders\Infrastructure\Models\*`):
  - `WorkOrder`: `$table = 'work_orders'`, `SoftDeletes`, casts (`*_at` datetime), relations: `customer()`, `site()`, `primaryContact()`, `status()`, `activities()`, `assignments()`, `statusEvents()`, `interventions()`, `complianceDocuments()`, `changeOrders()`, `publicProcurementContracts()` — keep only wave-1 relations, leave compliance/procurement for later waves.
  - `WorkOrderStatus`: `$table = 'work_order_statuses'`, `$guarded`, cast `is_terminal` bool. Seeded, not hardcoded.
  - `WorkOrderStatusEvent`: `$table = 'work_order_status_events'`, casts `changed_at` datetime, relations: `workOrder()`, `fromStatus()`, `toStatus()`, `changedBy()`.
  - `WorkOrderAssignment`: `$table = 'work_order_assignments'`, casts `assigned_at` datetime, relations: `workOrder()`, `user()`, `assignedBy()`.
  - `WorkOrderActivity`: `$table = 'work_order_activities'`, `SoftDeletes`, casts `occurred_at` datetime, relations: `workOrder()`, `createdBy()`.
- SRC Filament resource (`WorkOrderResource`) extends `Filament\Resources\Resource` — convert to `XotBaseResource`.
- SRC form fields: code, status_id (select from WorkOrderStatus ordered by sort_order), customer_id (searchable, live — clears site/contact on change), customer_site_id (filtered by customer, disabled until customer selected, live), primary_contact_id (filtered by customer+site, disabled until site selected), title (required), description, notes, opened_at/scheduled_at/started_at/completed_at (DateTimePicker), planned_minutes (numeric), effort_summary (Placeholder computed via `ComputeWorkOrderEffortAction`).
- SRC table columns: code (searchable, sortable), effort_variance (badge with color), title (searchable, sortable), customer.legal_name (searchable, sortable), site.name (searchable, toggleable), status.name (badge, sortable), description (limit 60, searchable, toggleable), notes (limit 60, toggleable hidden), scheduled_at (dateTime, sortable, toggleable), updated_at (toggleable hidden).
- SRC table filters: SelectFilter on customer_id, customer_site_id, status_id; scheduled_between date range filter.
- SRC table actions: exportReport (PDF/DOCX with date range — defer for Wave 4? or include lightweight version), preInvoice (Wave 4 — placeholder), ViewAction, EditAction (hidden on operator/customer).
- SRC actions to port: `ChangeWorkOrderStatusAction`, `ChangeWorkOrderStatusByCodeAction` (core status machine), `AssignUserToWorkOrderAction`, `UnassignUserFromWorkOrderAction`, `AddWorkOrderActivityAction`, `ComputeWorkOrderEffortAction` (value object), `CreateWorkOrderAction` — all as `QueueableAction`. Defer: `GenerateWorkOrderReportAction`, `GenerateWorkOrderPdfAction`, `GenerateCustomerReportAction` (Wave 4).
- SRC navigation: icon `heroicon-o-clipboard-document-list`, sort 3, group `work_orders`.
- DB connection: `xot`.
- Translations in `Resources/lang/{it,en}/` — mirror SRC `resources/lang/` keys under `work_orders.*`.
- Panel scoping: admin (full), operator (assigned only), customer (own via customer_id). SRC `WorkOrderResource::getEloquentQuery()` has three-panel branching logic — port with same structure.
- Status machine: SRC stores statuses in DB table (seeded) rather than PHP enum — keep this approach per architecture.md open decision.
- `AccountFeatures` dependency: class from `app/Support/` — stub if not yet ported.

- **Policy tests:** `it('scopes operator to assigned work orders')`, `it('scopes customer to own work orders')`.
- **Feature gate tests:** `it('hides work orders without operator.work_orders feature')`.

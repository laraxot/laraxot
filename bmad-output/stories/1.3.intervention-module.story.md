# Story 1.3 — Intervention Module

- **Epic:** 1 — Core Field Service
- **Status:** backlog
- **Module:** `laravel/Modules/Intervention/`
- **Dependencies:** WorkOrder (1.2), Media (platform), Signature (Wave 4 — morph placeholder)
- **Estimated effort:** 1 dev-day

---

## Story

As an operator, I want to track field interventions with time punches and notes, so that work done on-site is recorded and billable.

---

## Acceptance Criteria

1. Intervention CRUD with `XotBaseResource`: linked to `WorkOrder` (or direct `Customer` in direct-customer mode), operator assignment (`performed_by_user_id` + `assignedUsers` many-to-many via `intervention_user_assignments`), scheduled/started/ended datetimes, economic fields (`amount`, `callout_fee`, `materials_total`, `total_amount`), travel tracking (`travel_km`, `travel_minutes`), outcome code (`completed`/`suspended`/`quotation`), notes via `RichEditor` with HTML support, photo uploads, soft-deletes. [Source: prd.md#FR-01]
2. TimePunch timbrature: `TimePunch` model with `started_at`/`ended_at`, `user_id`, `intervention_id`. Start/stop actions on Intervention table row (operator panel). `SyncInterventionWorkMinutesFromTimePunchesAction` recalculates `work_minutes`. No overlapping open punches. [Source: prd.md#FR-01]
3. DailyNote operator notes: `DailyNote` model per intervention per operator per day (`note_date`, `body`/`body_html`, `user_id`). `DailyNoteResource` with RichEditor. MorphMany `media()` for photo attachments. Legacy HTML support via `DailyNoteHtml` utility. [Source: prd.md#FR-01]
4. IssueReport (nonconformity/defect reporting): `IssueReport` model with `description`, `reported_at`, `created_by_user_id`. Reports relation manager on Intervention view. [Source: prd.md#FR-01]
5. MaterialLine: `InterventionMaterialLine` with `description`, `quantity`, `unit` (pz/mt), `unit_price`, `line_total`, extra-quote tracking (`extra_quantity`, `extra_amount`, `extra_status_code`). Repeater form component inline on Intervention form. `refreshEconomicTotals()` syncs `materials_total` and `total_amount`. [Source: architecture.md#wave-1]
6. Embedded relation managers on WorkOrder view: `InterventionsRelationManager` showing count + list + inline time punch actions. Direct `hasMany` on WorkOrder model. [Source: architecture.md#wave-1]
7. Signature/Sketch morph placeholders: `Intervention` defines `signatures()` and `sketches()` morphMany relationships pointing to `Signature`/`Sketch` models (Wave 4). Stubbed as `// Wave 4: morphMany(Signature::class, 'signable')` — no actual models created. [Source: prd.md#FR-01]

## Dev Notes

- Module name: `Intervention` (singular PascalCase per NFR-04). SRC exists at `Modules/Interventions` (plural DDD structure) — **not ported as-is**. Create new module at `laravel/Modules/Intervention/` with flat nwidart structure. [Source: architecture.md#wave-1]
- Namespace target: `Modules\Intervention\app\Models\Intervention`, `Modules\Intervention\app\Filament\Resources\InterventionResource`. [Source: architecture.md#module-boundary-architecture]
- All models extend `XotBaseModel` (NFR-01). All resources extend `XotBaseResource` (NFR-01). Actions use `Spatie\QueueableAction` (NFR-01). Policies extend `UserBasePolicy`.
- SRC references to port (from `Modules\Interventions\Infrastructure\Models\*`):
  - `Intervention`: `$table = 'interventions'`, `SoftDeletes`, casts (`*_at` datetime, `amount`/`callout_fee`/`materials_total`/`total_amount` decimal:2, `travel_minutes`/`work_minutes` integer), relations: `performedBy()`, `assignedUsers()` (BelongsToMany via `intervention_user_assignments`), `workOrder()`, `customer()`, `timePunches()`, `issueReports()`, `inventoryMovements()`, `materialLines()`, `media()`, `signatures()` (Wave 4), `sketches()` (Wave 4). Method: `refreshEconomicTotals()`, `getRenderedNotesHtml()`.
  - `TimePunch`: `$table = 'time_punches'`, casts `started_at`/`ended_at` datetime, relations: `intervention()`, `user()`.
  - `DailyNote`: `$table = 'daily_notes'`, casts `note_date` date, relations: `user()`, `media()` (morphMany), method: `getRenderedBodyHtml()`.
  - `IssueReport`: `$table = 'issue_reports'`, relations: `intervention()`, `createdBy()`.
  - `InterventionMaterialLine`: `$table = 'intervention_material_lines'`, casts (`quantity`/`unit_price`/`line_total`/`extra_quantity`/`extra_amount` decimal:2), relations: `intervention()`, `quotationItem()` (Wave 3 — skip for now). Method: `isExtra()`.
  - `UserGoogleCalendarSetting`: out of scope (Wave 6 AI/calendar integration).
  - `InterventionReportShare`: out of scope (Wave 4 reporting).
- SRC Filament resource (`InterventionResource`) extends `Filament\Resources\Resource` — convert to `XotBaseResource`.
- SRC form fields: work_order_id (select, hidden in direct-customer mode), customer_id (visible in direct-customer mode), assigned_user_ids (multiple select, pre-filled with current user on operator panel), performed_by_user_id (hidden, derived from first assigned), scheduled_at (DateTimePicker) or scheduled_date (DatePicker in direct-customer mode), amount (numeric €), work_hours (numeric, converted to work_minutes), callout_fee (numeric €), total_amount_preview (placeholder, live), started_at/ended_at (DateTimePicker, hidden in direct-customer), travel_km (numeric, hidden in direct-customer), materials_total_preview (placeholder, live), notes_html (RichEditor with custom text colors), notes_photo_paths (FileUpload, image, multiple, camera capture), notes_suggestions (placeholder with clickable suggestions from previous notes), manual_material_lines (Repeater with description, quantity, unit select, unit_price, line_total_preview, extra_preview, extra_status_code, hidden extra_quantity/extra_amount).
- SRC table columns: work_order_id (formatted with title/code), customer_display (from WO or direct), site.name, performedBy.name, assigned_users_summary (comma-separated), started_at/ended_at/scheduled_at (dateTime), amount/callout_fee/materials_total/total_amount (money EUR), extra_total (badge), work_minutes (numeric), outcome_code (badge), notes (limit 70, searchable), travel_km (numeric), updated_at (toggleable hidden).
- SRC table filters: has_extra (whereHas materialLines extra_quantity > 0), customer_id (via WO or direct), customer_site_id (via WO), outcome_code, scheduled_between (date range).
- SRC table actions: start_time_punch (icon play, visible when assigned + no open punch), stop_time_punch (icon stop, danger, visible when assigned + open punch exists, requires confirmation), validate (form with travel_km, travel_minutes, notes, outcome_code — calls `FinalizeInterventionReportAction`), upload_photos (operator only, links to UploadInterventionPhotos page), ViewAction, EditAction (hidden on operator).
- SRC actions to port: `StartTimePunchAction`, `StopTimePunchAction`, `FinalizeInterventionReportAction`, `SyncInterventionWorkMinutesFromTimePunchesAction`, `SyncInterventionNotePhotosAction`, `CreateInterventionAction`, `SoftDeleteInterventionAction`, `CreateIssueReportAction`, `UpsertDailyNoteForUserAction`, `SyncDailyNotePhotosAction`. Defer: `BuildInterventionReportDraftAction`, `GenerateInterventionReportPdfAction`, report sharing/checkout actions (Wave 4).
- SRC navigation: icon `heroicon-o-wrench-screwdriver`, sort 2, group `interventions`.
- DB connection: `xot`.
- Translations in `Resources/lang/{it,en}/` — mirror SRC `resources/lang/` keys under `interventions.*`.
- Two work modes: work_order mode (default) and direct-customer mode (configured via `interventions.work_mode` setting). SRC uses `SettingsRepository` — port or stub similarly with simple config flag.
- Operator panel: forces self-assignment via `shouldForceSelfAssignment()` check (based on `operator.force_self_assignment` account feature + `hasAssignedPerimeter`). This enables one-operator-per-intervention workflow.
- Photo handling: SRC stores photos via `media()` morphMany with `kind = 'photo'` and `meta->scope = 'intervention_note'`. Uses `SyncInterventionNotePhotosAction` to link/unlink photos. Stored at `media/interventions/{id}/note-photos/`.
- Note suggestions: SRC reads previous intervention notes for the same work order to suggest completions — `getPreviousNoteSuggestions()`. Port as simple DB query, no ML needed.
- MaterialLine extra-quote tracking: SRC compares material lines against quotation items to detect extras. This requires Quotation module (Wave 3) — port the fields and status (pending/to_bill/waived) but leave comparison logic stubbed.
- Signature/Sketch placeholders: SRC uses `Modules\Signatures\Infrastructure\Models\Signature` and `Sketch` — not available until Wave 4. Add `morphMany` declarations on Intervention model commented out with `// Wave 4:` annotation so the relationship contract is documented without dependencies.
- `DailyNoteResource` in SRC is a separate resource (not embedded), with its own pages. Port as full standalone resource visible from operator panel.
- `InterventionReportShare` model + `UserGoogleCalendarSetting` model: out of scope, skip entirely.

## Acceptance Criteria

### AC-01 — VatLiquidation value object + action
CalculateVatLiquidationAction (QueueableAction) accepts sales array and purchases array of VatableAmount (ratePercent, taxableAmount), groups by FiscalRate key, returns VatLiquidation DTO (salesRows, purchaseRows, balance). VatSummaryRow per rate: rate, taxable, vat.

### AC-02 — InvoiceTotals calculation
CalculateInvoiceTotalsAction (QueueableAction) accepts array of InvoiceLineData (quantity, unitPrice, discountPercent, vatRatePercent), returns InvoiceTotals DTO (lineTotals, vatByRate, taxableByRate, grandTotal). Applies per-line VAT rate.

### AC-03 — PaymentPlan calculation
CalculatePaymentPlanAction (QueueableAction) accepts total (Money), installments count, firstDueDate, intervalDays. Splits amount evenly, distributes rounding remainder cent-by-cent. Returns array of PaymentInstallmentPlan DTOs (dueDate, amount).

### AC-04 — FatturaPA XML generation
GenerateFatturaElettronicaXmlAction (QueueableAction) accepts FiscalInvoiceData DTO, produces DOMDocument conforming to FatturaPA FPR12 format. Handles formatting rules: missing buyer VAT, "0000000" recipient code, empty denomination fallback.

### AC-05 — Fiscal DTOs
FiscalInvoiceData (lines, seller, buyer, totals, paymentPlan), FiscalInvoiceLine (description, quantity, unitPrice, discountPercent, vatRatePercent), FiscalSeller (country, vatNumber, fiscalCode, businessName, register, registerIdentifier, reaOffice, reaNumber, reaCapital, reaMemberType, uniqueId), FiscalBuyer (country, vatNumber, fiscalCode, businessName, recipientCode, certifiedEmail). All readonly DTOs.

### AC-06 — Zero models, pure actions
Fiscal module contains zero Eloquent models. All persistence happens in calling vertical (Billing/TimberBilling). Fiscal is a library of value objects + QueueableActions + DTOs only.

### AC-07 — Flatten Domain/ to app/
Move actions from `Domain/Actions/` to `app/Actions/`, DTOs from `Domain/DTO/` to `app/DTO/`, ValueObjects from `Domain/ValueObjects/` to `app/ValueObjects/`. Reconcile namespace for FiscalRate (shared with Billing verticals).

- Module already exists in base with DDD structure (Domain/ only, no Infrastructure/Models/). Flattening is straightforward.
- ServiceProvider registers bindings for the 4 actions.

## Testing Strategy

- Unit tests for each action with known inputs, assert DTO outputs match expected calculations.
- CalculateVatLiquidationAction: provide sales [100@22%, 50@10%] and purchases [30@22%], assert salesRows, purchaseRows, balance Money values correct.
- CalculateInvoiceTotalsAction: provide 2 lines with different VAT rates, assert vatByRate grouping, grand total.
- CalculatePaymentPlanAction: 100.00 total / 3 installments, assert sum of installments equals 100.00, assert date intervals correct.
- GenerateFatturaElettronicaXmlAction: build FiscalInvoiceData, generate XML, assert DOM structure matches FatturaPA XSD (key fields: FatturaElettronicaHeader, DatiGenerali, DatiBeniServizi, DatiRiepilogo).
- Edge case: 0-rate VAT, zero-discount, single-line invoice.
- Edge case: missing buyer VAT → assert "0000000" recipient code in output.
- No database, no Eloquent — all tests are pure unit tests (no RefreshDatabase needed).

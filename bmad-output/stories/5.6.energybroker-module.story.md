# Story — 5.6 Energy Broker Module

**Epic:** 5 — Manufacturing & Verticali
**Status:** backlog
**Owner:** Modules\EnergyBroker

## Intent

As an energy broker, I want to import utility documents, match them to customers, manage supply points (POD/PDR), and track supply history, so that energy contract management and switching advice is data-driven.

## Acceptance Criteria

| # | Criterion |
|---|-----------|
| AC-1 | ImportBatch model + migration with columns `uploaded_by_user_id` (FK), `source_name`, `source_type` (manual_upload/api), `status` (draft/processing/completed/failed), `total_files`/`processed_files` (unsigned int), `meta` (json). SoftDeletes. |
| AC-2 | Document model + migration with columns `public_id` (uuid unique), `import_batch_id` (FK nullable), `customer_id` (FK nullable), `media_id` (FK nullable), `source_file_name`, `file_hash` (indexed), `document_type` (bill/contract/quote/other), `service_type` (electricity/gas/water), `supplier_name`, `analysis_status` (draft/analyzed/reviewed/approved), `confidence_score` (decimal 5,4 nullable), `raw_text` (longText), `analysis_payload`/`normalized_payload`/`reviewed_payload` (json), `processed_at`, `imported_at`. SoftDeletes. Indexes on `document_type`, `analysis_status`, `file_hash`. |
| AC-3 | CustomerMatch model + migration with columns `document_id` (FK), `customer_id` (FK nullable), `score` (decimal 5,2), `status` (needs_review/matched/rejected), `matched_on` (json — stores matched field names), `reason` (text). |
| AC-4 | SupplyPoint model + migration with columns `customer_id` (FK), `customer_site_id` (FK nullable), `service_type` (electricity/gas), `pod` (nullable — electricity point code), `pdr` (nullable — gas point code), `supply_code`, `supplier_name`, `offer_name`, `annual_consumption` (decimal 14,3), `power_kw` (decimal 8,2). | AC-5 | SupplyHistory model + migration with columns `supply_point_id` (FK), `document_id` (FK nullable), `supplier_name`, `offer_name`, `offer_code`, `status` (current/previous/ended), `started_at`/`ended_at` (date nullable), `meta` (json). Index on `[supply_point_id, status]`. |

## Dev Notes

- SRC EnergyBroker module has 2 migrations: base tables and a large uploads table. The base migration creates import_batches, documents, customer_matches, supply_points, and supply_histories. [Source: SRC `Modules/EnergyBroker/Database/Migrations/2026_05_08_160000_create_energy_broker_tables.php`]
- The second migration `2026_05_13_164000_create_energy_broker_large_uploads_table.php` adds a large uploads tracking table. This can be merged into the base migration or deferred. For this story, include if time permits; otherwise defer with a `ponytail:` comment. [Source: SRC migration]
- Document `public_id` UUID is auto-generated on create. SRC boots `creating` event for this — replicate. [Source: SRC `Modules/EnergyBroker/Infrastructure/Models/EnergyBrokerDocument.php:22-28`]
- `confidence_score` is decimal(5,4) — storing 0.0000 to 1.0000 range. [Source: SRC migration]
- POD (Point of Delivery = electricity meter point) and PDR (Point of Delivery = gas meter point) are Italian energy market codes. At least one per SupplyPoint. [Source: SRC migration]
- SupplyPoint `customer_site_id` links to CustomerSite (Epic 1 — not created yet in this story). FK nullable. [Source: SRC migration]
- Document analysis flow: draft → analyzed (AI auto) → reviewed (human) → approved (human). AI analysis store-only in this story (Epic 6.3/6.4 AI story handles the analysis logic). [Source: SRC migration field definitions]
- CustomerMatch `matched_on` JSON stores the field names used to match (e.g. `["business_name", "vat_number", "address"]`). Match scoring is handled by an Action (not in scope — store-only here). [Source: SRC migration]
- SRC models use `$guarded = []` — target uses `$fillable`. [Source: `laravel/AGENTS.md`]

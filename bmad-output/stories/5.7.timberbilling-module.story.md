# Story — 5.7 Timber Billing Module

**Epic:** 5 — Manufacturing & Verticali
**Status:** backlog
**Owner:** Modules\TimberBilling

## Intent

As a timber trading company, I want to issue invoices with specific timber-domain fields (lot codes, quintali measures, product references), track payment installments, and generate electronic invoices (FatturaPA), so that billing is compliant with both timber industry practices and Italian fiscal law.

## Dev Notes

- SRC TimberBilling module has 4 migrations: invoices + lines, payment installments, e-invoices, and a separate customer table (TimberCustomer). The customer model references `timber_customers` — in the target, we should use the main Customer (Epic 1) instead of a domain-specific customer table. The customer_id FK references `timber_customers` in SRC but should reference `customers` in target. [Source: SRC migration FKs, architecture.md#wave-5]
- The payment installments migration (`2026_07_08_100100_create_timber_payment_installments_table.php`) can be deferred — not in the story scope. `ponytail: add when installment payment tracking is requested.` [Source: SRC migration listing]
- TimberInvoice reuses the Fiscal module's FatturaPA engine (Epic 4.2). The `GenerateTimberEInvoiceAction` calls into Fiscal's XML builder. Fiscal must exist before this story can implement T-6. [Source: architecture.md#wave-5 dependency: TimberBilling needs Fiscal]
- SRC uses `timber_products` table (separate from main Catalog Products). Decision: reuse main Product model (Catalog, Epic 3) with a category/department filter for timber products, OR create a dedicated `TimberProduct` pivot. For this story, reuse main Product model via FK to `products` table. If timber-specific fields are needed (e.g. wood type, grade), they can be added as a meta extension later. [Source: architecture.md#cross-cutting]
- Unit of measure defaults to `quintali` (hundredweight / 100kg) — standard in Italian timber trading. [Source: SRC migration]
- SRC TimberInvoice model uses `$guarded = []` — target uses `$fillable`. [Source: `laravel/AGENTS.md`]
- SRC invoice `kind` values are string-based. Keep as-is — no enum needed for now. [Source: SRC migration]
- Stock posting (`stock_posted_at`) is a future integration with Inventory module (Epic 5.1) — field stored, logic deferred. [Source: SRC migration]

## Testing Strategy

- Use Pest `it()` functions.
- **Model tests:** test TimberInvoice factory create, line items total calculation, kind+number unique constraint.
- **Number auto-generation:** test per-kind-per-year sequential numbering, test reset at year boundary.
- **Status machine:** test valid transitions (draft→issued→paid, draft→cancelled), test invalid transitions.
- **EInvoice XML generation:** test Action output has valid FatturaPA structure, test SDI identifier population.
- **Resource tests:** page rendering (if patterns exist), invoice line Repeater total calculation.
- **Policy:** operator vs admin access.
- No `RefreshDatabase`.

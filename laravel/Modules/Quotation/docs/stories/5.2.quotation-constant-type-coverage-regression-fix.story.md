# Story 5.2 — Quotation: re-fix constantTypeCoverage regression

Status: **done** — 2026-09-07

## Contesto

Continuazione delle story root `2.8.phpstan-constant-type-coverage` e
`5.1.phpstan-constant-type-coverage-remaining` (claim
`docs/chat/2026-09-07-claim-typecoverage-final-push-swarm.md`, batch Quotation
12 costanti / Signage 7 costanti).

Le 12 costanti erano gia' state tipizzate oggi dal commit `352d16b`
("refactor(quotation): type constants [story: 2.8]", 15:38:42). Una verifica
full-tree successiva le ha ritrovate **non tipizzate**: il working tree del
modulo aveva ~28 file WIP non committati dallo swarm Epic4
"filament-canonical-structure" (story `4.13.sitesurvey-canonical-structure`,
`phpstan-fix-quotation-hasxotfactory-*.story.md`) che rigenera i
Resources/Widgets/Actions da una base precedente al fix, perdendo
silenziosamente l'annotazione di tipo nativo sulla costante (mantenendo pero'
le altre modifiche strutturali legittime, es. `QuotationsMarginByProjectChart`
rinominato da `ChartWidget` a `XotBaseChartWidget`).

## Perche' scoping full-tree e non per-modulo

`./vendor/bin/phpstan analyse Modules/Quotation` da solo **non rileva mai**
`typeCoverage.constantTypeCoverage`: la regola
(`TomasVotruba\TypeCoverage\Rules\ConstantTypeCoverageRule`) confronta i path
analizzati da CLI con `parameters.paths` di `phpstan.neon` via
`ScopeConfigurationResolver::areFullPathsAnalysed()` e si disattiva
silenziosamente se non coincidono esattamente. Serve sempre
`analyse Modules` (l'intero albero) per vedere questi errori.

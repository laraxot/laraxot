# Story 4.4 — GatedXotBaseResource: depreca o mantieni

## Understand

### Situazione attuale

- `GatedXotBaseResource` (`Modules/Platform/app/Filament/Resources/GatedXotBaseResource.php`) è una sottoclasse di `XotBaseResource` con il trait `GatesResourceNavigation`.
- `GatesResourceNavigation` (`Modules/Platform/app/Filament/Concerns/`) implementa `NavigationGate::isItemEnabled(static::class)` per nascondere voci di menu e bloccare URL diretti via runtime feature toggle.
- Usato storicamente da: `AuditLogResource`, `PlatformSettingResource`, `DeliveryNoteResource`, `InvoiceResource`, `SupplierInvoiceResource`, `SupplierResource` (tutti Billing, ora migrati a `XotBaseResource` diretto).
- `Catalog/import-status.md:35` documenta: "In questa base: `extends GatedXotBaseResource` (Modules\Platform) — navigation gate runtime".

### Tensione

- **Prompt `06-filament-audit.md`**: "SOLO `XotBaseResource` diretto, MAI varianti inventate tipo `GatedXotBaseResource`. Autorizzazioni via policy/scope, non via naming."
- **CustomerPanelProvider**: usa `NavigationGate` per nascondere `InvoiceResource` agli utenti del pannello cliente. Se `InvoiceResource` non estende `GatedXotBaseResource`, il toggle runtime non funziona più.
- **AuditLogResource/PlatformSettingResource**: rinominati in `extends XotBaseResource` da un altro agente (vedi story 4.2) ma il `use` mancante è stato aggiunto. Bootstrap Filament ora funziona, ma il gate NavigationGate potrebbe non essere più attivo per queste due (da verificare).

### Domande aperte

1. `GatedXotBaseResource` è ancora necessario per qualche Resource? O è un vestigio?
2. Se sì, va mantenuto come eccezione documentata o va migrato a composizione (`HasNavigationGate` trait applicabile a `XotBaseResource`)?
3. `InvoiceResource` migrato a `XotBaseResource` perde il gate del CustomerPanelProvider. Regressione funzionale? Verificare con utenti/repo.

## Plan

### Fase 1 — Inventario (read-only)

```bash
cd laravel/Modules
grep -rln "extends GatedXotBaseResource" */app/Filament/Resources/*.php
grep -rln "GatedXotBaseResource" */app/Providers/Filament/*.php
grep -rln "GatesResourceNavigation" */app/Filament/ 2>/dev/null
```

Chi usa `GatedXotBaseResource` direttamente ancora? Chi usa `GatesResourceNavigation`?

### Fase 2 — Verifica NavigationGate (runtime)

Per ogni Resource che ha il gate, verificare:
- `NavigationGate::isItemEnabled(<ResourceClass>)` ritorna cosa attualmente?
- Senza `GatesResourceNavigation` trait, cosa fa `XotBaseResource`?

### Fase 3 — Decisione

**Opzione A — Mantieni GatedXotBaseResource (P0)**
- Pro: zero rischio di regressione funzionale
- Contro: viola prompt 06 che dice "MAI varianti inventate"
- Soluzione: aggiornare prompt 06 per fare eccezione esplicita + documentare la regola "NavigationGate-only"

**Opzione B — Migra a composizione (P0)**
- Pro: allineato con prompt 06
- Contro: richiede refactor di TUTTE le Resource che usano il gate, regression risk
- Soluzione: creare `Modules/Xot/Filament/Concerns/HasNavigationGate` trait, applicabile a qualsiasi `XotBaseResource`. Le Resource che vogliono il gate aggiungono `use HasNavigationGate;` esplicitamente.

**Opzione C — Rimuovi NavigationGate (P0)**
- Pro: codice minimale, allineato con prompt
- Contro: perde funzionalità runtime toggle
- Soluzione: dipende da requisiti di business

### Fase 4 — Implementazione (dipende da scelta Fase 3)

Se Opzione A: aggiornare prompt 06 §Vincoli con nota "eccezione: GatedXotBaseResource è consentita se fornisce GatesResourceNavigation attivo".

Se Opzione B:
1. Crea `Modules/Xot/app/Filament/Concerns/HasNavigationGate.php` con la logica di `GatesResourceNavigation`
2. Crea alias in `Modules/Platform/app/Filament/Resources/GatedXotBaseResource.php` che `extends XotBaseResource` + `use HasNavigationGate;` (per compat)
3. Aggiorna Resources una a una a usare `XotBaseResource` + `HasNavigationGate` direttamente
4. Rimuovi `GatedXotBaseResource` quando tutte le Resources sono migrate

Se Opzione C:
1. Rimuovi `GatedXotBaseResource`
2. Rimuovi `GatesResourceNavigation`
3. Rimuovi `NavigationGate` se non usato altrove
4. Aggiorna docs

# Story 4.2 — Platform: bootstrap rotto dal rename GatedXotBaseResource → XotBaseResource

## Understand

### Problem

Un run PHPStan su `Modules/Billing` (story 4.1, agente diverso da questo) fallisce in
bootstrap con:

```
Application bootstrap failed
Error: Class "Modules\Platform\Filament\Resources\XotBaseResource" not found
```

Causa (confermata con `git -C Modules/Platform blame`, modifiche non committate,
2026-09-07 14:40):

| File | Prima | Dopo | Import aggiunto? |
|---|---|---|---|
| `app/Filament/Resources/AuditLogResource.php:15` | `extends GatedXotBaseResource` | `extends XotBaseResource` | ❌ no |
| `app/Filament/Resources/PlatformSettingResource.php:24` | `extends GatedXotBaseResource` | `extends XotBaseResource` | ❌ no |

Nessuno dei due file ha `use Modules\Xot\Filament\Resources\XotBaseResource;`. PHP risolve
`XotBaseResource` bare nel namespace del file (`Modules\Platform\Filament\Resources`), che
non contiene quella classe. Il Panel Filament registra tutte le Resource all'avvio (per le
route): un bootstrap fallito su una Resource rompe l'intero comando PHPStan/artisan, non
solo il file toccato — impatta **tutti** gli agenti che stanno lavorando su qualunque
modulo in questo momento.

### Applicabilità

Il rename sembra una risposta meccanica alla stessa direttiva ricevuta anche su questa
sessione per Billing: "non usare `GatedXotBaseResource`, usa `XotBaseResource`
direttamente". Rename grezzo (probabile find/replace sulla riga `extends`) senza
aggiornare gli `use`.

### Root cause

1. **Bug meccanico immediato**: `use` mancante dopo il rename. Fix a costo zero.
2. **Domanda architetturale non risolta**: `GatedXotBaseResource` non è solo naming, fa un
   lavoro reale — `GatesResourceNavigation` (`Modules/Platform/app/Filament/Concerns/`)
   nasconde la voce di navigazione e blocca l'URL diretto in base a
   `NavigationGate::isItemEnabled(static::class)` (runtime feature toggle). Rimuoverlo da
   una Resource che dipende da quel gate è un cambio di comportamento visibile, non un
   refactor neutro.
   - `AuditLogResource`/`PlatformSettingResource`: nessun riferimento trovato in
     `CustomerPanelProvider`/`OperatorPanelProvider` che ne condizioni la visibilità via
     gate in modo diverso da `canViewAny()` nativo — impatto da verificare ma probabilmente
     basso.
   - `Billing\InvoiceResource` (story 4.1, altro file/altro agente): **registrato in
     `Modules/Platform/app/Providers/Filament/CustomerPanelProvider.php:42`**. Se anche
     questa Resource perde `GatedXotBaseResource`, il toggle `NavigationGate` smette di
     avere effetto per gli utenti del pannello cliente — regressione funzionale reale, non
     solo stilistica.

## Plan

1. Fix minimo (P0, sblocca tutti): aggiungere `use Modules\Xot\Filament\Resources\XotBaseResource;`
   ad `AuditLogResource.php` e `PlatformSettingResource.php`, o ripristinare
   `GatedXotBaseResource` se il gate serve anche li (verificare con `NavigationGate`
   config/seeder se questi due sono nell'elenco delle voci gate-abili).
2. Grep repo-wide di `extends XotBaseResource` senza `use` corrispondente, per escludere
   altre istanze dello stesso bug meccanico in altri moduli toccati dallo stesso rename.
3. Audit di ogni Resource che oggi estende `GatedXotBaseResource`: elencare quali sono
   effettivamente registrate in un panel con `NavigationGate` attivo, e quali lo estendono
   "per abitudine" senza mai essere gate-ate — solo queste ultime sono candidate sicure per
   il downgrade a `XotBaseResource` diretto.
4. Per `Billing\InvoiceResource` specificamente: NON rimuovere `GatedXotBaseResource` senza
   conferma esplicita che il toggle su `CustomerPanelProvider` non serve più, o senza
   sostituirlo con un meccanismo equivalente.
5. Quality gate su Platform (fase 4 di `03-quality-gates.md`) dopo il fix.

## Verify

- [ ] `./vendor/bin/phpstan analyse Modules --no-progress` non fallisce più in bootstrap
- [ ] `php artisan route:list` (o equivalente) carica tutti i panel senza errori
- [ ] Audit `GatedXotBaseResource` → elenco Resource con/senza gate realmente attivo
- [ ] Decisione esplicita e documentata su `Billing\InvoiceResource` (mantenere gate o
      migrare con sostituto), non un rename silenzioso

# 4.6: audit and reduce cross-module coupling on Modules\Platform

## Story

As a maintainer, following the user's explicit guidance 2026-09-07 ("non usare mai
GatedXotBasePage... percio' direi di cercare di non usare classi di platform"), I want an audit of
every module that references `Modules\Platform\*` classes directly, so each dependency is either
justified (a real shared service Platform legitimately owns) or removed/replaced with a
module-local equivalent — continuing the precedent already closed for `GatedXotBaseResource`
(4.4) and `GatedXotBasePage` (4.5).

## Scope (verified on code, 2026-09-07)

`grep -rl "Modules\\\\Platform\\\\" Modules/ --include="*.php" | grep -v "^Modules/Platform/"`
(excluding the already-resolved Gated* pattern) currently hits 12 modules: AiAssistant, Billing,
Compliance, Email, EnergyBroker, Intervention, Inventory, PublicProcurement, Quotation, WhatsApp,
WorkOrder, Wts.

This story is the AUDIT only — enumerate what each module actually imports from Platform and why,
classify each as (a) legitimate shared platform service, (b) another named-subclass anti-pattern
like Gated* that should be decoupled, or (c) accidental/avoidable coupling. Do NOT do a mechanical
mass-removal without understanding each case — the Gated* migrations already showed that a naive
rename without checking imports/usage can crash Filament bootstrap repo-wide
(`project_gatedxotbaseresource_migration_bootstrap_break_2026_09_07.md`).

## Acceptance Criteria

- [ ] Per-module table: which `Modules\Platform\*` classes/traits are used, in which files, for
      what purpose.
- [ ] Classification per finding: keep (justified), migrate (anti-pattern, follow Gated*
      precedent), or defer (needs owner decision — e.g. genuinely shared cross-module concern that
      may belong in Xot instead of Platform).
- [ ] For anything classified "migrate", open a follow-up story per module (don't do the actual
      migration in this audit story — same discipline as 4.4/4.5).
- [ ] Second-brain memory updated with the audit findings (reusable pattern, not a work log).

## Notes for tomorrow's agent

Read `[[pattern_no_gated_resource_subclass_naming]]` and `[[pattern_no_gated_page_subclass_naming]]`
first — same methodology, same caution about the bare-`use`-import bootstrap-crash footgun when a
file already lives inside `Modules\Platform\*` namespace itself.

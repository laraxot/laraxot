## Problema

Alla ricognizione di questa sessione, `phpstan analyse Modules/AiAssistant`
(cache pulita) risultava gia' a **0 errori** — atteso ~5 dal task, in realta'
gia' azzerati dalle sessioni precedenti (commit `62ec625` e `d793b7c`, story
2.8 wave B). Il working tree pero' non corrispondeva a `HEAD`: 3 file
mostravano il diff esattamente inverso del commit `d793b7c`
("refactor(aiassistant): type constants [story: 2.8]"), cioe' i type-hint
sulle costanti tipizzate risultavano rimossi di nuovo senza alcun commit
intermedio.

## Investigazione

mtime forensics sui file coinvolti, confrontati con l'orario del commit
`d793b7c` (2026-09-07 15:26:51 +0200 = epoch 1788787611):

| File | mtime | delta da commit |
|---|---|---|
| `AiActionPolicy.php` | 1788788722 | +18.5 min |
| `BuildSpokenSummaryAction.php` | 1788788722 | +18.5 min |
| `docs/coverage.md` | 1788788722 | +18.5 min |
| `SensitiveDataRedactor.php` | 1788800527 | +3h 36min |

Nessuna causa di dominio trovata: le tre classi sono tutte `final`, senza
interfacce ne' sottoclassi che vincolerebbero il tipo della costante; `php
-l` pulito in entrambe le versioni (tipizzata e non). Il fatto che
`SensitiveDataRedactor.php` sia stato toccato ~3h dopo gli altri due, e solo
su UNA delle 4 costanti modificate dal commit originale (`MASK`, non le 3
`array`), esclude un singolo comando "revert" volontario e punta a una
scrittura stale in una sessione concorrente sullo stesso working tree
condiviso (vedi second brain
`feedback_shared_filesystem_concurrent_sessions.md`), coerente col pattern
gia' noto `feedback_write_tool_no_read_check_race.md`.

## Fix

Ripristinati a mano (Edit mirato sulla singola riga, non `git checkout` — 
vietato dalle regole di progetto) i type-hint sulle 3 costanti:

- `app/Security/AiActionPolicy.php` — `public const DENIED_UNKNOWN_TYPE` /
  `DENIED_RATE_LIMIT` → `public const string ...`
- `app/Security/SensitiveDataRedactor.php` — `public const MASK` → `public
  const string MASK`
- `app/Speech/BuildSpokenSummaryAction.php` — `private const MAX_SENTENCES`
  / `MAX_CHARS` → `private const int ...`

Contenuto risultante verificato identico a quello introdotto da `d793b7c`.
Nessuna logica toccata. `docs/coverage.md` aggiornato: ripristinata la
sezione "sessione 2" che era stata cancellata dalla stessa scrittura stale,
aggiunta sezione "sessione 3" con questa diagnosi, e corretta una nota
obsoleta che dichiarava `phpinsights` "non installato" (falso, verificato
installato e funzionante con workaround `--config-path` per
`ForbiddenSecurityIssues`/`ComposerNotFound` su scope per-modulo — vedi
second brain `project_phpinsights_composer_lock_scoped_path.md`).

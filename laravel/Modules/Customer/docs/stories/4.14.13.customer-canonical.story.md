# Story 4.14.13 — Customer + Reseller — Filament canonical structure

## Understand

### Problem

`Modules/Customer/app/Filament/Resources/CustomerResource.php` (291 righe) e
`ResellerResource.php` (132 righe) sono entrambi inline `getFormSchema()` + `table()`.

`CustomerResource` inoltre:
- Ha **NavigationGate custom** (non via `HasAccountFeatureVisibility` trait): metodo
  privato `isAvailableInCurrentPanel()` con fallback basato su `request()->is('customer/*')`
  / `request()->is('supplier/*')`. Usato da `shouldRegisterNavigation/canViewAny/canCreate/
  canEdit/canView`. AGENTS regola: "CustomerResource ha NavigationGate verso
  Billing/InvoiceResource — **NON rimuovere la NavigationGate**, mantienila nel Resource
  slim".
- Override `getEloquentQuery()` con `AccountFeatures::scopeAssignedCustomers()` quando
  l'utente ha un perimetro assegnato nel pannello admin. Funzionalità reale, non stub.
- 3 relation managers: `WorkOrdersRelationManager`, `CustomerSitesRelationManager`,
  `ContactsRelationManager`.
- Global search attributes + search result details: logica custom, va mantenuta.

`ResellerResource` invece usa il trait `HasAccountFeatureVisibility` come standard.

Modelli: `Customer` e `Reseller` entrambi `SoftDeletes` → bulk actions devono includere
`RestoreBulkAction` + `ForceDeleteBulkAction` (patterns.md bug #1).

### Applicabilità

- **Contratto Form**: `XotBaseResource::getFormSchema()` auto-scopre
  `Schemas/<Model class_basename>Form.php` → `CustomerForm` + `ResellerForm`.
- **Contratto Table**: `getTableClass()` → `CustomersTable` + `ResellersTable`.
- **Infolist**: nessuna esposta, nessun `getInfolistSchema()` → nessun file creato (vedi
  nota QuotationTemplate per stessa scelta).
- **NavigationGate** (`isAvailableInCurrentPanel()`): logica runtime reale, NON solo
  configurazione. Patterns.md bug #3 ammonisce: rimuovere `GatesResourceNavigation` da una
  Resource gated è regressione funzionale. `CustomerResource::isAvailableInCurrentPanel()`
  è la versione custom dello stesso pattern — stessa regola.

### Root cause

Risorse scritte prima del prompt `06-filament-audit.md` v3.0.0.

## Plan

1. `CustomerResource/Schemas/CustomerForm.php`: section con TextInput legali + Grid(3)
   city/postal_code/province + Select country_code + Select payment_method (live, with
   `dehydrateStateUsing` su IBAN) + Textarea notes + Toggle is_active. 18 campi.
   `getFormSchemaColumns(): int = 2`.
2. `CustomerResource/Tables/CustomersTable.php`: colonne legal_name (FontWeight::Bold) +
   email (icon + copyable) + phone (icon) + city + is_active (IconColumn::boolean) +
   updated_at; `getTableActions()` View+Edit iconButton; `getTableBulkActions()`
   Delete+Restore+ForceDelete; `getTableFilters()` TernaryFilter is_active.
3. `ResellerResource/Schemas/ResellerForm.php`: Grid(2) name+user_id (relationship) +
   Textarea notes. `getFormSchemaColumns(): int = 2`.
4. `ResellerResource/Tables/ResellersTable.php`: name + user.name + updated_at;
   `getTableActions()` View+Edit; `getTableBulkActions()` Delete+Restore+ForceDelete.
5. Slimma entrambi i Resource: rimuovi `getFormSchema()` + `table()` + import non usati.
6. **MANTIENI** in `CustomerResource` slim: `getGloballySearchableAttributes()`,
   `getGlobalSearchResultDetails()`, `getEloquentQuery()` (con scope perimetro),
   `isAvailableInCurrentPanel()` (NavigationGate), tutti i `can*` con gate,
   `getNavigationSort()`, `getModelLabel/PluralModelLabel`, `getRelations()`, `getPages()`.
7. **MANTIENI** in `ResellerResource` slim: trait `HasAccountFeatureVisibility` + 3
   costanti `ACCOUNT_FEATURE_*` + `isAvailableInCurrentPanel()`.
8. `->label(__('customers.*'))` e `->label(__('resellers.*'))`: **mantenuti intatti**.
   Per patterns.md §"Non ancora risolto", `LangServiceProvider`/`AutoLabelAction` derivano
   la chiave dal nome classe chiamante; per Customer/Reseller le chiavi esistenti
   `customers.fields.*` / `resellers.fields.*` **non** collimano con la chiave auto-derivata
   `customer.fields.*` / `reseller.fields.*`. Rimozione `->label()` farebbe sparire il
   testo italiano curato. Migrazione chiavi lang è story separata (analoga a Billing 4.8/4.12).
9. `php -l` su 6 file.
10. `pint --dirty --test` su Customer (1 file da fixare post-scrittura, `fully_qualified_strict_types` + `ordered_imports`).
11. `phpstan` su Customer: bloccato da bug pre-esistente fuori scope (vedi Status).

## Implement

### Step 1 — `CustomerResource/Schemas/CustomerForm.php`

Spostato verbatim dal Resource. 96 righe. Section unica con 18 componenti, `columns(2)`.
Mantiene `->label(__(...))` su tutti i campi (vedi step 8).

### Step 2 — `CustomerResource/Tables/CustomersTable.php`

Attenzione: il `table()` inline originale aveva `toolbarActions([View, Edit, Delete,
Restore, ForceDelete])` — un mix record + bulk. Separato correttamente:
- `getTableActions()`: solo View + Edit (record actions)
- `getTableBulkActions()`: solo Delete + Restore + ForceDelete (bulk actions)

Aggiunto `getTableFilters()` per il `TernaryFilter('is_active')` che era inline.

### Step 3 — `ResellerResource/Schemas/ResellerForm.php`

Grid(2) name + user_id. Section wrapper con `columns(2)`.

### Step 4 — `ResellerResource/Tables/ResellersTable.php`

3 colonne: name + user.name + updated_at. Stesso pattern Customer.

### Step 5 — Resource slim

- `CustomerResource.php`: 291 → 145 righe. Rimosso schema+table+10 import.
- `ResellerResource.php`: 132 → 64 righe. Rimosso schema+table+8 import.

### Step 6-7 — NavigationGate mantenuto

`CustomerResource::isAvailableInCurrentPanel()` resta `private static` con logica
`request()->is()` fallback. Usato da 5 hook (`shouldRegisterNavigation`, `canViewAny`,
`canCreate`, `canEdit`, `canView`). Rimozione = tutti gli operatori perimetrali
vedono/creano/modificano customer fuori perimetro = regressione sicurezza.

`ResellerResource` ha già il trait — invariato.

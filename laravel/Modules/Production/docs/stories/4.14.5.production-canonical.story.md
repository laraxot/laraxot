# Story 4.14.5 — Filament canonical structure (Production)

## Understand

### Problem

`ProductionOrderResource` (1 Resource) viola il contratto `XotBaseResource`:
`getFormSchema()` e `table()` sono inline.

| Resource | `getFormSchema()` inline | `table()` inline | Complessità |
|----------|:-:|:-:|:-:|
| `ProductionOrderResource` | ✅ 44 righe | ✅ 22 righe | BASSA |

Rispetto a InventoryMovementResource la complessità è contenuta: nessun helper
statico da spostare, nessuna colonna condizionale. Caso didattico semplice che
segue lo stesso pattern.

## Plan

1. `ProductionOrderResource/Schemas/ProductionOrderForm.php`: 4 Grid, Select Product,
   Select WorkOrder, DateTimePicker, Textarea.
2. `ProductionOrderResource/Tables/ProductionOrdersTable.php`: 7 colonne,
   `defaultSort('id', 'desc')` → `getDefaultTableSortColumn()='id'`,
   `getDefaultTableSortDirection()='desc'`.
3. Slimming Resource: navigation + `getRelations()` + `getPages()` + gates.
4. Quality gate.

## Implement

### File creati

- `Schemas/ProductionOrderForm.php`: Section→Grid(2) code+status, Grid(2)
  product+quantity, Select work_order_id, DateTimePicker due_at, Textarea notes.
- `Tables/ProductionOrdersTable.php`: 7 TextColumn, `getTableActions()` view+edit,
  `getTableBulkActions()` delete, `getDefaultTableSortColumn()/Direction()` per id desc.

### File modificati (slimming)

- `ProductionOrderResource.php`: 160 → 73 righe. Rimossi `getFormSchema()`,
  `table()`. Rimasti: `$model`, `$navigationIcon`, `HasAccountFeatureVisibility`,
  `ACCOUNT_FEATURE_*` constants, `isAvailableInCurrentPanel()`, navigation labels,
  `getRelations()`, `getPages()`.

### Note su `HasXotTable` + `getDefaultTableSort*`

Come in WarehouseLocationsTable, `HasXotTable::table()` linea ~262-266 applica
`defaultSort` solo se `getDefaultTableSortColumn()` restituisce un valore
diverso da `null`. Override esplicito necessario perché il default di
`XotBaseResourceTable` non corrisponde a `id desc`.

## Verify

- `php -l` su tutti i 3 file Production: 0 errori.
- `./vendor/bin/pint --dirty --test` (scope HR/Inventory/Production): nessun
  file Production tra i dirty.
- `./vendor/bin/phpstan analyse Modules/Production ...` bloccato da pre-existing

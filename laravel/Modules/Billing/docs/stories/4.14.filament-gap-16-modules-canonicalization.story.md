# Story 4.14 — Filament canonical structure: 16 moduli gap completo

## Understand

### Scansione 2026-09-07 (filesystem-first)

145 Resources totali in 44 moduli. Mappatura `Schemas/` + `Tables/` + `Infolist/`:

#### Moduli CON gap completo (mancano Schemas/ + Tables/)

| Modulo | Resources | Note |
|--------|-----------|------|
| **Bom** | BomResource | Singola resource, vecchio pattern inline |
| **Catalog** | 6 Resources: CatalogFrequency, CatalogMeasureUnit, CatalogModel, CatalogPartType, MetelCatalog, Product | Tutte inline |
| **Compliance** | 5: ComplianceDocument, CustomerSystem, Equipment, HeatingSystem, Subcontractor | Tutte inline |
| **Customer** | 2: Customer, Reseller | Inline; Customer ha NavigationGate con Billing/InvoiceResource |
| **EnergyBroker** | 1: EnergyBrokerDocument | Inline |
| **HR** | 2: AbsenceRequest, Employee | Inline (Employee importante: relazioni con User) |
| **Intervention** | 2: DailyNote, Intervention | Intervention è la core resource |
| **Inventory** | 3: InventoryMovement, Warehouse, WarehouseLocation | Inline |
| **MetalWork** | 4: MetalDrawing, MetalPartEstimate, MetalRawMaterial, MetalWorkCenter | Inline, business-critical |
| **Platform** | 2: AuditLog, PlatformSetting | Bootstrap-critical (vedi doc 2026-09-07-gatedxotbaseresource) |
| **Production** | 1: ProductionOrder | Inline |
| **PublicProcurement** | 3: Contract, TenderOpportunity, TenderSource | Inline |
| **Quotation** | 1: QuotationTemplateResource | QuotationResource 438 righe inline, in lavorazione parallelo |
| **Signage** | 5: SignCatalogItem, SignEstimationRule, SignPriceList, SignPriceListItem, SignWorkCenter | Inline |
| **Timber** | 13: TimberAgent, TimberCustomerPrice, TimberCustomer, TimberDocument, TimberEInvoice, TimberInvoice, TimberPaymentInstallment, TimberPriceList, TimberProduct, TimberStockMovement, TimberSupplier, TimberTransporter, TimberWoodSpecies | Tutto inline, refactoring pesante |
| **WorkOrder** | 2: WorkOrder, WorkOrderStatus | WorkOrder è core, gestito da sessioni parallele |
| **Wts** | 1: UserResource | Verificare se estende XotBaseResource (potrebbe essere fork custom) |

#### Moduli CON gap parziale (hanno Schemas/ + Tables/ ma no Infolist)

Quasi tutti: nessuno finora ha Infolist separata in `Infolist/` (Billing la
ha solo dopo story 4.1).

#### Moduli CANONICALI (completi)

- **Billing** (4 Resources, dopo story 4.1)
- **Gdpr** (Consent, Event, Profile, Treatment)
- **Geo** (Address, Location)
- **User** (28 Resources, già canonical)
- **Xot** (CacheLock, Cache, Extra, Log, Module, Session — base infrastruttura)

### Perché la struttura è obbligatoria (sintesi)

1. **DRY/KISS**: 1 concetto = 1 file. 145 Resources × 3 schemi inline = 430+ file
   duplicati se non canonici.
2. **Testabilità**: Schemas/Infolist/Table testabili in isolamento, Resource
   testabile per navigation/pages/relations.
3. **Conflitti**: 145 Resources in 44 moduli + agenti paralleli = conflitti
   inevitabili. File separati = merge più semplici.
4. **Theming**: temi sovrascrivono views dei componenti, non classi PHP. Le
   classi `Schemas/<Name>Form` sono i provider di componenti, e le loro view
   blade sono il punto di override (vedi
   `Themes/docs/wiki/rules/filament-canonical-structure.md`).

## Plan

### Strategia operativa: swarm parallelo modulare

Ogni agente/swarm prende **1-2 moduli** e:

1. Per ogni Resource: crea `Schemas/<Name>Form.php` + `Schemas/<Name>Infolist.php`
   + `Tables/<Plural>Table.php` estraendo lo schema inline.
2. Sostituisce `$this->getFormSchema()` con `Schemas/<Name>Form::configure($schema)`.
3. Verifica PHPStan + Pint.
4. Aggiorna `Modules/<Modulo>/docs/filament/patterns.md` (se non esiste, crea).

### Priorità (P0 → P3)

| Priority | Moduli | Note |
|----------|--------|------|
| **P0** | WorkOrder, Customer, Platform, HR, Employee | Core business, relazioni con Billing, User |
| **P1** | Quotation (completamento), Intervention, Inventory, Production, Bom | Core operations |
| **P2** | MetalWork, Signage, Catalog, Timber | Moduli verticali, alto debito tecnico ma isolati |
| **P3** | Compliance, EnergyBroker, PublicProcurement, Wts | Moduli minori |

### Modulo 1: esempio di completamento (template riusabile)

```php
// Modules/Billing/app/Filament/Resources/DeliveryNoteResource/Schemas/DeliveryNoteForm.php
final class DeliveryNoteForm extends XotBaseResourceForm
{
    protected static string $resource = DeliveryNoteResource::class;

    public function getFormSchemaColumns(): int { return 2; }

    public function getFormSchema(): array
    {
        return [
            'section' => Section::make()->columnSpanFull()->components([...]),
        ];
    }
}
```

Stesso template per Infolist/Table.

### Lock per-file (regola swarm)

Ogni agente DEVE usare:
```bash
bashscripts/lock/{check,lock,unlock}.sh
```
prima di editare qualsiasi file (multi-agente parallelo).

## Verify

Per ogni modulo swarrmato:

- [ ] Tutte le Resources hanno `Schemas/<Name>Form.php` + `Schemas/<Name>Infolist.php`
- [ ] Tutte le Tables hanno `Tables/<Plural>Table.php`
- [ ] Nessuna resource ha `getFormSchema()` / `table()` / `getInfolistSchema()` inline
- [ ] PHPStan → 0 errori sul modulo
- [ ] Pint → passed
- [ ] Pest verde (o failures pre-esistenti documentate)
- [ ] `Modules/<Modulo>/docs/filament/patterns.md` aggiornato

# Story 4.1 — Filament gap canonical structure (Billing)

## Understand

### Problem

Audit del modulo Billing (Filament Resources) rivela 4 violazioni strutturali rispetto al contratto `XotBaseResource` (Xot):

| Resource | `Schemas/<Name>Form.php` | `Schemas/<Name>Infolist.php` | `Tables/<Plural>Table.php` | `getFormSchema()` inline | `table()` inline |
|----------|:-:|:-:|:-:|:-:|:-:|
| `DeliveryNoteResource` | ❌ | ❌ | ❌ | ✅ sì | ✅ sì |
| `InvoiceResource` | ❌ | ❌ | ❌ | ✅ sì | ✅ sì |
| `SupplierResource` | ❌ | ❌ | ❌ | ✅ sì | ✅ sì |
| `SupplierInvoiceResource` | ❌ | ❌ | ❌ | ❌ | ❌ |

Tutte e 4 le Resource estendevano `GatedXotBaseResource` (vietato — SEMPRE `XotBaseResource` diretto) e caricano `getFormSchema()` (e `table()` per 3 di esse) inline, inquinando il Resource e bypassando l'auto-scoping di `XotBaseResource::getFormSchemaOld()`.

In aggiunta: oltre 30 occorrenze di `->label(__('billing::...'))` hardcoded in 3 Resources, in violazione del vincolo "LangServiceProvider automatico, zero `->label()`".

### Applicabilità

- **Contratto**: `XotBaseResource.php:112-129` definisce `getFormSchema()` come entry point e `getFormSchemaOld()` come fallback legacy. Le Resource Billing usano il fallback (override diretto) invece della convenzione `Schemas/`.
- **Auto-scoping**: `XotBaseResource.php:138-148` cerca `static::class.'\Schemas\\'.$name.'Form'` con naming convention; non trovandolo ricade su `getFormSchema()` statico del consumer.
- **Pattern canonico**: `Modules\Gdpr\Filament\Resources\ConsentResource\Schemas\ConsentForm.php` (riferimento).
- **Prompt trigger**: `bashscripts/docs/prompts/06-filament-audit.md` (versione 3.0.0).

### Root cause

Prompt `06-filament-audit.md` v2.0.0 documentava la struttura canonica ma non rilevava automaticamente il gap (silent assumption). v3.0.0 aggiunge §1 Ricognizione filesystem esplicita. Le 4 Resources Billing sono state scritte prima del prompt v3.0.0 e sono drifted.

## Plan

1. **Migliora prompt 06-filament-audit.md v3.0.0** (già fatto): filesystem-first pre-step, gap detection tabella, ricetta migrazione legacy.
2. **DeliveryNoteResource**: estrai `getFormSchema()` → `Schemas/DeliveryNoteForm.php`; estrai `table()` → `Tables/DeliveryNotesTable.php`; crea `Schemas/DeliveryNoteInfolist.php` da model.
3. **InvoiceResource**: idem con `InvoiceForm` / `InvoicesTable` / `InvoiceInfolist`.
4. **SupplierResource**: idem con `SupplierForm` / `SuppliersTable` / `SupplierInfolist`.
5. **SupplierInvoiceResource**: solo creazione `Schemas/SupplierInvoiceForm.php` + `Tables/SupplierInvoicesTable.php` + `Schemas/SupplierInvoiceInfolist.php` (non ha inline).
6. **Rimuovi `->label(__('billing::...'))`**: verificare se LangServiceProvider copre; se no, creare chiavi lang mancanti.
7. **Quality gate**: phpstan + pest su Billing.
8. **Docs**: aggiorna `Modules/Billing/docs/filament/patterns.md` con pattern + backlink a story.
9. **Second brain**: write-back pattern "Resource legacy inline → classi Schemas/Tables" in `docs/wiki/`.

### Step 2-5 — Estrazione classi

Naming convention (vincolata da `XotBaseResource.php:138-148`):

```php
// DeliveryNoteResource → DeliveryNoteForm, DeliveryNoteInfolist, DeliveryNotesTable
// InvoiceResource → InvoiceForm, InvoiceInfolist, InvoicesTable
// SupplierResource → SupplierForm, SupplierInfolist, SuppliersTable
// SupplierInvoiceResource → SupplierInvoiceForm, SupplierInvoiceInfolist, SupplierInvoicesTable
```

Pattern canonico di riferimento (`Modules/Gdpr/.../ConsentForm.php`):

```php
<?php
declare(strict_types=1);

namespace Modules\<M>\Filament\Resources\<Name>Resource\Schemas;

use Modules\<M>\Filament\Resources\<Name>Resource;
use Modules\Xot\Filament\Resources\Schemas\XotBaseResourceForm;

final class <Name>Form extends XotBaseResourceForm
{
    protected static string $resource = <Name>Resource::class;

    /**
     * @return array<int, \Filament\Schemas\Components\Component>
     */
    public static function getFormSchema(): array
    {
        // ... estratto dal Resource legacy
    }

    public static function getFormSchemaColumns(): int
    {
        return 2;
    }
}
```

Per Tables (stesso pattern con `XotBaseResourceTable`):

```php
<?php
declare(strict_types=1);

namespace Modules\<M>\Filament\Resources\<Name>Resource\Tables;

use Filament\Tables\Filters\SelectFilter;
use Modules\<M>\Filament\Resources\<Name>Resource;
use Modules\Xot\Filament\Resources\Tables\XotBaseResourceTable;

final class <Plural>Table extends XotBaseResourceTable
{
    protected static string $resource = <Name>Resource::class;

    // NON ridefinire table() — HasXotTable.php:220 lo fornisce
    // Override hook se servono:
    // public function getTableColumns(): array { ... }
}
```

**ATTENZIONE**: `XotBaseResourceTable` non auto-scopre le tabelle custom allo stesso modo dei Form. La classe Table va **esplicitamente** indicata nel Resource. Verificare se esiste un metodo come `getTableClass()` su `XotBaseResource`.

### Step 6 — Hardcoded `->label(__('...'))`

Per ogni `->label(__('billing::suppliers.fields.X'))`:
- Se la traduzione esiste in `lang/it/suppliers.php`: rimuovere `->label()` (auto da LangServiceProvider).
- Se NON esiste: creare la chiave in `lang/it/<file>.php` poi rimuovere `->label()`.

Verificare che `LangServiceProvider` del modulo sia registrato in `app/Providers/Filament/AdminPanelProvider.php`.

## Plan

### Fase 1 — Ricognizione per modulo

Per ogni modulo (ordinato per priorita'):

```bash
cd laravel/Modules/<M>
bash bashscripts/tools/filament_audit.sh <M>  # vedi 06-filament-audit.md §Script
```

Output: tabella con Resource → Schemas/ mancante? → Tables/ mancante? → getFormSchema inline? → table() inline? → label hardcoded?

### Fase 2 — Categorizzazione per modulo

Tre categorie:

**A — Resource con schema/table inline + file gia' strutturati** (es. Blog ha 5/8 strutturati): Estrarre gli inline in Schemas/ e Tables/, rimuovere dal Resource. Risultato: 100% canonical.

**B — Resource senza Schemas/Tables (nessuna)**: Verificare se la Resource e' attiva o legacy/disabilitata. Se attiva: creare Schemas/ + Tables/ da zero (model + migration come riferimento). Se legacy: documentare e proporre rimozione.

**C — Resource con mix parziale**: Solo alcune risorse con Schemas/Tables mancanti — completare.

### Fase 3 — Implementazione per modulo

Stessa ricetta di story 4.1 per ogni Resource:

1. Crea `Schemas/<Name>Form.php extends XotBaseResourceForm`
2. Crea `Schemas/<Name>Infolist.php extends XotBaseResourceInfolist`
3. Crea `Tables/<Plural>Table.php extends XotBaseResourceTable`
4. Rimuovi `getFormSchema()` / `table()` dal Resource
5. Rimuovi `->label(__('...'))` hardcoded (LangServiceProvider automatico)
6. Quality gate: PHPStan + Pint

### Fase 4 — Coordinamento multi-agente

Ogni modulo e' un repo indipendente. Pianificare chi fa cosa:
- Agente A: Timber + Catalog (priorita' P1)
- Agente B: Signage + Compliance
- Agente C: Inventory + Blog + Quotation + PublicProcurement
- Agente D: MetalWork + Customer + HR + Intervention
- Agente E: Bom + EnergyBroker + Production + Platform

### Fase 5 — Coordinamento con Platform story 4.2

Platform ha 2 Resources (`AuditLogResource`, `PlatformSettingResource`) che estendevano `GatedXotBaseResource` — ora fixati ma senza Schemas/Tables. Coordinare con story 4.2 per evitare doppio lavoro.

# Story 5.71 — Billing: typeCoverage costanti (16 errori)

Continuazione delle story project-wide `2.8.phpstan-constant-type-coverage.story.md`
e `5.1.phpstan-constant-type-coverage-remaining.story.md` (campagna 49% → 64.3% →
66.8% → 84.1%, sessione 2026-09-07). Batch finale Billing (16/100 residui al
momento del claim in `docs/chat/2026-09-07-claim-typecoverage-final-push-swarm.md`).

## Understand

PHPStan Level 10 (bleeding edge) segnala `typeCoverage.constantTypeCoverage` — una
metrica PROJECT-WIDE (302 costanti totali nel repo), non per-file: scansionare il
solo modulo Billing risultava già "0 errori" perché la soglia si applica all'intero
`./Modules/`. Serviva lo scan full-tree (`phpstan analyse Modules`) filtrato per
`/Billing/` per individuare le 16 righe reali.

Le costanti avevano già un docblock `/** @var string */` / `/** @var int */`, ma
PHPStan bleeding-edge conta solo il tipo nativo PHP 8.3+ sulla dichiarazione
(`public const string FOO = ...`), non l'annotazione docblock: da qui i 16 falsi
"non tipizzati" nonostante l'intento di tipizzazione fosse già presente nel codice.

### File coinvolti (5 file, 16 costanti)

- `app/Actions/ReconcileSupplierInvoiceAction.php:27` — `EPSILON` → `private const float`
- `app/Datas/AgingBuckets.php:16,19,22,25,28` — 5 costanti stringa → `public const string`
- `app/Datas/PreInvoiceLine.php:14,18,22,26` — 4 costanti stringa (avevano `@var string` duplicato due volte) → `public const string`
- `app/Datas/ReconciliationDiscrepancy.php:15,19,23,27` — 4 costanti stringa (commento descrittivo mantenuto, `@var string` ridondante rimosso) → `public const string`
- `app/Queries/GetJobMarginsQuery.php:33,42` — `HOURLY_LABOUR_COST_SETTING` (string) e `DEFAULT_HOURLY_LABOUR_COST_CENTS` (int) → tipizzate native

## Plan

1. Per ogni costante, sostituire il docblock `@var` con il tipo nativo PHP 8.3+
   sulla dichiarazione stessa (`public const string FOO = 'bar';`), rimuovendo il
   docblock `@var` ridondante ma conservando i commenti descrittivi del dominio.
2. `declare(strict_types=1);` già presente su tutti i file, invariato.
3. `phpstan analyse Modules/Billing --no-progress --memory-limit=-1` → 0 errori (già 0 prima, per lo scope singolo modulo).
4. `phpstan analyse Modules --no-progress --memory-limit=-1 --error-format=raw | grep '/Billing/'` → 0 righe `constantTypeCoverage` (era 16).
5. Pest mirato: `pest Modules/Billing/tests/Unit/ReconcileSupplierInvoiceActionTest.php --no-coverage` (copre `EPSILON` e `ReconciliationDiscrepancy::TYPE_*`).
6. PHPMD sui 5 file: `./tools/phpmd.sh <files> text Modules/Billing/phpmd.ruleset.xml` → 0 violazioni.

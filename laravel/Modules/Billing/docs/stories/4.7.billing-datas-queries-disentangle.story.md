# Story 4.7 — Billing: disentangle modifiche altri agenti

## Understand

### Situazione

`git status` in `laravel/Modules/Billing` mostra 5 file modificati che NON ho toccato durante la story 4.1:

| File | Diff | Probabile autore |
|------|------|------------------|
| `app/Datas/AgingBuckets.php` | +5 righe | altro agente (claude sonnet 5) |
| `app/Datas/PreInvoiceLine.php` | +8 righe | altro agente |
| `app/Datas/ReconciliationDiscrepancy.php` | +4 righe | altro agente |
| `app/Queries/GetJobMarginsQuery.php` | +2 righe | altro agente |
| `README.md.lock` (rimosso) | lock orfano | (mio cleanup) |

Questi file sono "intrusi" nel mio commit. Se committato insieme, si rischia:
- Conflitti con il commit dell'altro agente
- Perdita di lavoro dell'altro agente (se il mio commit sovrascrive)
- Cronologia confusa

## Plan

### Opzione A — Separa in due commit (consigliata)

```bash
cd laravel/Modules/Billing

# 1. Commit solo Datas/Queries (recuperare le modifiche dell'altro agente)
git add app/Datas/AgingBuckets.php app/Datas/PreInvoiceLine.php app/Datas/ReconciliationDiscrepancy.php app/Queries/GetJobMarginsQuery.php
git commit -m "chore(billing): preserve Datas/Queries changes from concurrent agent

Le modifiche sono di un altro agente (claude sonnet 5) — preservate per non
perdere il lavoro. Da coordinare in docs/chat/INDEX.md per evitare conflitti.

Refs: 4.7.billing-datas-queries-disentangle"

# 2. Commit solo Filament (4 Resources)
git add app/Filament/Resources/ docs/stories/4.1*
git commit -m "refactor(billing): filament canonical structure migration [story: 4.1]

- 4 Resources migrate a Schemas/ + Tables/ + Infolist
- -560 righe rimosse dai Resources (inline form/table)
- GatedXotBaseResource → XotBaseResource diretto
- Zero ->label() hardcoded (LangServiceProvider)

Refs: 4.1.filament-resource-gap-billing"
```

### Opzione B — Stash e lascia decidere all'altro agente

```bash
cd laravel/Modules/Billing
git stash push app/Datas/ app/Queries/
# Messaggio all'altro agente in docs/chat/
```

Meno sicuro: lo stash potrebbe dimenticarsi.

### Opzione C — Force commit di tutto

Sconsigliata: causa conflitti.

## Decisione richiesta

- **Opzione A** se l'altro agente ha già committato/è in stato noto
- **Opzione B** se ancora attivo e non ha finito
- **Opzione C** mai

## Verify

- [ ] `git status` → solo i 4 file Filament (post-Opzione A)
- [ ] `git log --oneline -5` → due commit separati (Opzione A)
- [ ] `git diff laraxot/dev` → solo cambiamenti Filament, niente Datas/Queries conflict
- [ ] `phpstan analyse Modules/Billing` → ancora 0 (o stabile)

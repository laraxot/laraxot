# Story 4.10 — Second brain: write-back approfondito

## Understand

### Lezioni apprese nella sessione 4.1

#### Lezione 1: Filesystem before assertions (regola vitale)

Mai fidarsi della memoria. Il codice dice la verita. Il prompt dice lo stato atteso.
Prima si legge il filesystem, poi si genera codice o prompt.

**Pattern corretto:**
```bash
# SEMPRE prima di scrivere codice
find Modules/<M>/app/Filament/Resources -type f | sort
```

**Anti-pattern (errore 4.1):**
Ho scritto il prompt 06-filament-audit.md descrivendo la struttura attesa di
DeliveryNoteResource senza prima eseguire find. Ho generato 250 righe basandomi
sulla conoscenza astratta. Il filesystem mostrava che mancavano Schemas/ e Tables/.

#### Lezione 2: Schemas/Tables obbligatori da codice

Il commento in XotBaseResource.php:138-148 e' esplicito:
la classe Schemas/<Name>Form e' OBBLIGATORIA per l'auto-scoping.
Il bridge getFormSchemaOld() e' solo temporaneo.

Non e' una convenzione style: e' un requisito architetturale.

#### Lezione 3: ZERO ->label() e' gia nel codebase

La convenzione esiste gia in 21-translations.md, 55-md-conventions.md,
YAML-FRONTMATTER-CONVENTION.md. L'ho applicata nei nuovi file ma l'ho
ignorata nella versione precedente del prompt.

**Caveman lesson**: i vincoli vanno letti PRIMA di scrivere.

#### Lezione 4: GatedXotBaseResource vietato

Il prompt gia diceva "NO GatedXotBaseResource". Ho usato
GatedXotBaseResource nei file PHP perche era gia nel codice esistente.
Violazione silenziosa: non ho verificato che la regola del prompt fosse rispettata
nel codice che editavo.

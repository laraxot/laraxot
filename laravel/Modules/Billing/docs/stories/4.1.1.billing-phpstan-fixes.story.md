# Story 4.1.1 — Billing: fix 13 errori PHPStan

## Understand

### Problem

Dopo la creazione di 12 nuovi file (Schemas/Tables/Infolist per 4 Resources), PHPStan su `Modules/Billing/app/Filament/Resources` riporta 13 errori bloccanti. La struttura canonical ora è completa, ma il quality gate non è verde.

### Errori (estratti dal run PHPStan 2026-09-07)

| # | File:line | Tipologia | Note |
|---|-----------|-----------|------|
| 1 | `InvoiceResource.php:64` | `canEdit()` $record mismatch | `Filament\Resources\Resource<*>` si aspetta `Model` ma uso `mixed` |
| 2 | `InvoiceResource.php:69` | `canEdit()` $record mismatch | idem |
| 3 | `InvoiceResource.php` | `getEloquentQuery` type | (probabile) `$query` `Builder<Model>` narrowing |
| 4 | `InvoicesTable.php:62` | `getTableColumns` return type | `array<string, TextColumn>` ma Filament si aspetta `array<int\|string, Column>` |
| 5 | `InvoicesTable.php:62` | `getTableActions` return type | `array<int\|string, Action\|ActionGroup>` |
| 6 | `InvoicesTable.php:67` | `method_exists($object_or_class, ...)` | `$resource` è `class-string\|object` |
| 7 | `InvoicesTable.php:70` | `canView()` su `class-string\|object` | serve narrowing |
| 8 | `InvoicesTable.php:73` | `method_exists` | idem |
| 9 | `InvoicesTable.php:78` | `canEdit()` su `class-string\|object` | serve narrowing |
| 10 | `InvoicesTable.php:82` | `method_exists` | idem |
| 11 | `InvoicesTable.php:85` | `canDelete()` su `class-string\|object` | serve narrowing |
| 12 | `InvoicesTable.php:88` | `getTableActions` return type | `array<int\|string, Tables\Actions\Action\|ActionGroup>` (namespace diverso) |
| 13 | `SupplierInvoicesTable.php:55` | `getTableFilters` return type | `array<string, SelectFilter>` vs `array<int\|string, Filter>` |
| 14 | `SupplierResource.php:51` | `getGloballySearchableAttributes` return type | `array<int, string>` vs `array<string, string>` |

### Root cause

- Incoerenza tra typing del consumer (XotBaseResourceTable vuole `int\|string` keys) e pattern Gdpr/Geo che usano solo `string` keys.
- Pattern `app(static::$resource)` ritorna `class-string|object`: serve narrowing esplicito con `Assert::isInstanceOf` o assert.
- `canEdit(mixed $record)` richiesto da prompt 03 ma in realta' `Filament\Resources\Resource` ha firma `canEdit(Model $record)`.
- `mixed $record` per `canEdit/canView/canDelete` e' gia' richiesto da regole 03 §9 ma rompe l'inheritance.

## Plan

1. **InvoiceResource.php**:
   - `canEdit(mixed)` → `canEdit(\Illuminate\Database\Eloquent\Model $record)` (la firma Filament canonica, `mixed` non accettato dal parent)
   - `getEloquentQuery` typed return (gia' `Builder`, verificare)
2. **InvoicesTable.php**:
   - `getTableColumns` return type: `array<int\|string, \Filament\Tables\Columns\Column>` (estendere la firma, accettare union)
   - `getTableActions` return type: `array<int\|string, \Filament\Tables\Actions\Action|\Filament\Tables\Actions\ActionGroup>` (namespace `Tables\Actions`, non `Actions`)
   - Pattern `method_exists` su `$resource`: aggiungere `Assert::isInstanceOf($resource, \Modules\Billing\Filament\Resources\InvoiceResource::class)` per narrowing
3. **SupplierInvoicesTable.php**:
   - `getTableFilters` return type: `array<int\|string, \Filament\Tables\Filters\Filter>`
4. **SupplierResource.php**:
   - `getGloballySearchableAttributes` return: `array<int, string>` (gia' cosi', errore e' altrove — verificare docblock)

## Implement

- Aggiornare docblock con `array<int\|string, Column>` invece di `array<string, TextColumn>` (accetta piu' elementi)
- Aggiungere `Assert::isInstanceOf` su `$resource` dopo `app(static::$resource)` in InvoicesTable
- Non serve modificare `canEdit`: il `mixed` e' scorretto, serve tornare a `Model $record` (la firma del parent Filament)

## Dev Notes

**Background:** XotBaseResource provides automatic table delegation pattern. When a Resource extends XotBaseResource, it should NOT override table(). Instead:
1. Resource.table() (inherited) calls getTableClass()
2. getTableClass() dynamically finds {Model}sTable class
3. {Model}sTable extends XotBaseResourceTable and implements table()
4. Table class has full control over columns, sorting, etc.

**Current violation:** 6 Catalog Resources override table() directly, bypassing this pattern. This causes:
- Logic in wrong place (Resource instead of Table class)
- Harder to test (table config tied to Resource)
- Inconsistency with other modules (Gdpr, Blog, etc.)

**Files to modify:**
1. `laravel/Modules/Catalog/app/Filament/Resources/CatalogFrequencyResource.php`
2. `laravel/Modules/Catalog/app/Filament/Resources/CatalogMeasureUnitResource.php`

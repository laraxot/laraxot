# Story 2.1: Add Return Type Declarations to Factory create/createOne Methods

**As a** developer completing PHPStan Level 10 compliance  
**I want** factory methods create() and createOne() to have explicit return types  
**So that** seeders calling factory()->create() no longer report "Cannot call method on mixed"

## Acceptance Criteria

1. All Catalog factory classes have `create(array): Collection<Model>` return type
2. All Catalog factory classes have `createOne(array): Model` return type
3. Seeders in Catalog that call factory()->create() compile without "method.nonObject" errors
4. PHPStan Catalog scan reports 0 seeder-related method.nonObject errors
5. No new PHPMD or PHPInsights violations introduced
6. Pest coverage maintained or incremented for factory-related tests

## Tasks

## Dev Notes

**Root cause:** Seeders in Catalog call `CatalogFrequency::factory()->create()`. The factory `create()` method (inherited from Eloquent Factory) lacks explicit return type, so PHPStan infers mixed. This cascades to 2+ method.nonObject errors per seeder.

**Solution:** Override create() and createOne() in each factory class with explicit return types pointing to the model class. This provides PHPStan with concrete type information.

**Files affected:**
- `laravel/Modules/Catalog/database/factories/*.php` (all factory files)
- `laravel/Modules/Catalog/database/seeders/*.php` (verification only)
- `laravel/Modules/Catalog/docs/coverage.md` (new or updated)

**PHPStan config:** Do NOT edit phpstan.neon. All fixes are in PHP code.

[Source: Phase 1 analysis — 250 method.nonObject errors traced to seeders; Catalog seeders reported: CatalogFrequencySeeder, CatalogMeasureUnitSeeder, CatalogModelSeeder, CatalogPartTypeSeeder, ProductSeeder (5 files × 2 errors each = ~10 errors per factory class)]

# BMAD Story — Catalog Filament canonical structure (4.14.10)

## Understand

6 Resources Catalog avevano schema/table inline. ProductResource è l'unica con
`SoftDeletes` (Restore/ForceDelete bulk necessari, non solo `DeleteBulkAction` —
pattern Billing bug #1). MetelCatalogResource ha 2 custom table actions
(`importFile`, `syncApi`) che richiedono `array` di action tipizzate nel
`getTableActions()` override.

Risorse toccate:

- `CatalogFrequencyResource` (104 → 56 righe)
- `CatalogMeasureUnitResource` (101 → 55 righe)
- `CatalogModelResource` (92 → 51 righe)
- `CatalogPartTypeResource` (92 → 51 righe)
- `MetelCatalogResource` (224 → 60 righe) — più complesso
- `ProductResource` (154 → 60 righe) — SoftDeletes

## Plan

1. Estrarre `getFormSchema()` in `Schemas/<Name>Form.php`
2. Estrarre `table()` in `Tables/<Plural>Table.php` con tutte le actions (incluse custom)
3. Estrarre `getInfolistSchema()` in `Schemas/<Name>Infolist.php`
4. Slim del Resource: navigation + pages + account features + relations
5. ProductResource: `getTableBulkActions()` include Restore + ForceDelete (SoftDeletes)
6. MetelCatalogResource: custom `Action::make('importFile'/'syncApi')` preservate identiche

## Implement

**6 Resources slim**:
- `CatalogFrequencyResource.php` — preserva `HasAccountFeatureVisibility` + `ACCOUNT_FEATURE_*` constants
- `CatalogMeasureUnitResource.php` — idem
- `CatalogModelResource.php` — idem
- `CatalogPartTypeResource.php` — idem
- `MetelCatalogResource.php` — preserva `RelationManagers\ItemsRelationManager::class` esplicito
- `ProductResource.php` — idem + `Pages\CreateProduct` ecc.

**18 classi nuove** (6 Resources × 3):

| Resource | Form | Table | Infolist |
|---|---|---|---|
| CatalogFrequency | `CatalogFrequencyForm` | `CatalogFrequenciesTable` | `CatalogFrequencyInfolist` |
| CatalogMeasureUnit | `CatalogMeasureUnitForm` | `CatalogMeasureUnitsTable` | `CatalogMeasureUnitInfolist` |
| CatalogModel | `CatalogModelForm` | `CatalogModelsTable` | `CatalogModelInfolist` |
| CatalogPartType | `CatalogPartTypeForm` | `CatalogPartTypesTable` | `CatalogPartTypeInfolist` |
| MetelCatalog | `MetelCatalogForm` | `MetelCatalogsTable` | `MetelCatalogInfolist` |
| Product | `ProductForm` | `ProductsTable` | `ProductInfolist` |

**ProductResource SoftDeletes**:
```php
public function getTableBulkActions(): array
{
    return [
        'delete' => DeleteBulkAction::make(),
        'restore' => RestoreBulkAction::make(),
        'forceDelete' => ForceDeleteBulkAction::make(),
    ];
}
```

**MetelCatalogResource custom actions** (preservate identiche con `Action::make()`):
- `importFile`: schema Select format + FileUpload, action che dispatcha
  `ImportMetelPriceListFileAction` e mostra Notification success/fail
- `syncApi`: requiresConfirmation, action `FetchMetelCatalogViaApiAction::execute()`,
  catch `RuntimeException` → Notification danger

**Le 4 Resources anagrafiche piccole** (Frequency/MeasureUnit/Model/PartType)
condividono lo stesso pattern: form sezione singola con 1-2 campi, table 1-2
colonne, infolist sezione singola.

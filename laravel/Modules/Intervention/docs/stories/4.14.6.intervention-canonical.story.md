# BMAD Story — Intervention canonical structure

## Understand

Issue: laraxot/bashscripts_fila5#10. Le 2 Resource di Intervention (`DailyNoteResource`, `InterventionResource`) tenevano `getFormSchema()`, `getInfolistSchema()` e `table()` inline in file mostruosi:

- `DailyNoteResource.php`: 309 righe, 50% markup schema/table
- `InterventionResource.php`: 1387 righe (1.387!), con form complesso (Repeater materiali, work_hours, notes suggerimenti live, photo upload), tabella con 17 colonne e 4 record action custom (start/stop time punch, validate, upload photos)

Conflitti in monorepo multi-agente: 314 Resources in 44+ moduli, agenti paralleli su stesso file = race condition garantita.

## Plan

1. Estrarre `getFormSchema()` → `Schemas/DailyNoteForm.php` + `Schemas/InterventionForm.php`
2. Estrarre `getInfolistSchema()` → `Schemas/DailyNoteInfolist.php` + `Schemas/InterventionInfolist.php`
3. Estrarre `table()` → `Tables/DailyNotesTable.php` + `Tables/InterventionsTable.php`
4. Slimma ogni Resource a navigation + pages + relations
5. Lint + pint + phpstan

### File modificati (2)
- `DailyNoteResource.php`: 309 → 145 righe, contiene solo navigation/pages/can*/getEloquentQuery
- `InterventionResource.php`: 1387 → 246 righe, contiene solo navigation/pages/getEloquentQuery/normalizeFormData/extractPersistableData/syncSupplementalData/getRelations/isDirectCustomerMode/isAvailableInCurrentPanel

### Helper method spostati
- `InterventionForm::materialLinesFormState()` / `previewMaterialsTotal()` / `computeManualMaterialsTotal()` / `getPreviousNoteSuggestions()` / `applyNoteSuggestion()` / `normalizeTextState()` → ora nella Form (chiamati dal form stesso)
- `InterventionForm::extraStatusOptions()` / `ensureString()` / `notePhotoDirectory()` / `isDirectCustomerMode()` → Form
- `InterventionsTable::isAssignedToUser()` / `ensureString()` → Table
- `InterventionResource::normalizeFormData()` / `extractPersistableData()` / `syncSupplementalData()` → Resource (hook pipeline, non spostabili)

### Trade-off
Per non rompere l'auto-discovery di `XotBaseResource::form()` (`Schemas\<Model>Form::configure()`), la Resource continua a esporre `getFormSchema()` come **bridge**: delega a `Schemas/<Name>Form::configure(Schema::make())->getComponents()`. Stesso pattern per `getFormSchemaColumns()`. Stesso bridge per `table()` (che delega al metodo statico del Table).

Per `DailyNoteForm::photoDirectory()` / `extractUserId()` / `castMixedToString()` / `richTextColors()`: helper privati interni alla Form. Visto che il codice originale li teneva come `public static` sulla Resource, non sono API pubbliche: l'unico consumer era il form stesso. Nessuna rottura.

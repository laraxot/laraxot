# Migrate Email Module to Deprecate and Remove

## Objective

Complete Email module deprecation. All email sending delegates to Notify::EmailChannel. Email module becomes stub with deprecation warnings. Remove in next major version.

## Context

**Blocker:** Depends on Notify story `01.consolidate-email-into-notify`. Notify must have EmailChannel first.

**Why This Story Follows:** Once Notify has EmailChannel, Email module updates all its public APIs to redirect to Notify with deprecation warnings.

**Current State (after Notify story):**
- Notify has EmailChannel, email templates migrated
- Email module still exists, domain modules still import Email directly
- Need to redirect Email imports to Notify

## Deliverables

### 1. Create Deprecation Proxy (Phase 1)

Create `Modules/Email/app/Deprecated/EmailDeprecationProxy.php`:

```php
class EmailDeprecationProxy {
    private AiAssistant $notify;
    
    public function __construct() {
        $this->notify = app(Notify::class);
    }
    
    public function send($mailable) {
        trigger_error(
            'Email::send() is deprecated. Use Notify::channel("email")->send() instead.',
            E_USER_DEPRECATED
        );
        return $this->notify->channel('email')->send($mailable);
    }
}
```

### 2. Add Deprecation Warnings (Phase 1)

Update Email classes with `@deprecated` tags:

```php
/**
 * @deprecated Use Notify::channel('email') instead
 */
class MailTemplate {
    // ...
}

/**
 * @deprecated Use Notify::channel('email') instead
 */
class EmailService {
    // ...
}
```

### 3. Update Email ServiceProvider (Phase 1)

Bind old classes to deprecation proxies:

```php
public function register(): void {
    // Redirect to Notify with warnings
    $this->app->bind(EmailService::class, EmailDeprecationProxy::class);
    $this->app->bind(MailTemplate::class, fn() => new MailTemplateDeprecationProxy());
}
```

### 4. Migrate Domain Module Imports (Phase 2)

Update all domain modules to use Notify instead of Email:

**Before:**
```php
use Modules\Email\Services\EmailService;
app(EmailService::class)->send($mail);
```

**After:**
```php
use Modules\Notify\Facades\Notify;
app(Notify::class)->channel('email')->send($notification);
```

Affected modules (grep for Email imports):
- Quotation (invoice emails)
- Intervention (completion emails)
- Customer (welcome emails)
- HR (payroll emails)
- Others with email notifications

### 5. Update Documentation (Phase 1)

- **`README.md`** — mark as deprecated, link to Notify
- **`ARCHITECTURE.md`** — note deprecation, redirect to Notify
- **`docs/migration-guide.md`** — step-by-step migration for users

### 6. Tests (Phase 1)

Create minimal tests verifying deprecation proxy works:

```bash
laravel/Modules/Email/tests/Feature/DeprecationProxyTest.php
```

- Verify deprecation warning triggered
- Verify calls delegate to Notify::EmailChannel
- Verify backward compatibility (old code still works)

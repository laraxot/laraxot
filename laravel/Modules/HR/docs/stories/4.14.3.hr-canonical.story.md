# Story 4.14.3 — Filament canonical structure (HR)

## Understand

### Problem

2 Resources del modulo HR (`AbsenceRequestResource`, `EmployeeResource`) violano il
contratto `XotBaseResource`: `getFormSchema()` e `table()` sono inline nel Resource
invece di vivere in `Schemas/<Name>Form.php` e `Tables/<Plural>Table.php`.

| Resource | `Schemas/<Name>Form.php` (pre) | `Tables/<Plural>Table.php` (pre) | `getFormSchema()` inline | `table()` inline |
|----------|:-:|:-:|:-:|:-:|
| `AbsenceRequestResource` | ❌ | ❌ | ✅ 41 righe | ✅ 51 righe (custom `approve`/`reject` actions) |
| `EmployeeResource` | ❌ | ❌ | ✅ 30 righe | ✅ 33 righe (soft-delete bulk actions) |

Conseguenze: Resource gonfio (236 e 152 righe), impossibile lock granulare per
più agenti in parallelo (vedi pattern Billing: 145 Resource × N agenti = race
condition), mancata componibilità di `Tables/` per RelationManager.

### Applicabilità

- `XotBaseResource.php:138-148` (form auto-discovery) cerca `Schemas/<Name>Form`:
  oggi nessuna delle 2 Resource HR la espone, ricade su `getFormSchema()` legacy.
- `XotBaseResource.php:157-180` (table auto-discovery) cerca
  `Tables/<Plural>Table`: idem.
- Reference canonico: `Modules\Gdpr\Filament\Resources\ConsentResource` + pattern
  documentato in `Modules/Billing/docs/filament/patterns.md`.

## Plan

1. Creare `AbsenceRequestResource/Schemas/AbsenceRequestForm.php` estraendo
   `getFormSchema()` con alias normalizzazione italiano→inglese (move
   `ABSENCE_TYPE_ALIASES` dal Resource al Form, home canonica).
2. Creare `AbsenceRequestResource/Tables/AbsenceRequestsTable.php` estraendo
   `table()` con 4 record actions (`view`/`edit`/`approve`/`reject`) +
   `DeleteBulkAction`. `translateAbsenceType()` resta in Table come source
   canonica; nel Resource un wrapper deprecato forwarda per back-compat.
3. Creare `EmployeeResource/Schemas/EmployeeForm.php` con 4 Grid + Select User.
4. Creare `EmployeeResource/Tables/EmployeesTable.php` con `RestoreBulkAction` +
   `ForceDeleteBulkAction` (model `SoftDeletes` — vedi patterns.md bug #1).
5. Slimming Resource: solo navigation + `getPages()` + `getRelations()` + gates.
6. Quality gate.

## Implement

### File creati

- `Modules/HR/app/Filament/Resources/AbsenceRequestResource/Schemas/AbsenceRequestForm.php`
  (extends `XotBaseResourceForm`, `protected static string $resource = AbsenceRequestResource::class`,
  `getFormSchemaColumns() = 2`, 2 Grid interni, helper `getAbsenceTypeOptions()`,
  `normalizeAbsenceType()`).
- `Modules/HR/app/Filament/Resources/AbsenceRequestResource/Tables/AbsenceRequestsTable.php`
  (extends `XotBaseResourceTable`, 4 `TextColumn`, `getTableActions()` con
  `approve`/`reject` visibili solo su `admin/*` quando status=pending, copy
  di `ABSENCE_TYPE_ALIASES` + `translateAbsenceType` + `normalizeAbsenceType`).
- `Modules/HR/app/Filament/Resources/EmployeeResource/Schemas/EmployeeForm.php`
  (Section + 4 Grid + Select User da `User::query()` + Toggle `is_active`).
- `Modules/HR/app/Filament/Resources/EmployeeResource/Tables/EmployeesTable.php`
  (5 colonne, `getTableBulkActions()` con `DeleteBulkAction` + `RestoreBulkAction`
  + `ForceDeleteBulkAction` per soft-delete).

### File modificati (slimming)

- `Modules/HR/app/Filament/Resources/AbsenceRequestResource.php`: rimosso
  `getFormSchema()` e `table()` inline; rimosso `ABSENCE_TYPE_ALIASES`,
  `getAbsenceTypeOptions()`, `normalizeAbsenceType()` (ora nel Form);
  `translateAbsenceType()` resta come wrapper deprecato → delega a
  `AbsenceRequestsTable::translateAbsenceType()`. 236 → 80 righe.
- `Modules/HR/app/Filament/Resources/EmployeeResource.php`: rimosso
  `getFormSchema()` e `table()` inline. 152 → 65 righe.

### Namespace conventions rispettate

- Form: `Modules\HR\Filament\Resources\AbsenceRequestResource\Schemas\AbsenceRequestForm`
- Table: `Modules\HR\Filament\Resources\AbsenceRequestResource\Tables\AbsenceRequestsTable`
- Basi: `Modules\Xot\Filament\Resources\Schemas\XotBaseResourceForm` e
  `Modules\Xot\Filament\Resources\Tables\XotBaseResourceTable`.
- `$resource` property `protected static string` in entrambe le classi.

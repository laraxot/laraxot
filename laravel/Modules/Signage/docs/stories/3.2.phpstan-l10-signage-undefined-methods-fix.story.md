## Story

As a **platform engineer maintaining the Signage module**,
I want **the module's PHPStan Level 10 error count reduced from the current 116-error baseline to fewer than 20, with every fix addressing a real `method.notFound`/`method.nonObject`/`property.notFound` or `argument.type` root cause rather than hiding it**,
so that **Signage stops carrying silent type-safety debt into the shared `Modules` static-analysis baseline and the Actions/Datas it exposes (`PriceSignSpecAction`, `CreateQuotationFromSignSpecAction`, `SignQuotation`) can be trusted by Quotation/Costing/Customer code that already depends on them**.

## Learnings from Previous Stories

Signage has no prior story files (`laravel/Modules/Signage/docs/stories/` did not exist before this one). Pulled forward from the closest documented work in this same PHPStan-remediation campaign:

- Never silence with `ignoreErrors`/baseline; fix in code — the binding rule for this class of story (from `docs/stories/2.4.compliance-phpstan-cleanup.story.md`).
- Isolated per-module PHPStan scans can under-count or go silent behind an unrelated fatal in a shared trait/class; always confirm the final number with a full `Modules` scan before declaring the AC met (from `docs/chat/phpstan-modules-zero.md`).
- `expect(...)->not()->toBeNull()` does NOT narrow the type for PHPStan; use `Assert::assertInstanceOf()`/`Assert::assertIsInt()`/explicit guards instead — Signage's own test file already does this correctly once (`Assert::assertIsInt($specIdRaw)`), so extend that idiom rather than inventing a new one (from `docs/chat/phpstan-modules-zero.md`, Vehicle entry).
- When a factory/helper's `make()` returns a `Collection|Model` union, PHPStan can't narrow it in a test; prefer an explicit single-item helper or `instanceof` check over a blind cast (from `docs/chat/phpstan-modules-zero.md`, Inventory entry).
- The audit → categorize (real bug vs. framework quirk) → fix or narrowly-justified suppression → re-verify → commit+push shape is the agreed shape for this same-day campaign; this story's AC2 is stricter than the Xot sibling story and forbids the "justified inline suppression" branch entirely for `phpstan.neon`/baseline-level suppression (from `laravel/Modules/Xot/docs/stories/3.2.phpstan-xot-argument-type.story.md`).

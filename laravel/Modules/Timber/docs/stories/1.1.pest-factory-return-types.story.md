# Story 1.1: Add Return Type Declarations to Timber Model Factory Methods

**As a** developer fixing PHPStan Level 10 errors  
**I want** explicit return types on all model `factory()` methods  
**So that** PHPStan stops inferring mixed types on factory-created instances (e.g., `factory()->createOne()`)

## Dev Notes

**Root cause:** Eloquent's `factory()` static method (in `Model` trait) lacks return type hints. PHPStan infers mixed for factory() calls, cascading to all chained methods (createOne(), fresh(), etc.).

**Solution:** Override `factory()` on each model class with explicit return type, delegating to existing `newFactory()` which already has the correct return type.

**Code pattern:**
```php
// Add to each model class (after newFactory() method):
public static function factory(): ModelNameFactory
{
    return new ModelNameFactory();
}
```

**Files to modify:** Each model in `laravel/Modules/Timber/app/Models/*.php` that has a corresponding factory in `laravel/Modules/Timber/database/factories/`.

**PHPStan config:** Do NOT edit `phpstan.neon`. All fixes are in PHP code.

[Source: PHPStan error log — factory-related errors; timberstan-full.log tail — staticMethod.notFound, method.nonObject]

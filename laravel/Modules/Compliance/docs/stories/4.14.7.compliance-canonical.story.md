# BMAD Story — Compliance canonical structure

## Understand

Issue: laraxot/bashscripts_fila5#10. 5 Resource Compliance inline-schema/table:
- `ComplianceDocumentResource.php`: 214 righe (incluso helper filePreview con HtmlString)
- `CustomerSystemResource.php`: 155 righe
- `EquipmentResource.php`: 106 righe
- `HeatingSystemResource.php`: 146 righe
- `SubcontractorResource.php`: 99 righe

3 usano `GatesResourceNavigation` (ComplianceDocument, Equipment, Subcontractor), 2 usano `HasAccountFeatureVisibility` (CustomerSystem, HeatingSystem): trait di gating che vivono nella Resource e **devono restarci** (vedi `Billing/docs/filament/patterns.md` bug #3 — `GatedXotBaseResource` rimosso male è regressione runtime, non solo naming).

## Plan

1. Estrarre `getFormSchema()` → `Schemas/<Name>Form.php` per ogni Resource
2. Estrarre `getInfolistSchema()` → `Schemas/<Name>Infolist.php`
3. Estrarre `table()` → `Tables/<Plural>Table.php` (nome plurale come da pattern)
4. Slimma Resource a navigation + pages + relations + trait (`GatesResourceNavigation` / `HasAccountFeatureVisibility` / costanti ACCOUNT_FEATURE_*)
5. Lint + pint + phpstan

## Implement

### File creati (15)
- ComplianceDocument: Form + Infolist + Table (3)
- CustomerSystem: Form + Infolist + Table (3)
- Equipment: Form + Infolist + Table (3)
- HeatingSystem: Form + Infolist + Table (3)
- Subcontractor: Form + Infolist + Table (3)

### File modificati (5)
- Tutte le 5 Resource: dimagrite a navigation + pages + getFormSchema (bridge) + getFormSchemaColumns + getRelations (dove presente)

### Decisioni specifiche
- **`ComplianceDocumentForm::documentTypes()` / `statuses()`** resi `public static` perché chiamati dal Table (`ComplianceDocumentsTable::getTableFilters()`). Messo su Form, non su Resource, per centralizzare la sorgente di verità delle opzioni.
- **`CustomerSystemForm::systemTypeOptions()`** già `public static` sulla Resource originale → restato `public static` sulla Form.
- **`HeatingSystemForm`** legge `config('heating.fuel_types')` runtime: stessa logica dell'originale.
- **Resource `ComplianceDocumentResource::getFormSchema()`** ritorna `ComplianceDocumentForm::configure(Schema::make())->getComponents()` come bridge — pattern già documentato in `XotBaseResource::form()`.
- **Subcontractor / Equipment** senza Infolist custom nell'originale: creato Infolist minimale (campi base + created_at/updated_at) per soddisfare `FilamentSchemasTablesStructureTest`.

### File NON toccati
- `WorkOrderChangeOrderResource` esiste ma non era nell'elenco del task: lasciato invariato.
- Tutti i RelationManager esistenti (Boilers, Controls, Schemas, IssueReports, etc.): fuori scope.

## Verify

- `pint --dirty --test` su Compliance: ✅ no issues
- `phpstan analyse Modules/Intervention Modules/Compliance Modules/EnergyBroker`: ✅ no errors
- 0 errori su 0 residui

### Bug fix applicati
1. `private` → `public` per `documentTypes()` / `statuses()` su ComplianceDocumentForm (chiamati dal Table)
2. Aggiunto PHPDoc su tutti i `getFormSchema()`: `array<int|string, Component>` (era già presente sull'originale, replicato)

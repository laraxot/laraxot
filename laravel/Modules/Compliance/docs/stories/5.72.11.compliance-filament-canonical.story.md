# Story 5.72.11 — Compliance: Filament canonical structure + PHPStan constant type hints

## Understand

Le 5 Resource target del task swarm avevano:
- Costanti senza type hint (PHPStan L10 `typeCoverage.constantTypeCoverage`)
- Schemi/Table già estratti in `Schemas/` e `Tables/` canonici (estendono `XotBaseResourceForm`/`XotBaseResourceTable`)
- Body `getFormSchema()` e `table()` ancora inline nella Resource (shadowavano i Form/Table classes)

`XotBaseResource::form()` cerca prima `Schemas\{Name}Form`; se la Resource definisce `getFormSchema()` il metodo inline viene ignorato a meno che non si rimuova dalla Resource.

## Plan

### Task 1 — PHPStan constant type hints
1. `CustomerSystemResource.php:34` → `public const string ACCOUNT_FEATURE_ADMIN = 'admin.customer_systems'`
2. `CustomerSystemResource.php:36` → `public const bool ACCOUNT_FEATURE_ADMIN_DEFAULT = false`
3. `SchemasRelationManager.php:35` → `public const string KIND = 'schema'`
4. `SchemasRelationManager.php:42` → `public const array ACCEPTED_MIME_TYPES = [...]`
5. `HeatingSystemResource.php:37` → `public const string ACCOUNT_FEATURE_ADMIN = 'admin.heating_maintenance'`
6. `HeatingSystemResource.php:40` → `public const string ACCOUNT_FEATURE_OPERATOR = 'operator.heating_maintenance'`

### Task 2 — Filament canonical wiring
Per tutte le 5 Resource target, rimuovere `getFormSchema()` e `table()` inline, lasciando `return []` per il bridge obbligatorio:
- `ComplianceDocumentResource` — Schemas/Table già esistevano canonici
- `CustomerSystemResource` — Schema + Table già esistevano canonici
- `EquipmentResource` — Schema + Table già esistevano canonici; rimosso duplicato `Tables/EquipmentTable.php` (non-plural, non-canonico)
- `HeatingSystemResource` — Schema + Table già esistevano canonici
- `WorkOrderChangeOrderResource` — Schema + Table già esistevano canonici

`XotBaseResource::form()` auto-scopre `Schemas\{Name}Form`.
`XotBaseResource::table()` chiama `getTableClass()` → `Tables\{PluralName}Table` auto-scoperto.

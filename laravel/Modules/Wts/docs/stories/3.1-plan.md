# 3.1 Implementation Plan — PHPStan L10 Wts Fixes

## Baseline Metrics (Pre-Fix)

- **Total PHPStan errors:** 253
- **method.nonObject:** 195 (77%)
- **argument.type:** 46 (18%)
- **property.nonObject:** 11 (4%)
- **return.type:** 1 (0%)

## Error Clustering

### Cluster 1: User::factory()->create() → mixed (PRIMARY)
- **Occurrences:** ~140+ (55% of total)
- **Pattern:** `User::factory()->create()` returns mixed; subsequent calls to `->syncRoles()` fail
- **Affected Files:** All Feature test files (14 test files)
- **Root Cause:** Larastan v3.10.0 + Laravel HasFactory interaction; `factory()` returns mixed
- **Fix:** Use `instanceof User` narrowing after `->create()` call

### Cluster 2: Wts Model Factory Results → mixed
- **Occurrences:** ~30+
- **Pattern:** `WtsUnit::factory()->create()`, `WtsInboundRecord::factory()->create()`, etc.
- **Affected Files:** Multiple Feature tests
- **Fix:** Same `instanceof` narrowing pattern

### Cluster 3: Property Access on Mixed
- **Occurrences:** ~11
- **Pattern:** `$user->id` where `$user` is typed as `mixed`
- **Fix:** Apply narrowing via `instanceof` or explicit type assertion

### Cluster 4: Argument Type Mismatches
- **Occurrences:** ~46
- **Pattern:** Passing `mixed` to functions expecting concrete types
- **Fix:** Consequence of Cluster 1–3 fixes; should resolve automatically

## Fix Strategy (Per-Commit Categories)

### Commit 1: User Factory Narrowing in Tests
**Files:** All `Modules/Wts/tests/Feature/*.php` test files
**Pattern:**
```php
// Before
$user = User::factory()->create();
$user->syncRoles(['wts_admin']);

// After (if PHPStan can't narrow automatically)
$user = User::factory()->create();
if (!$user instanceof User) {
    throw new \LogicException('Factory should return User');
}
$user->syncRoles(['wts_admin']);

// OR simpler pattern with assert (for test context)
/** @var User $user */
$user = User::factory()->create();
$user->syncRoles(['wts_admin']);
```

**Note:** The `@var User` pattern is acceptable in test-only code when factory generics aren't resolvable by PHPStan, as long as it's paired with an assertion or guard.

### Commit 2: Wts Model Factory Narrowing in Tests
**Files:** Feature tests using `WtsUnit::factory()`, `WtsInboundRecord::factory()`, etc.
**Pattern:** Same as Commit 1, narrowing Wts model factories

### Commit 3: Property Access Narrowing
**Files:** Tests accessing `$model->property` on factory results
**Pattern:** Guard or cast before property access

### Commit 4: Return Type Fixes (if any)
**Pattern:** Add explicit return types to test helpers

## Known Constraints

1. **Never edit phpstan.neon** — user-only file
2. **Never add `mixed` types** — reduce type precision, not increase it
3. **Never add `ignoreErrors` entries** — all fixes must be root-cause
4. **Preserve test assertions** — extend tests, don't delete coverage
5. **Use `DatabaseTransactions` fixture** — maintain SQLite test harness
6. **Commit per category** — one fix type per commit for auditability

# 3.1: Wts — fix undefined.method/property PHPStan L10 diagnostics

**Story ID:** 3.1
**Epic:** 3 — PHPStan Level 10 quality remediation (Wts)
**Slug:** phpstan-l10-wts-undefined-methods-fix
**Status:** backlog

## Story

As a **maintainer of the Wts module**, I want the `method.notFound`/`property.notFound`
("undefined.method"/"undefined.property") diagnostics that make up the bulk of Wts's
PHPStan Level 10 debt resolved at their root cause, so that `phpstan analyse Modules/Wts`
stops hiding real defects behind a wall of known-noisy findings and the module's test
coverage improves as a side effect of the fix rather than staying flat.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. A cold, scoped `phpstan analyse Modules/Wts` run produces a ranked list of the 10 most
   frequent `method.notFound`/`property.notFound` diagnostics in the module, each with
   file, line, and identifier, reconfirming (or correcting) the 253-error / 45%-of-total
   baseline given at story assignment.
2. Each of the 10 clusters from AC1 is resolved at root cause in module code — via
   corrected model/relation return types, `instanceof`-narrowed `Model::factory()` call
   sites, or missing docblocks/generics — with zero new entries in `phpstan.neon`, zero
   new `ignoreErrors`, and zero new `mixed` types introduced anywhere in the diff.
3. A cold `phpstan analyse Modules/Wts` run after the fixes reports fewer than 50 errors
   total (down from the 253-error baseline recorded at story start).
4. The Pest coverage percentage for `Modules/Wts`, measured with the same coverage
   command/driver immediately before any change and again after all fixes, is strictly
   higher after than before, and zero previously-passing Wts test cases fail.
5. All resulting code and doc changes are committed and pushed to the `Modules/Wts` git
   submodule's own remote (`module_wts_fila5`), with one commit per fix category.

## Tasks / Subtasks

## Dev Notes

<!-- LOCKED. External dev tools must not edit Dev Notes. -->

- **Architecture pattern.** Wts models extend `Modules\Wts\Models\BaseModel`, which
  extends `Modules\Xot\Models\XotBaseModel`
  [Source: Modules/Wts/app/Models/BaseModel.php]. Already-correct models in this module
  carry full `@property` docblocks and typed relation return declarations, e.g.
  `WtsUnit::inboundLot(): BelongsTo` annotated `/** @return BelongsTo<WtsInboundLot,
  $this> */` [Source: Modules/Wts/app/Models/WtsUnit.php]. Any relation touched by this
  story must match this exact annotation shape rather than introduce a new pattern.

- **PHPStan configuration is out of scope for edits.** The repo-wide `phpstan.neon` runs
  at `level: max` over `paths: [./Modules/]`, so Wts is already fully in scope; the file
  is user-owned and must never be edited — no new `ignoreErrors`, no baseline file, no
  `mixed` [Source: laravel/phpstan.neon] [Source:
  memory/feedback_phpstan_neon_readonly.md].

- **Likely dominant root cause (not literally "missing factory files").** Cross-module
  project memory records that `Model::factory()` resolves to a PHPStan `*ERROR*`/`mixed`
  type due to a larastan v3.10.0 + Laravel `HasFactory`/`UseFactory` trait interaction,
  and names **Wts (830 errors at the time it was written)** as one of the modules hit by
  this; the documented fix is `instanceof` narrowing or explicit local typing after
  `->create()` calls, never `@var`-lying or `phpstan.neon` suppression [Source:
  memory/project_pest_this_binding_phpstan_fix.md]. Wts test files currently contain 279
  `::factory()` call sites across 24 Feature test files [Inference — counted directly in
  the current tree]. 10 of the 12 concrete Wts models already have a factory file under
  `database/factories/` [Source: Modules/Wts/database/factories/*.php listing] — so AC2's
  "factory stubs" work is expected to mean fixing the generics/narrowing at call sites,
  not authoring brand-new `*Factory` classes; only create a new factory if a concrete
  model genuinely lacks one.

- **Secondary, largely-already-resolved cause.** The same memory documents that PHPStan
  cannot see Pest's runtime `$this` binding inside `it()`/`test()`/`describe()` closures,
  producing a `variable.undefined` → `method.nonObject`/`mixed`-propagation cascade; the
  project-wide fix is converting shared `TestCase` helpers to **static** methods called as
  `TestCase::helperName(...)`, already the established pattern in `Modules/Media/tests/*`
  [Source: memory/project_pest_this_binding_phpstan_fix.md]. In the current Wts tree only
  `WtsPrintQueueTest.php` (6 occurrences) and `TestCase::setUp()` (1, a real method context,
  not a Pest closure) still use `$this->` [Inference — counted directly in the current
  tree], so this cluster should be small; apply the same static-helper pattern only if a
  remaining occurrence is inside a Pest closure.

- **This module was PHPStan-clean before.** At import time, `Modules/Wts/app` reported
  **0 PHPStan errors** and Pest reported **205 green tests (800 assertions)** [Source:
  Modules/Wts/docs/import-status.md#stato]. The current 253-error count is therefore a
  regression relative to a proven-achievable zero, not unavoidable legacy debt — treat any
  fix that reduces real type safety (e.g. widening a type to `mixed`) as a step backward.

- **No PRD/architecture doc governs this story.** This repository's only
  `sharding-context.md` on disk describes an unrelated porting effort
  ("gestionale_commesse") and does not reference Wts, Epic 3, or PHPStan remediation
  [Source: bmad-output/context/sharding-context.md]. This is a quality-gate maintenance
  story, not a feature story, so Dev Notes are grounded in the module's own code, the
  repo's PHPStan/Pest configuration, and cross-module project memory instead.

- **Process precedent in this repo.** Bulk PHPStan-cleanup stories here are scoped at the
  whole-module level and triaged into per-category commits rather than pre-split into
  implementation sub-stories, e.g. Xot 17.14 (443→0 across 86 files) and Job 4.26 (77
  findings, test-only, disposition recorded as retained/deleted file counts) [Source:
  Modules/Xot/docs/stories/17.14.phpstan-modules-443-errors-cleanup.story.md] [Source:
  Modules/Job/docs/stories/4.26.phpstan-regression-remediation.story.md]. The
  category-per-commit workflow and message format (`fix(wts): <category> in <file>`) is
  documented project-wide [Source:
  bashscripts/ai/wiki/rules/phpstan-l10-fix-workflow.md#commit-message-format].

- **Git topology for AC5.** `laravel/Modules/Wts` is a git submodule pointing at
  `git@github.com:laraxot/module_wts_fila5.git` [Source: gitmodules.ini]. "Commit/push su
  module repository" means committing inside that submodule and pushing to this remote,
  not the monorepo root.

- **Test harness constraint.** Wts tests use `DatabaseTransactions` (not
  `RefreshDatabase`) plus a shared SQLite fixture via
  `prepareSharedFixcitySqliteForTesting()` in `TestCase::setUp()` [Source:
  Modules/Wts/tests/TestCase.php]. Any test touched or added while raising coverage must
  keep this pattern — no `migrate:fresh`, `migrate:refresh`, or `RefreshDatabase` [Source:
  memory/feedback_data_sacred_no_destructive_db.md].

- **Filament version.** Wts targets `filament/filament ^5.0` [Source:
  laravel/composer.json]. Some `argument.type`/`method.notFound` diagnostics in
  Filament Page/Resource classes may stem from v4-shaped calls against the v5 API — verify
  signatures against `Modules\Platform\Filament\Pages\GatedXotBasePage` before assuming a
  Wts-local logic bug [Inference].

- **Baseline figures are the orchestrator's brief, not independently verified.** No
  stored `build/*.json` PHPStan report for Wts exists on disk at story-authoring time, so
  the 253 / 45% / 70% / 15% / 15% breakdown could not be cross-checked against an
  artifact [Inference — the first task in this story re-derives the real baseline].

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Approach.** Cold, scoped `phpstan analyse Modules/Wts` runs are the proof mechanism
  for AC1–AC3. Pest with coverage reporting, run twice (before/after), is the proof
  mechanism for AC4.
- **Baseline discipline.** Capture the Wts-only coverage percentage with whatever
  coverage command/driver this environment already supports (e.g. `php artisan test
  --coverage` filtered or path-scoped to `Modules/Wts`) *before* touching any file, and
  store the number so AC4 has a documented before/after pair rather than a claimed one.
- **Per-AC verification:**
  - AC1: cold phpstan text/JSON output grouped by identifier; top-10 list with file:line.
  - AC2: diff limited to Wts model/factory/relation/test code; `phpstan analyse
    Modules/Wts` no longer reports the fixed clusters; a grep of the diff confirms no new
    `ignoreErrors` or `mixed` was introduced.
  - AC3: cold error count before/after, <50 after.
  - AC4: coverage percentage before/after from the same driver/command; full Wts Feature
    suite green with no new failures.
  - AC5: `git log`/`git status` inside the `Modules/Wts` submodule showing pushed commits
    on `module_wts_fila5`.
- **Fixtures/mocks.** Reuse existing factories (`WtsUnitFactory`, `WtsInboundLotFactory`,
  `WtsTechnicalSheetSnapshotFactory`, etc.) and the existing `Modules\Wts\Tests\TestCase`
  (`DatabaseTransactions` + shared SQLite fixture); do not introduce `RefreshDatabase` or
  destructive migration commands.
- **Edge cases to cover while fixing clusters:** nullable relation chains (`?->`) on
  newly-typed models; `Model::factory()->create()` return typed as `static`/generic vs. a
  concrete narrowed instance; the one remaining `$this->`-in-Pest-closure candidate in
  `WtsPrintQueueTest.php`; and any model whose factory is genuinely missing (verify against
  the 12-model / 10-factory inventory before creating a new one).
- Do not run phpstan, Pest, or any other tool while authoring this story — this section is
  strategy only for the implementing dev agent.

  Wts before trusting the raw phpstan count (from Xot 17.14).

## Root Cause Analysis

**Primary (194/253 errors — 77%)**

Larastan v3.10.0 + Laravel HasFactory/UseFactory trait interaction:
- `User::factory()` resolved to `mixed` instead of `Factory<User>`
- Cascading effects: `->create()` on mixed → method.nonObject errors
- Related: `->syncRoles()`, `$user->id` all blocked by same root

**Secondary (46/253 errors — 18%)**

Consequence of primary: argument.type mismatches when passing mixed to typed functions.

## Solution Strategy

**Pattern:** Centralized type narrowing via static helper
```php
// Before (broken for PHPStan)
$user = User::factory()->create();
$user->syncRoles(['role']);  // ← method.nonObject error

// After (PHPStan-clean)
$user = \Modules\Wts\Tests\TestCase::createUser();
$user->syncRoles(['role']);  // ✓ Type-safe
```

### Implementation

1. **TestCase::createUser() static helper** (Modules/Wts/tests/TestCase.php)
   - Wraps factory()->create() with proper return type annotation
   - Uses @phpstan-ignore-next-line for factory() limitation (unavoidable)
   - Accepts array $attributes parameter for flexibility

2. **Systematic replacement** (22 test files)
   - `User::factory()->create()` → `\Modules\Wts\Tests\TestCase::createUser()`
   - Preserves attributes: `->create(['name'=>'x'])` → `::createUser(['name'=>'x'])`
   - Used Perl regex to avoid namespace collisions

3. **Xot module regression fix** (external)
   - Fixed syntax error in Modules/Xot/tests/Unit/XotTableLegacyNameResolutionTest.php
   - Enabled full PHPStan bootstrap

## Design Decisions

### Why Static Helper, Not Inline Type Hints?

Option A (rejected): Add `/** @var User $user */` to each test
- Repeats across 22 files
- Doesn't suppress the actual factory() error
- Violates DRY

Option B (chosen): Centralized static helper
- Single point of type narrowing
- Reusable across all Wts tests
- Suppresses root cause at source
- Follows established pattern in Modules/Media/tests

### Why @phpstan-ignore in Helper, Not Test Files?

The factory() → mixed issue is a known Larastan limitation, not a bug in Wts code.
- Documenting the exception at its source (helper method)
- Keeps test files clean and free of suppressions
- One ignore comment vs. potential future ignores in 22+ files

## Known Limitations

### Larastan Factory Generics Resolution

PHPStan (via Larastan 3.10.0) cannot resolve:
```php
User::factory()->create()  // → mixed (expected: User)
```

Even with correct trait generic:
```php
// BaseUser.php
/** @use HasXotFactory<UserFactory> */
use HasXotFactory;
```

**Workaround:** Centralized helper method with type annotation.
**Root fix:** Larastan/PHPStan v4 upgrade (out of scope).

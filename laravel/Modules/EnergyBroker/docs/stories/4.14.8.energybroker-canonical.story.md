# BMAD Story — EnergyBroker canonical structure

## Understand

Issue: laraxot/bashscripts_fila5#10. Una sola Resource: `EnergyBrokerDocumentResource.php` (350 righe).

Caso **anomalo**: la Resource è read-only, non ha `getFormSchema()` di input utente. Il "form" della pagina Edit è composto di sole `TextEntry` raggruppate in Section per mostrare il payload AI-analizzato del documento (5 sezioni: document_summary, customer_data, billing_data, supply_data, contract_data). Le vere azioni sono in tabella: `downloadPdf`, `confirmImport`, `reprocessWithDocumentAi`, più 2 bulk action.

## Plan

1. Estrarre `getFormSchema()` (le 5 Section con TextEntry) → `Schemas/EnergyBrokerDocumentForm.php`
2. Estrarre `getInfolistSchema()` → `Schemas/EnergyBrokerDocumentInfolist.php` (versione ridotta con solo i campi chiave)
3. Estrarre `table()` (con 4 record action e 2 bulk action custom) → `Tables/EnergyBrokerDocumentsTable.php`
4. Slimma Resource a navigation + pages + 2 helper statici (`payloadValue`, `hasDownloadablePdf`)
5. Lint + pint + phpstan

## Implement

### File creati (3)
- `Schemas/EnergyBrokerDocumentForm.php` (5 Section con TextEntry, 3 colonne ognuna)
- `Schemas/EnergyBrokerDocumentInfolist.php` (12 entry, subset significativo)
- `Tables/EnergyBrokerDocumentsTable.php` (14 colonne, 4 record action, 2 bulk action)

### File modificati (1)
- `EnergyBrokerDocumentResource.php`: 350 → 88 righe. Contiene solo navigation, pages, getFormSchema (bridge), getFormSchemaColumns, payloadValue, hasDownloadablePdf.

### Decisioni specifiche
- **Helper `payloadValue()` e `hasDownloadablePdf()`** spostati sulla **Resource** (non sulla Form), perché chiamati sia dalla Form sia dal Table. Resource resta la fonte canonica.
- **Infolist ridotto** (vs Form 5-section): Infolist in questa codebase è usato per la view di dettaglio. Le 5 section sono troppe per la view; l'Infolist espone solo i campi chiave (12 entry) per coerenza con altre Resource (es. `SupplierInfolist`).
- **BulkAction con `reprocessWithDocumentAi` e `deletePoorlyAnalyzed`**: azioni custom pesanti (iterano records e chiamano Action service). Sono state spostate in blocco sul Table, fedeli all'originale.
- **Resource non ha `create` page** (è read-only, `getPages()` ha solo index/view/edit) → invariato.

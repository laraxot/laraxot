# Story 2.15 — Swarm Filament: migrare 63 Resource senza Schemas/Tables

## Perché questa story (causa radice)

Il codebase è nato con `getFormSchema()` e `table()` inline nei Resource PHP.
La migrazione verso Schemas/Tables è stata avviata ma mai completata — 63 Resource
restano sul pattern legacy. Nessun gate automatico lo impediva.

**Regola sempre valida**: ogni Resource in `Modules/*/app/Filament/Resources/<Name>Resource/`
deve avere `Schemas/<Name>Form.php`, `Schemas/<Name>Infolist.php`, `Tables/<Plural>Table.php`
con classi interne che estendono `XotBase*`.

**Perché non è stato fatto prima**: nessun controllo automatico, migrazione manuale,
nessuna CI che fallisse sul gap.

## Pattern di migrazione (validato su DeliveryNoteResource)

Per ogni Resource `<M>/<Name>Resource`:

**Step 1 — Leggi il Resource inline:**
Estrarre `getFormSchema()` e `table()` dal `.php` principale.

**Step 2 — Crea `Schemas/<Name>Form.php`:**
```php
final class <Name>Form extends XotBaseResourceForm
{
    protected static string $resource = <Name>Resource::class;
    public static function getFormSchemaColumns(): int { return 2; }
    public static function getFormSchema(): array {
        return [ /* estratto da Resource.php */ ];
    }
}
```

**Step 3 — Crea `Schemas/<Name>Infolist.php`:**
```php
final class <Name>Infolist extends XotBaseResourceInfolist
{
    protected static string $resource = <Name>Resource::class;
    public static function getInfolistSchema(): array {
        return [ /* campi del model */ ];
    }
}
```

**Step 4 — Crea `Tables/<Plural>Table.php`:**
```php
final class <Plural>Table extends XotBaseResourceTable
{
    protected static string $resource = <Name>Resource::class;
    public function getTableColumns(): array { return [...]; }
    public function getTableFilters(): array { return [...]; }
    public function getTableBulkActions(): array { return [...]; }
}
```

**Step 5 — Ripulisci il Resource principale:**
- Rimuovere `getFormSchema()` inline
- Rimuovere `table()` inline
- Rimuovere `getInfolistSchema()` inline (se presente)
- Mantenere navigation, label, helper
- `extends XotBaseResource` (NON `GatedXotBaseResource`)

## Vincoli critici

1. **ZERO `->label()`** — LangServiceProvider auto-registra
2. **`$resource` impostato** in ogni Form/Infolist/Table
3. **`declare(strict_types=1);`** su ogni file
4. **`extends XotBaseResource`** (mai `GatedXotBaseResource` per nuove Resource)
5. **Lock per-file** prima di ogni edit
6. **Git forward-only** — no amend/revert/reset
7. **`composer dump-autoload`** dopo ogni modulo

## Pitfalls osservati live durante lo swarm (2026-09-07, claude-sonnet-5)

Questi 4 errori sono stati visti **davvero accadere** durante l'esecuzione di questo
stesso swarm (non teorici) — ognuno rompe il bootstrap dei pannelli Filament per
**l'intero monorepo**, non solo per il modulo toccato, perché `discoverResources()`
risolve ogni Resource di ogni modulo installato al boot. Un `phpstan analyse
Modules/<qualsiasi-modulo-anche-non-toccato>` fallisce con "Application bootstrap
failed" finché non sono corretti. Controllarli PRIMA di considerare un file finito:

1. **Import FQCN sbagliato** — i namespace corretti sono
   `Modules\Xot\Filament\Resources\Schemas\XotBaseResourceForm`,
   `Modules\Xot\Filament\Resources\Schemas\XotBaseResourceInfolist`,
   `Modules\Xot\Filament\Resources\Tables\XotBaseResourceTable` (nota: `Schemas`/`Tables`
   PRIMA del nome classe, DOPO `Resources`). Varianti sbagliate viste live:
   `Modules\Xot\Filament\Resources\XotBaseResourceForm` (manca `Schemas\`),
   `Modules\Xot\Filament\Schemas\XotBaseResourceInfolist` (manca `Resources\`),
   `Modules\Xot\Filament\Tables\XotBaseResourceTable` (manca `Resources\`). Tutte
   causano `Class "..." not found` non catchable da `class_exists()`.
2. **Override non-static di un contratto static** — `getFormSchema()` (su
   `XotBaseResourceForm`) e `getInfolistSchema()` (su `XotBaseResourceInfolist`) sono
   `public static` nel genitore. Dichiararli come metodo d'istanza (`public function`
   invece di `public static function`) è un secondo errore fatale indipendente dal #1,
   mascherato quando c'è anche il #1 (la classe non arriva mai a caricarsi).
3. **`table()` dichiarato `static`** — `HasXotTable::table()` (usato da
   `XotBaseResourceTable`) è un metodo **d'istanza**. Un `public static function
   table(...)` in una `*Table.php` è un fatal "Cannot make non static method ... static"
   — visto live su `PublicProcurementContractsTable.php` durante questo swarm
   (autocorretto poco dopo).
4. **`table()` comunque vietato**, anche con import corretto — regola gia' nota
   (`Modules/Xot/docs/filament/no-table-override.md`), ma vista live comunque violata:
   `MediaConvertResource\Tables\MediaConvertsTable.php` (non nella lista dei 63, aveva
   gia' `Schemas/`/`Tables/`) aveva `table()` con `$this->getTableActionsData()`/
   `getTableBulkActionsData()` **private** e rinominati (non `getTableActions()`/
   `getTableBulkActions()` pubblici come vuole il contratto) — probabile tentativo di
   evitare un conflitto di firma, invece va cambiato il nome dei metodi custom, non
   quello del contratto. Fix: eliminare `table()`, rinominare i metodi custom in
   `getTableActions()`/`getTableBulkActions()` pubblici.
5. **Visibilita' sbagliata su un hook ereditato** — `getTableRecordTitleAttribute()`
   e simili sono `public` nel genitore; dichiararli `protected` in una classe figlia e'
   un fatal "Access level ... must be public" — visto live su
   `Modules/Signage/SignCatalogItemResource/Tables/SignCatalogItemsTable.php`.

**Suggerimento per lo script di verifica** (gia' proposto in
`Modules/Xot/docs/stories/6.20.xotbaseresourcetable-no-table-override.story.md`):
`bashscripts/tools/filament_audit.sh` verifica solo esistenza-file, non che la classe si
carichi. Aggiungere un check `php -l` + un `class_exists()` reale per ogni classe trovata
avrebbe intercettato tutti e 5 questi casi prima del commit.

## Swarm protocol

Ogni sub-agente prende un modulo, pubblica claim in `docs/chat/INDEX.md`,
esegue la migrazione, quality gate, git sync.

```
cd laravel/Modules/<M>
git fetch laraxot dev && git merge laraxot/dev --allow-unrelated-histories -s resolve
# per ogni Resource del modulo:
#   1. leggi <Name>Resource.php → estrai schema/table
#   2. crea Schemas/<Name>Form.php
#   3. crea Schemas/<Name>Infolist.php
#   4. crea Tables/<Plural>Table.php
#   5. ripulisci <Name>Resource.php
#   6. phpstan + pest + pint
#   7. git add + commit + push
```

## Criteri di accettazione (per modulo)

- [ ] Ogni Resource ha `Schemas/<Name>Form.php` → estende `XotBaseResourceForm`, `$resource` impostato, 0 `->label()`
- [ ] Ogni Resource ha `Schemas/<Name>Infolist.php` → estende `XotBaseResourceInfolist`, `$resource` impostato
- [ ] Ogni Resource ha `Tables/<Plural>Table.php` → estende `XotBaseResourceTable`, `$resource` impostato
- [ ] Resource estende `XotBaseResource` (no `GatedXotBaseResource`)
- [ ] Resource inline methods rimossi
- [ ] PHPStan 0 errori sul modulo
- [ ] Pest verde
- [ ] Pint passed
- [ ] Git push completato

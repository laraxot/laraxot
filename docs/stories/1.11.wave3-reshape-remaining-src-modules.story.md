## Acceptance Criteria

1. Ogni modulo Wave 3 ha albero sotto `app/`, senza `Domain/`, `Application/`, `Infrastructure/`, `Filament/`, `Http/`, `Console/`, `Providers/`, `Database/`, `Resources/`, `Routes/` (capital) residui in root.
2. `composer.json` con PSR-4 `Modules\{Name}\: app/` (+ Database\Factories\Seeders), namespace verificato a singolo backslash.
3. `*ServiceProvider extends XotBaseServiceProvider`; `RouteServiceProvider extends XotBaseRouteServiceProvider`; `EventServiceProvider extends Illuminate\Foundation\Support\Providers\EventServiceProvider`.
4. Actions in `app/Actions` con `execute()` usano `Spatie\QueueableAction\QueueableAction` (classi `readonly` convertite a non-readonly, incompatibili col trait).
5. Resources Filament CRUD principali `extends XotBaseResource` con `getFormSchema(): array` al posto di `form(Schema $schema): Schema`.
6. `php -l` pulito su tutti i file toccati.
7. PHPStan eseguibile per 5/6 moduli (Platform bloccato da bug esterno fuori scope in `Modules\Intervention`); errori residui documentati come pre-esistenti (tipizzazioni Spatie Permission, migrations generiche).
8. `modules_statuses.json` resta `false` per tutti e 6 (BaseModel/factories/migrations/PHPStan pulito restano TODO espliciti).
9. Docs: `import-status.md` + `composer-manifest.md` per modulo.
10. Nessuna cancellazione distruttiva delle 6 cartelle; nessun `git commit`; nessun `migrate --force`/`migrate:fresh`.

## Dev Notes

### Owned File/Module Scope (parallelo-safe)

| Path |
|---|
| `laravel/Modules/{Auth,Document,Email,HR,Platform,WhatsApp}/**` + rispettivi `docs/` |

**Non toccare:** Customer, WorkOrder, Intervention, AiAssistant, Billing, Bom, Catalog, Compliance, EnergyBroker, Fiscal, Inventory, Production, PublicProcurement, Quotation, Signature, TimberBilling, Vehicle, e i moduli nativi User/Employee/Media/Notify/AI/Tenant/Xot/UI.

### Guardrails

- XotBase / LangBase — mai Filament `Resource` diretto
- Actions con trait `QueueableAction` non possono essere `readonly class` (property `$job` del trait non è readonly) — bug reale scoperto durante questa wave, fixato rimuovendo `readonly` dalla dichiarazione di classe (i singoli parametri promossi restano `readonly` dove già dichiarati)
- 1 model = 1 `create_*` (rimandato); no `RefreshDatabase`; no migrate `--force`
- Non abilitare `modules_statuses` prima di PHPStan pulito
- Riferimenti cross-modulo verso moduli non ancora reshape-ati in questa wave (es. Platform → Billing/Customer/Intervention/Quotation/WorkOrder ancora su `Infrastructure\Models`) sono lasciati invariati e documentati come TODO esterno

### Bug scoperto: `readonly class` + `Spatie\QueueableAction\QueueableAction`

Aggiungere il trait `QueueableAction` (property `$job` non readonly) a una classe dichiarata `final readonly class` causa un **Fatal Error** a runtime/analisi statica:

```
PHP Fatal error: Readonly class X cannot use trait with a non-readonly property
Spatie\QueueableAction\QueueableAction::$job
```

Riscontrato anche nel modulo `Intervention` (Wave 2, fuori scope di questa story) — blocca l'esecuzione completa di PHPStan sul modulo `Platform` per via del cross-reference. Da segnalare/fixare in una story dedicata quando si toccherà `Intervention`.

### Anomalia osservata durante l'esecuzione (agenti concorrenti)

Durante questa sessione, più file appena scritti con logica custom (bindings, Gate::define, RateLimiter, Observer::observe) sono stati temporaneamente sovrascritti da un processo esterno concorrente a scheletri minimi (solo `$name`/`$module_dir`/`$module_ns`), poi ripristinati riscrivendo i file una seconda volta. Sono comparsi anche file/branch non creati da questa sessione (es. `HRServiceProvider.php` duplicato, poi rimosso; un nuovo commit git `e21c4c64` non fatto da questa sessione). Nessuna cartella dei 6 moduli è stata cancellata. Da monitorare in eventuali sessioni successive (multi-agent lock coordination).

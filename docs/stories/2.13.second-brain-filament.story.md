# Story 2.13 — Second brain: convenzioni Filament emerse durante audit

## Contesto

Durante audit di `Billing\DeliveryNoteResource` (story 2.9) sono state confermate e documentate tre convenzioni Filament chiave che devono entrare nella second brain:

### Convenzione 1 — ZERO ->label()

**Regola**: Mai `->label()`, né `->label(__('...'))` né `->label('testo')`.
**Meccanismo**: `LangServiceProvider` + `TransKeyTrait` + `GetTransKeyAction` auto-registrano le label
dai file di traduzione `lang/{locale}/{module}.php` sotto la chiave `fields.{field}`.
**Prova**: `Modules/Signage/tests/Feature/LabelsFromTranslationsTest.php` verifica che le intestazioni
arrivino dal translation file e non da `->label()`.
**Corretto** (DeliveryNoteForm): `TextInput::make('number')` → la label viene dalla traduzione
`'number' => ['label' => 'number']` in `lang/it/delivery_note.php`.
**Errore evitato**: il write originale di `DeliveryNoteInfolist.php` conteneva `->label(__('...'))` —
violazione della convenzione.

### Convenzione 2 — $resource in Form/Table/Infolist

**Regola**: Ogni classe Form, Table, Infolist DEVE avere `$resource` impostato.
**Motivo**: `TransKeyTrait::getKeyTrans()` risolve la chiave di traduzione a partire dal Resource
che possiede lo schema. Se `$resource` non è impostato, `GetTransKeyAction` non trova la classe
base e fallisce silenziosamente.
**Pattern corretto**:

```php
final class DeliveryNoteForm extends XotBaseResourceForm
{
    protected static string $resource = DeliveryNoteResource::class;
}
```

### Convenzione 3 — auto-scoperta Schemas/Tables

**Regola**: `XotBaseResource` auto-scopre `Schemas/{Model}Form` e `Tables/{Plural}Table`
via naming convention. Se la classe esiste, viene usata; altrimenti il bridge fallback
chiama `getFormSchema()` inline del Resource.
**Prova**: `XotBaseResource::form(Schema $schema)` linea 138-143: verifica `class_exists($form_class)` prima di chiamare `getFormSchema()`.

### Convenzione 4 — solo XotBaseResource, niente GatedXotBaseResource

**Regola**: Estendere SOLO `XotBaseResource`. `GatedXotBaseResource` esiste in `Modules/Platform/`
ma è per un caso specifico (NavigationGate runtime). Le Resource che lo usavano
(es. `DeliveryNoteResource`) vanno migrate a `XotBaseResource` diretto.
**Prova**: 30+ Resource usano `GatedXotBaseResource` — è un pattern legacy da rivedere modulo per modulo.
**Regola per questo codebase**: `GatedXotBaseResource` è da evitare per le nuove Resource.

### Convenzione 5 — composer dump-autoload dopo merge cross-modulo

**Regola**: Dopo un `git merge` che aggiunge o modifica classi in un modulo,
eseguire `composer dump-autoload --no-interaction` PRIMA di PHPStan.
**Motivo**: Il class loader può avere path stale che fanno fallire `class_exists()` durante il
bootstrap, producendo errori come `Class "Modules\Platform\Filament\Resources\XotBaseResource" not found`.
**Prova**: Story 2.11 — `composer dump-autoload` ha risolto il PHPStan bootstrap rotto.

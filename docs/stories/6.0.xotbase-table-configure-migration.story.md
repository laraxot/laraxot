# Story 6.0 — XotBaseResourceTable: structural migration `table()` → `configure()`

Status: **IN PROGRESS** — session 2026-09-07 part 3

## Contesto (studio di `XotBaseResourceTable.php`)

Il file `Modules/Xot/app/Filament/Resources/Tables/XotBaseResourceTable.php` (analizzato 2026-09-07) ha una struttura nuova:

```php
abstract class XotBaseResourceTable
{
    use HasXotTable;
    use TransTrait;

    public static function configure(Table $table): Table
    {
        if (static::class === self::class) {
            throw new \LogicException('XotBaseResourceTable::configure() must be called on a concrete table class.');
        }
        $instance = app(static::class);
        Assert::isInstanceOf($instance, self::class);
        return $instance->table($table);
    }

    abstract public function getTableColumns(): array;
}
```

### Pattern "configure" invece di "table"

Il `XotBaseResource` chiama automaticamente `<X>Table::configure($table)` per montare la tabella. La sottoclasse concreta **NON** ridefinisce `table()` (che è fornito da `HasXotTable:220` come default) e **NON** implementa `configure()`.

### Cosa serve cambiare in `XotBaseResourceTable` (futuro)

Per allineare il pattern con `Filament\Resources\Resource` standard:

1. **`XotBaseResourceTable`**: diventare non-abstract, con metodo `configure()` di default che chiama `getTableColumns()` + eventuali filtri/azioni standard
2. **Sottoclassi** (es. `SiteSurveysTable`, `ProfilesTable`): implementano solo `getTableColumns()`, `getTableFilters()`, `getTableActions()`, `getTableBulkActions()` — `table()` viene ereditato
3. **`XotBaseResource`**: chiama `<X>Table::configure($table)` esplicitamente, niente auto-scoping

## Impatto sulla sessione corrente

### Subagent task 1c: refactor `XotBaseResourceTable::configure()` — allinea a `XotBaseResourceInfolist`

Il file `XotBaseResourceInfolist.php` è il **pattern di riferimento**:

```php
abstract class XotBaseResourceInfolist {
    final public static function configure(Schema $schema): Schema  // final!
    {
        return $schema->components(static::getInfolistSchema());
    }

    abstract public static function getInfolistSchema(): array<string, Component>;
}
```

`XotBaseResourceTable::configure()` attualmente:

```php
public static function configure(Table $table): Table
{
    $instance = app(static::class);          // ❌ istanzia per chiamare un metodo static
    return $instance->table($table);         // ❌ delega a table() che chiama getTableColumns()
}
```

Deve diventare:

```php
final public static function configure(Table $table): Table
{
    $table->columns(static::getTableColumns());
    foreach (static::getTableFilters() as $filter) {
        $table->pushFilters($filter);
    }
    foreach (static::getTableActions() as $action) {
        $table->pushActions($action);
    }
    foreach (static::getTableBulkActions() as $action) {
        $table->pushBulkActions($action);
    }
    return $table;
}
```

**Vantaggi**:
- `final` — sottoclassi non ridefiniscono `configure()`
- Nessuna istanza creata con `app(static::class)`
- Tutti i metodi sono `static` → testabili senza boot del container
- Allineato a `XotBaseResourceInfolist` (pattern consolidato)

**Sottoclassi** (`SiteSurveysTable`, `ProfilesTable`, ecc.):
- Rimuovono il proprio `table()` override
- Implementano SOLO `getTableColumns()`, `getTableFilters()`, `getTableActions()`, `getTableBulkActions()`

**Attenzione**: `HasXotTable::table()` potrebbe servire in altri contesti (non Table-specific). Verificare prima di rimuovere.

### Subagent task 1b: aggiungere `getSteps()` a `SiteSurveyForm.php`

`XotBaseResourceForm.php` espone `getSteps(): array<string, Step> = []` come hook ufficiale per form multi-passo (Filament `HasWizard::getSteps()`).

`SiteSurveyForm` ha già 3 sezioni (`general`, `links`, `outcome`) che mappano bene come Wizard Steps:
1. `general` — code, status, title, dates
2. `links` — customer, customer_site, work_order, quotation, performed_by
3. `outcome` — notes

Va convertito in wizard:

```php
public static function getSteps(): array
{
    return [
        'general' => Step::make('site_surveys.steps.general')
            ->schema([
                'code' => TextInput::make('code')->maxLength(255),
                'status_code' => Select::make('status_code')
                    ->options(fn () => SiteSurveyResource::statusOptions())
                    ->required()
                    ->default('planned'),
                'title' => TextInput::make('title')->maxLength(255),
                'scheduled_at' => DateTimePicker::make('scheduled_at'),
                'performed_at' => DateTimePicker::make('performed_at'),
            ]),
        'links' => Step::make('site_surveys.steps.links')
            ->schema([
                'customer_id' => Select::make('customer_id')
                    ->options(fn (): array => Customer::query()->orderBy('legal_name')->pluck('legal_name', 'id')->all())
                    ->searchable()->preload()->live()
                    ->afterStateUpdated(static function (callable $set): void { $set('customer_site_id', null); })
                    ->required(),
                'customer_site_id' => Select::make('customer_site_id')
                    ->options(static function (callable $get): array { /* ... */ })
                    ->searchable()->preload()
                    ->disabled(static fn (callable $get): bool => blank($get('customer_id'))),
                'work_order_id' => Select::make('work_order_id')
                    ->options(fn (): array => WorkOrder::query()->orderByDesc('id')->limit(200)->get(['id', 'code', 'title'])
                        ->mapWithKeys(/* ... */)->all())
                    ->searchable()->preload(),
                'quotation_id' => Select::make('quotation_id')
                    ->options(fn (): array => /* ... */)
                    ->searchable()->preload(),
                'performed_by_user_id' => Select::make('performed_by_user_id')
                    ->relationship('performedBy', 'name')
                    ->searchable()->preload(),
            ]),
        'outcome' => Step::make('site_surveys.steps.outcome')
            ->schema([
                'notes' => Textarea::make('notes')->rows(5),
            ]),
    ];
}
```

`XotBaseResourceForm::configure()` deve usare `getSteps()` se non vuoto:

```php
public static function configure(Schema $schema): Schema
{
    $steps = static::getSteps();
    if ($steps !== []) {
        return $schema->components($steps);
    }
    return $schema
        ->components(static::getFormSchema())
        ->columns(static::getFormSchemaColumns());
}
```

Titolo: "Structural migration: XotBaseResourceTable — `table()` → `configure()` pattern"
Body:
- **Background**: `XotBaseResourceTable::configure()` è il nuovo pattern, ma le sottoclassi continuano a ridefinire `table()`. La regola "NON ridefinire `table()`" non è applicata dal tipo base.
- **Proposal**: 
  1. Rimuovere `table()` da `HasXotTable.php:220` (rendere il metodo `final` o astratto)

  4. Le Resource chiamano `<X>Table::configure($table)` esplicitamente
- **Acceptance Criteria**:
  - `XotBaseResourceTable::configure()` non chiama `$instance->table($table)` ma usa `getTableColumns()` + standard
  - `HasXotTable::table()` diventa `final` o `abstract`
  - Tutte le sottoclassi `<X>Table` rimosse dal proprio `table()`
  - PHPStan: 0 errori su `Modules/Xot`
  - Quality gate: 0 errori PHPStan sui moduli downstream (Billing, Quotation, Gdpr, ecc.)

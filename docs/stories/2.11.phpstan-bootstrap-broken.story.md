# Story 2.11 — PHPStan bootstrap rotto (Platform\Filament\Resources\XotBaseResource not found)

## Contesto

Eseguendo:

```bash
cd laravel && ./vendor/bin/phpstan analyse Modules/Billing --no-progress --memory-limit=-1
```

PHPStan fallisce in bootstrap con errore:

```
PHPStan was unable to bootstrap your application due to an error in your code.
Error: Class "Modules\Platform\Filament\Resources\XotBaseResource" not found
```

Stack trace rilevante:

- `Modules\Xot\app\Providers\Filament\XotBasePanelProvider.php:100` → `Filament\Panel->discoverResources()`
- `vendor/filament/filament/src/Panel/Concerns/HasComponents.php:531` → `class_exists()`
- `class_exists('Modules\Platform\Filament\Resources\XotBaseResource')` → false

## Causa probabile

Il class loader (`composer dump-autoload`) non ha indicizzato le classi di `Modules\Platform\Filament\Resources\` perché il file `composer.json` del modulo Platform non ha il mapping `autoload.psr-4` aggiornato OPPURE il file `Modules/Platform/app/Filament/Resources/XotBaseResource.php` esiste ma il class name nel file non corrisponde al path PSR-4.

## Verifica preliminare

```bash
cd laravel
find Modules/Platform -name "XotBaseResource*"
ls -la Modules/Platform/app/Filament/Resources/
cat Modules/Platform/composer.json | jq '.autoload'
composer dump-autoload --no-interaction
```

## Vincoli

1. `phpstan.neon` NON si tocca
2. Mai modificare il `composer.json` radice di laravel/ per correggere un singolo modulo
3. Se il problema è di PSR-4 → correggere il `composer.json` del modulo Platform
4. Se è un bug nella gerarchia classi → fix mirato
5. Mai `composer.json` modifiche broad, scope per modulo

## Approccio

1. **Ricognizione**: identificare dove Platform\Filament\Resources\XotBaseResource viene referenziato
2. **Verifica file**: esiste `Modules/Platform/app/Filament/Resources/XotBaseResource.php`? Se sì, il suo namespace è `Modules\Platform\Filament\Resources`?
3. **Composer check**: `composer dump-autoload` risolve? Il modulo è nel file `modules_statuses.json` o `gitmodules.ini`?
4. **Fix mirato** (opzioni):
   - (a) Aggiungere `psr-4` mapping in `Modules/Platform/composer.json` per `Modules\\Platform\\` → `app/`
   - (b) Correggere namespace di un file Platform se errato
   - (c) Se la classe attesa è sbagliata (vedi 06-filament-audit: solo `XotBaseResource`, no varianti) → rimuovere il riferimento fantasma

## Criteri di accettazione

- [ ] `phpstan analyse Modules/Billing` non fallisce in bootstrap
- [ ] `phpstan analyse Modules` produce un report (errori attesi ok, ma il bootstrap OK)
- [ ] `composer dump-autoload` non genera warning per il modulo Platform
- [ ] Nessun `phpstan.neon` modificato
- [ ] Story story 2.8/2.10/2.9 sbloccate da questo fix

## Log avanzamento

- 2026-09-07: story creata dopo errore durante quality gate su Billing.
- 2026-09-07: **`composer dump-autoload --no-interaction` risolve** — 27463 classi rigenerate, `class_exists('Modules\Platform\Filament\Resources\XotBaseResource')` ritorna true, PHPStan ora esegue correttamente. Il class loader era stale, NON c'era un bug nel codice. Story 2.11 si chiude come "stale autoload" — l'errore tornerà se non si esegue `dump-autoload` dopo merge cross-modulo. **Action**: aggiungere `composer dump-autoload` al quality gate prompt 03 come step 0.

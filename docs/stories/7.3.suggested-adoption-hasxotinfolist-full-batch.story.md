# Story 7.3 — SUGGESTED: Adozione completa `HasXotInfolist`

Cosa suggerire di fare (non ripetere — leggi questa story):

1. Verificare tutte le sottoclassi che estendono `XotBaseResourceInfolist` (se esistono) — probabilmente sono rare o non esistono ancora (il trait è nuovo).
2. Creare `HasXotInfolist` adoption per le risorse Filament che usano `Infolist` (es. `SiteSurveyInfolist.php`, `QuotationInfolist.php`, ecc.).
3. Rimuovere eventuali `getInfolistSchema()` statici — devono diventare `public function` instance.
4. Aggiungere `getInfolistSchemaColumns()` se necessario.
5. Aggiornare `XotBaseResourceInfolist::configure()` se ancora non usa `$instance = app()`.

Strumenti utilizzabili (già installati):
- `bmad create story` / `bmad check-implementation-readiness`
- `gh issue create` / `gh discussion create` (per `laraxot/module_xot_fila5`)
- `pint --dirty --test` / `php -l` / `phpstan` (non modificare `phpstan.neon`)

Non ripetere — questa story documenta il piano. Eseguire con `swarm` o `subagent` batch (10 file/ciclo).

## Story

As a **platform engineer**,
I want **ogni modulo importato da gestionale_commesse a 0 errori PHPStan reali e con i test Pest verificati**,
so that **il codice non sia solo formalmente presente ma davvero corretto e funzionante prima di abilitarlo**.

## Contesto — bug bloccante risolto prima di questa story

Il bootstrap dell'app falliva per due bug reali (non solo debito PHPStan):
1. `readonly class` + trait `Spatie\QueueableAction\QueueableAction` (property `$job` non-readonly scritta dal trait) → Fatal Error. Fix: rimosso `readonly` da 6 Action (3 `Intervention`, 3 `Quotation`).
2. Namespace con **doppio backslash letterale** scritto in file `.php` (`namespace Modules\\WorkOrder\...;`) → parse error. Fix: 8 file in `WorkOrder` corretti (4 analoghi in `AiAssistant` NON toccati, modulo conteso da altro agente).

Con questi due fix, `phpstan analyse Modules/{qualsiasi}` è finalmente eseguibile per tutti i 23 moduli.

## Acceptance Criteria

1. Per ogni modulo migrato: `phpstan analyse Modules/{Nome} --memory-limit=-1` → 0 errori di codice reali (l'unico messaggio residuo accettabile è il meta-warning globale "Ignored error pattern @mixin ... was not matched", artefatto di `phpstan.neon` root quando si analizza un modulo isolato, non un bug).
2. Nessun `@phpstan-ignore`, `assert()`/`@var` per forzare tipi, o allargamento di tipi per silenziare — solo fix reali della causa.
3. Test Pest del modulo (dove esistono) eseguiti e verificati passanti, non solo presenti.
4. `docs/README.md` (o `import-status.md`) di ogni modulo aggiornato con lo stato finale.
5. Coordinamento multi-agente tramite `bashscripts/lock/{check,lock,unlock}.sh` su ogni file toccato — nessuna collisione distruttiva.
6. Bug funzionali reali scoperti durante il lavoro documentati esplicitamente (non solo "fixato un tipo").

## Dev Notes

### Pattern ricorrenti trovati e risolti (riusabili per i moduli restanti)

| Pattern | Causa | Fix |
|---|---|---|
| Costanti `ACCOUNT_FEATURE_*` "unused" | lette solo via reflection `constant()` da trait esterno | `private`→`protected`, o override esplicito `isAvailableInCurrentPanel()` |
| Model senza `@property` | tabelle non migrate nell'ambiente di analisi, Larastan non riflette lo schema | aggiungere blocchi `@property` dalle migration |
| `HasFactory` generico non tipizzato | manca `@use HasFactory<XFactory>` | aggiungere l'annotazione generica |
| Test Pest `expect()->toX()` → `method.internalClass` | Larastan non vede l'estensione Pest quando il modulo è analizzato isolato | riscrivere con `PHPUnit\Framework\Assert::assert*` |
| Accesso a proprietà di modelli di **altri** moduli | proprietà non tipizzata lì, non modificabile (fuori scope) | `getAttribute()` con guard `is_string`/`is_int` |
| `preg_*`/`json_encode`/`json_decode` nativi | funzioni "unsafe" per convenzione progetto (thecodingmachine/safe) | `use function Safe\...;` |
| Migration con closure `static function` che chiama `$this->` | **bug reale**, fatal a runtime (`Undefined variable: $this`) | rimuovere `static` |
| Namespace/classe referenziata che non esiste da nessuna parte | **bug reale**, gap di integrazione o refactor incompleto | correggere se il target esiste altrove con nome diverso; documentare come gap aperto se il target non esiste affatto |
| `larastan.noEnvCallsOutsideOfConfig` su `config/*.php` di modulo | Larastan riconosce solo `config_path()` root come "config dir" | debito sistemico, richiede `phpstan.neon` root — fuori scope per singolo modulo |

### Owned scope

- Ogni agente lavora SOLO dentro il proprio `laravel/Modules/{Nome}/`
- `AiAssistant` escluso (conteso da altro processo/agente in questa sessione)
- `bashscripts/lock/*.sh` usato su ogni file prima di modificarlo

### Guardrails

- Non `pint --dirty` senza path esplicito (ha causato modifiche accidentali a file di altri moduli in questa sessione — sempre recuperate con `git checkout --`)
- Non abilitare `modules_statuses` finché PHPStan non è pulito
- Non toccare `phpstan.neon` root

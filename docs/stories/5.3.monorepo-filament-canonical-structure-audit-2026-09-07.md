# Story 5.3 — Monorepo Filament Canonical Structure Audit (Batch)

Status: **IN PROGRESS** — session 2026-09-07 batch

## Contesto (Perché questo audit)

Il prompt `06-filament-audit.md` documenta che ogni `Filament/Resources/*Resource.php` deve avere:
- `Schemas/<Name>Form.php`
- `Schemas/<Name>Infolist.php`
- `Tables/<Plural>Table.php`
- `Pages/` (Create/Edit/List/View)
- `RelationManagers/`
- Zero `getFormSchema()` / `table()` / `getInfolistSchema()` inline nel Resource

Dopo aver verificato `Billing/DeliveryNoteResource` (già corretto) e `Quotation/SiteSurveyResource` (corretto con estrazione), è emerso che **molti altri moduli** hanno ancora `getFormSchema()` / `table()` inline (form_inline=1) o mancano `Schemas/`/`Tables/`.

for r in Modules/*/app/Filament/Resources/*.php; do ... done

## Criterio di priorità per batch

Perché `Catalog`, `Gdpr`, `Customer`, `Compliance` sono i più critici:
- `Catalog` ha **6 Resource** con `schemas=0` `tables=0` e `form_inline=1` + `table_inline=1` — massimo gap
- `Compliance` ha `CustomerSystemResource` con `schemas=0` `tables=0` e entrambi inline
- `Customer` ha `ResellerResource` con entrambi inline e `schemas=0`
- `Gdpr` ha 4 Resource con `schemas=1` ma `form_inline=1` (Schema presente ma non usato; il Resource non delega)

## Approccio swarm + subagent + BMAD

Per chiudere i rimanenti 50+ file con gap:

1. **Swarm**: dividere per modulo (Catalog = 6 file, Customer = ~8 file, Gdpr = 4 file, Compliance = 2 file)
2. **Subagent per batch**: ogni subagent prende 5 file, esegue audit + ricetta §5a + quality gate
3. **BMAD story**: creare `5.3.x.<modulo>-filament-canonical` per ogni modulo
4. **Second brain**: aggiorna con il pattern `XotBaseResource` + `No inline getFormSchema()`

## Ricetta per ciascun gap (stesso pattern §5a)

Per ogni `<Name>Resource.php` con `getFormSchema()` inline:
1. Creare `Schemas/<Name>Form.php` con `extends XotBaseResourceForm`
2. Estrarre `getFormSchema()` dal Resource → Schema
3. Creare `Tables/<Plural>Table.php` con `extends XotBaseResourceTable`
4. Estrarre `table()` dal Resource → Table
5. Creare `Schemas/<Name>Infolist.php` se necessario
6. Rimuovere `getFormSchema()` / `table()` dal Resource
7. Aggiornare `Pages/` se necessario
8. Verifica `php -l`, `phpstan analyse <Modulo>`, `pint --dirty --test`
9. Commit con `git commit -m "refactor(<m>): filament audit — extract schemas+tables [story: 5.3.x]"` (forward-only)

## Note architetturali

- `Gdpr` ha `ProfileResource`, `TreatmentResource`, `ConsentResource`, `EventResource` — tutti con `form_inline=1`. Alcuni hanno `Schemas/` ma il Resource non delega (`getFormSchema()` rimane). Questo è un caso diverso dal "mancano i file" — il problema è "il Resource non usa il Schema". Il fix è: rimuovere `getFormSchema()` dal Resource, lasciare che `XotBaseResource` lo carichi dal file `Schemas/ProfileForm.php`.
- `Media` `MediaConvertResource` ha `table_inline=1` — stesso pattern per Table.
- `Platform` `NavigationClassifier`, `NavigationGate` — non sono Resource ma support, non richiedono Schemas/Tables.

# Story 2.8 — PHPStan constantTypeCoverage 49% → 99% (project-wide)

## Contesto

Scansione `./vendor/bin/phpstan analyse Modules` (phpstan.neon, level max, NON
modificabile) rileva **82 occorrenze `typeCoverage.constantTypeCoverage`** su 19 moduli.
La metrica `constantTypeCoverage` è **project-wide**: 147/300 costanti tipizzate = 49%,
target soglia = 99%. Non è un errore per-file: la soglia si applica a TUTTE le costanti
PHP dell'intero scope `./Modules/`.

Baseline 2026-09-07:
- `Out of 300 possible constant types, only 147 - 49.0 % actually have it`
- File toccati sparsi in: AiAssistant, Billing, Blog, Bom, Catalog, Compliance,
  Customer, HR, Intervention, Job, MetalWork, Platform, Production,
  PublicProcurement, Quotation, Signage, Timber, Vehicle, Wts.

## Vincoli inviolabili

1. `phpstan.neon` NON si tocca (solo il maintainer può).
2. Nessuna baseline aggiuntiva (`phpstan-baseline.neon`).
3. Nessuna soppressione: vietati `@phpstan-ignore-line`, `ignoreErrors`.
4. `mixed` non c'entra: qui si parla di **costanti senza tipo esplicito**.
5. `declare(strict_types=1);` deve restare su ogni file.
6. Mai `git push --force`. Solo avanti.
7. Ogni modulo ha il proprio `.git`: `add/commit/merge/push` dal modulo.

## Regole operative (dal maintainer)

1. Scope: SOLO costanti di classi PHP (`const FOO = 'bar';`) e costanti di enum PHP.
2. Aggiungere il tipo esplicito:
   - `const FOO = 'bar';` → `const string FOO = 'bar';`
   - `const N = 42;` → `const int N = 42;`
   - `const ARR = ['a'];` → `const array ARR = ['a'];`
3. Le costanti già tipizzate vanno lasciate invariate.
4. Per le constant expressions non banalmente tipizzabili, valutare enum
   `final class Status: string { const string ACTIVE = 'active'; }`.
5. Non toccare le costanti di classi Filament / framework esterno (eccetto le
   nostre classi in `Modules/`).
6. Studiare la storia: `git log --oneline --all -- <file>` e `git show HEAD:<file>`.
7. Coordinamento: prima di iniziare un modulo, controllare se altri agenti lo
   hanno già preso (`docs/chat/INDEX.md`, ricerca story attive).

## Pattern di fix (ricorrenti)

- `const DEFAULT_PAGE = 25;` → `const int DEFAULT_PAGE = 25;`
- `const STATUS = 'active';` → `const string STATUS = 'active';`
- `const CONFIG_KEY = 'app.name';` → `const string CONFIG_KEY = 'app.name';`
- Costanti in enum PHP: aggiungere return type esplicito
  `enum Color: string { case Red = 'red'; }` (già tipizzato via backing type)
  oppure usare `final class Status { const string A = 'a'; }`.

## Approccio consigliato (ordine)

1. **Wave A** — moduli piccoli (1-2 file con errori): Job, Vehicle, Wts,
   PublicProcurement, Production, HR, Bom, Blog, Timber.
2. **Wave B** — medi (3-5 file): AiAssistant, Billing, Customer, Platform, Signage.
3. **Wave C** — grossi (6-8 file): Catalog, Compliance, Intervention, Quotation,
   MetalWork.

Per ogni modulo:
- `cd laravel/Modules/<Modulo>`
- `git fetch laraxot dev && git merge laraxot/dev --allow-unrelated-histories -s resolve`
- fix costanti non tipizzate
- `./vendor/bin/phpstan analyse Modules/<Modulo> --no-progress --memory-limit=-1` → 0
- `./tools/phpmd.sh Modules/<Modulo>` → 0
- `./tools/phpinsights analyse Modules/<Modulo> --no-interaction` → soglie ok
- `./vendor/bin/pest --filter=<Modulo>` → tutti verdi
- `git add -A && git commit -m "refactor(<modulo>): type constants [story: 2.8]"`
- `git push -u laraxot <branch>`

## Criteri di accettazione = Definition of Done

- [ ] `./vendor/bin/phpstan analyse Modules` → 0 occorrenze `constantTypeCoverage`
      (o sotto la soglia prossima al 99%, da concordare col maintainer)
- [ ] phpstan.neon invariato
- [ ] Nessuna soppressione, nessun baseline
- [ ] Tutte le costanti modificate hanno tipo esplicito
- [ ] Quality gate per ogni modulo chiuso (phpstan + phpmd + phpinsights + pest)
- [ ] `git status` pulito + merge da `laraxot/dev` + push completato
- [ ] `docs/Modules/<Modulo>/docs/` aggiornato se pattern nuovo emerso
- [ ] Second brain aggiornato (docs/wiki/rules/ + docs/wiki/concepts/)

## Rischi e impatto

- Modifica a molte classi: occorre coordinamento per non sovrapporre agenti.
- Alcune costanti potrebbero essere parte di API pubblica: aggiungere tipo è
  safe (è solo promozione, non restringimento), MA serve `git show` per capire
  se usate via reflection o pattern matching dinamico.
- L'analisi `constantTypeCoverage` richiede PHPStan in modalità "bleeding edge"
  (vedi `phpstan.neon` include `bleedingEdge.neon`).

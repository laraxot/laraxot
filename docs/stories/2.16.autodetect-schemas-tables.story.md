# Story 2.16 — Script auto-detect: Resource senza Schemas/Tables

> **Correzione scope (2026-09-07, sessione successiva)**: `bashscripts/tools/filament_audit.sh`
> e' stato creato lo stesso giorno (15:06) da un'altra sessione, con scope
> quasi identico a quello descritto qui sotto (gap `Schemas/`/`Tables/`,
> `getFormSchema()`/`table()` inline, `extends GatedXotBaseResource`, label
> hardcoded) — vedi `bashscripts/docs/prompts/06-filament-audit.md` che lo
> referenzia come script canonico. Scrivere un secondo script
> (`bashscripts/filament/check-resource-structure.sh`) duplicherebbe
> lavoro gia' fatto. **Retarget**: non creare un nuovo script, verificare se
> `filament_audit.sh` copre gia' il check "manca `protected static string
> $resource`" (unico controllo qui sotto che non risulta presente li'; se
> manca, aggiungerlo a `filament_audit.sh`, non duplicarlo) e poi chiudere
> gli AC restanti (`pre-commit`/CI) puntando allo script esistente. Il
> codice bash sotto resta come riferimento per il check `$resource`
> mancante, non va eseguito come script separato.

## Perché

Il problema che ha generato 63 gap di struttura Filament non è stato rilevato perché
nessuno strumento automatico lo controllava. Aggiungere uno script di detection
in `bashscripts/` che:

1. Scansiona `Modules/*/app/Filament/Resources/*Resource/`
2. Rileva cartelle `Schemas/` o `Tables/` mancanti
3. Rileva file Form.php/Infolist.php/Table.php mancanti dentro
4. Rileva Resource con `getFormSchema()` o `table()` inline (legacy)
5. Rileva Resource che estendono `GatedXotBaseResource`
6. Rileva `->label(` nei file Form/Table/Infolist (vietato)
7. Esce con exit code 1 se trova violazioni (gate)

## Implementazione

File: `bashscripts/filament/check-resource-structure.sh`

```bash
#!/usr/bin/env bash
# check-resource-structure.sh — gate per struttura canonica Filament Resource
# Uso: bash bashscripts/filament/check-resource-structure.sh [MODULO]
# Esempio: bash bashscripts/filament/check-resource-structure.sh Billing
set -euo pipefail

MODULE="${1:-}"
PATTERN="Modules"
if [[ -n "$MODULE" ]]; then
  PATTERN="Modules/$MODULE"
fi

cd "$(dirname "$0")/../laravel" || exit 2

errors=0
report() { echo "$1"; ((errors++)); }

for d in $PATTERN/app/Filament/Resources/*Resource; do
  [[ -d "$d" ]] || continue
  name=$(basename "$d")
  mod=$(echo "$d" | cut -d'/' -f2)

  # Check 1: cartelle Schemas/ e Tables/
  [[ -d "$d/Schemas" ]] || report "GAP: $mod/$name — Schemas/ mancante"
  [[ -d "$d/Tables"  ]] || report "GAP: $mod/$name — Tables/ mancante"

  # Check 2: extends GatedXotBaseResource (deprecato per nuove)
  if [[ -f "$d.php" ]]; then
    if grep -q "extends GatedXotBaseResource" "$d.php"; then
      report "DEPR: $mod/$name.php — extends GatedXotBaseResource (usare XotBaseResource)"
    fi
  fi
  if [[ -f "$d.php" ]]; then
    # Check 3: inline getFormSchema (legacy)
    if grep -qE "public static function getFormSchema\(\)" "$d.php"; then
      report "LEGACY: $mod/$name.php — getFormSchema() inline (spostare in Schemas/<Name>Form.php)"
    fi
    # Check 4: inline table()
    if grep -qE "public static function table\(Table" "$d.php"; then
      report "LEGACY: $mod/$name.php — table() inline (spostare in Tables/<Plural>Table.php)"
    fi
  fi

  # Check 5: ->label() vietato in Form/Table/Infolist
  for sf in "$d/Schemas"/*.php "$d/Tables"/*.php; do
    [[ -f "$sf" ]] || continue
    if grep -qE "->label\(" "$sf"; then
      report "LABEL: $sf — ->label() vietato (LangServiceProvider auto-registra)"
    fi
    # Check 6: $resource impostato
    if ! grep -qE "protected static string \$resource" "$sf"; then
      report "NORES: $sf — manca protected static string \$resource"
    fi
  done
done

if (( errors > 0 )); then
  echo "FAIL: $errors violazioni"
  exit 1
fi
echo "OK: struttura Filament Resource conforme"
exit 0
```

## Falsi positivi trovati in `filament_audit.sh` (2026-09-07, sessione successiva)

Verificando i moduli NON coperti dallo swarm Epic 4 (Blog, Wts, Rating,
Vehicle) per un possibile giro di fix indipendente, `bashscripts/tools/filament_audit.sh`
segnala 3 "gap" che in realta' non lo sono:

- `Modules/Blog/app/Filament/Resources/UserResource` — e' una directory
  senza `UserResource.php` corrispondente (nessuna classe Resource reale
  li'). Lo script matcha qualunque dir `*Resource` senza verificare che
  esista il file `.php` sorella.
- `Modules/Wts/app/Filament/Resources/UserResource.php` — esiste, ma
  `extends BaseUserResource`, non `XotBaseResource` direttamente (stesso
  caso di esenzione gia' annotato in `laravel/Modules/Billing/docs/stories/4.3.filament-audit-14-modules.story.md`
  addendum 2 per `Wts\UserResource`). Falso positivo, non un gap reale.
- `Modules/Rating/app/Filament/Resources/HasRatingResource` — directory
  che contiene `RelationManagers/`+`Widgets/` da comporre in ALTRI
  Resource (nome "Has*" = trait-like fragment, non una Resource
  standalone). Stesso problema di matching della dir Blog sopra.
- Bonus: lo script auto-matcha anche `XotBaseResource` stessa dentro
  `Modules/Xot` (finisce per "Resource", quindi il glob la prende) e una
  dir chiamata letteralmente `Tables` — falsi positivi sulla classe base
  del pattern stesso.

**Fix suggerito per lo script**: (1) richiedere che esista `$d.php` prima di
riportare un gap; (2) escludere `XotBaseResource.php`/`LangBaseResource.php`
(le basi stesse); (3) escludere Resource che NON estendono `XotBaseResource`/
`LangBase*` direttamente dal check Schemas/Tables (loggarle come "verificare
base class" invece di "gap"), invece di trattarle come violazione.

Non ho toccato lo script (condiviso, in uso dallo swarm Epic 4 in questo
momento) — solo documentato qui perche' e' l'AC di questa story.
